# AI 镜头规划与预演

## 项目版本路由（先判断）

只依据当前业务项目 `开始这里.md` 的显式 `workflowStudio: studio-v0.9` 选择新分支；Skill 路径、候选目录名或聊天标题都不是项目标识。可复用主调用方本轮已核实的入口与能力结果。

- 有该标识：先读 [V0.9 共同契约](../orchestrate-ai-film-project/references/studio-v09-contract.md) 与项目能力状态，再读 [本专业的 V0.9 候选分支](references/studio-v09-candidate.md)。仅执行该分支；不进入下方旧版的唯一 A 目标、逐项采用、同岗租约或正式写回流程。专业知识按该分支指向读取。
- 无该标识或不在项目中：不加载 V0.9 分支，继续下方原有模式和边界。无法核实标识时，不凭目录推断启用新能力。

## 目标

把已经具备可见行动、人物目标和基本场景信息的剧本段落，按“场景任务 -> 人物与空间调度 -> 单镜头设计 -> 镜头衔接与覆盖 -> 镜头组、时间与视听节奏”转译成能交给生成与剪辑环节继续执行的镜头方案。

镜头设计服从段落，不从技术名词反推创作。先判断观众必须看见和感到什么，再选择景别、视点、构图、运动与覆盖。

## 边界

负责：

- 提炼段落叙事任务、情绪与信息节拍。
- 确定观众视点、信息权限、人物调度、空间与轴线基准、视觉推进和覆盖策略。
- 设计逐镜任务、可见动作、摄影机行为、切入与切出动机、声音接口和连续性要求。
- 设计摄影基准与叙事布光：信息尺度、焦点策略、光源动机、方向、光质、反差及跨镜变化。
- 读取并保持已经采用的场景表演主线，让摄影机服务既定目标、节拍、动作因果和关键反应。
- 检查镜头组怎样建立基准、推进变化、兑现节拍并交接下一段。
- 输出静态分镜描述和动态预演时间线。
- 识别生成前的动作复杂度、连续性和可剪辑性风险，并给出必要替代方案。

不负责：

- 替用户补写人物目标、关键行动、结局或故事因果。
- 重新解释、覆盖或代写已经采用的角色表演方案。
- 重写故事主线或把生产失败解释成剧本必然失败。
- 输出生图、生视频或分镜图的最终模型提示词。
- 调用图像或视频生成工具。
- 评价已经生成的图片或视频质量、追踪全项目资产一致性。
- 决定实际剪辑节奏、完成剪辑或发布。

镜头方案确认后，图片提示词交给 `$format-gpt-image-2-prompt`，Seedance 2 视频提示词交给 `$format-seedance-2-prompt`；已有生成结果的问题归因仍由 C_视觉生成处理；实际组合和节奏判断交给 D_后期剪辑。

## 规划流程

### 0. 检查段落是否可规划

确认至少可以从输入中辨认：

- 谁正在追求什么或试图完成什么。
- 观众可以看见的行动或状态变化。
- 行动发生的基本空间及参与者。

只缺少一个会改变整套镜头策略的关键事实时，只问一个高杠杆问题。缺少可见行动、人物目标或基本场景信息时，停止镜头展开并路由 B；不要把猜测伪装成剧本事实。

对白不是可见行动。若段落只有台词，应指出需要由 B 或用户确认的行为、关系变化或视觉事件。

对白、关系变化、关键反应或动作戏已经有采用表演方案时，把它作为镜头规划约束，不另行发明表演；尚无表演方案且表演解释会改变镜头组织时，先路由 `$direct-ai-character-performance` 完成第一遍。空镜、普通插入和简单机械动作不强制调用表演 Skill。

### 1. 第一阶段：镜头策略

先输出以下十项，不分配正式 `V` 编号，不写项目文件：

```text
段落叙事任务：
主要情绪与信息节拍：
观众视点：
人物和空间基准：
视觉强度变化：
需要的镜头覆盖：
预计镜头数量和总时长：
现有与缺失资产：
AI 生成风险：
需要用户确认的唯一关键选择：
```

“唯一关键选择”必须能真实改变镜头组织，例如主观还是客观、长镜头还是覆盖剪辑、先揭示结果还是先保留信息。不要把十个小参数伪装成一个问题。若没有影响策略的分歧，明确说明“无关键分歧，请确认是否按此策略展开”。

“人物和空间基准”必须至少说明：人物起止位置与有动机的调度、关系轴或主要行动轴、关键屏幕方向、入口出口和空间锚点。两人以上互动、追逐或复杂动作场景，在十项之后条件性补一张简洁空间／轴线示意；简单单人场景不强制画图。

已有采用表演方案时，人物调度必须承接其目标、节拍、动作链和关键状态；如空间、覆盖或生成限制无法承载关键表演，应列出冲突和最小镜头替代，不静默改写表演。

尊重用户明确的形式意图。用户要求一镜到底时，先按一镜到底设计内部节拍，同时说明连续变景、复杂动作或角色一致性的生成风险；可以给保底替代，但不能擅自改成多镜。

### 2. 等待策略确认

“按这个做”“采用这个策略”“就这样展开”等明确表达才进入第二阶段。用户仍在比较方向时继续讨论策略，不提前编号，不偷偷写回。

### 3. 第二阶段：逐镜方案

策略确认后分配稳定 `V01`、`V02` 等编号。项目模式从现有最大编号继续；独立模式可从 `V01` 开始，并说明编号只属于本次方案。

每镜必须写：

```text
镜头 ID：
场景节拍位置：
镜头任务与主要功能：
建议时长：
可见动作：起点 / 过程 / 终点
开始状态 / 结束状态：
景别：
视点与构图重点：
信息尺度 / 焦点策略：
摄影机：固定，或运动方式
运动触发点与结束构图：
轴线侧 / 屏幕方向 / 视线关系：
光源动机 / 方向 / 光质 / 反差：
切入动机 / 切出动机：
必要的声音接口：
与镜头组视觉推进的关系：
所需资产：
连续性要求：
AI 生成风险与必要替代方案：
状态：待定 / 采用 / 停用
```

只在确实影响镜头任务、生成或衔接时补充焦距与距离、精确机位、特殊光学或声音。摄影/灯光字段也按叙事作用填写；简单镜头可写项目基准引用，不为显得专业机械填满参数。

一个镜头可以承担相邻的两个简单功能，但不能把多个独立动作、两次信息反转和复杂变景塞进同一 AI 生成单元。已有表演方案时，“可见动作”和首尾状态从采用方案承接，镜头只决定怎样看见和衔接。先保住因果、表演和剪辑接口，再讨论炫技。

### 4. 静态预演

为每个 `V` 镜头输出：

- 分镜画面描述。
- 人物、关键道具和入口出口位置。
- 被截取的动作瞬间。
- 第一视觉重点与第二视觉重点。
- 与前后镜相接的连续性锚点。

分镜表只按真实镜头数排版：

```text
1-4 镜：最多 2x2
5-6 镜：最多 3x2
7-9 镜：3x3
超过 9 镜：拆成多张连续编号的分镜表
```

空格保持空白，不为凑满 3x3 制造无功能镜头。

### 5. 动态预演

按时间顺序输出：

```text
镜头 ID：
入点 / 出点 / 时长：
人物可见动作：
摄影机行为：
前后镜转场：
声音提示：
开始状态：
结束状态：
```

时间线总时长应与各镜时长之和一致。声音提示只记录用于节拍、连接或可见反应的临时声音接口，不在这里完成 DX/FX/MX、配乐或最终声音设计。静态分镜、动态预演和临时声音只能证明方案层面理论可生成/可衔接，不是 CUT，也不证明真实素材可剪。

### 6. 检查方案

交付前逐项检查：

- 每镜是否有不可替代的叙事任务；重复功能能否合并。
- 人物调度与摄影机调度是否分别有动机，还是为了制造运动而移动。
- 观众是否知道人物在哪里、看向哪里、向哪里行动。
- 动作起点、接触点、终点和道具状态能否跨镜匹配。
- 轴线、视线、屏幕方向和人物左右关系是否一致；若有意越轴，是否有表达收益、新空间基准和必要的重建办法。
- 每个切点是否带来新的信息、关系、动作、情绪或节奏价值，而不是只因为“能切”。
- 视觉强度是否随段落变化，而不是随机切换景别和机位。
- 镜头组是否完成基准、变化、兑现与交接；节奏是否同时考虑画面内部动作、镜头时长、声音和停顿。
- 每个生成单元是否只有一个主要动作，首尾状态是否明确。
- 是否具备建立、动作、反应、关键细节等真正需要的覆盖，又没有机械过度覆盖。
- 功能化 coverage 是否覆盖叙事信息、关键反应、动作阶段、空间基准、必要插入和声音接口，而不是机械按景别凑数量。
- 光源动机、方向、光质、反差、焦点和摄影运动是否服务信息与人物关系，并能跨镜保持或有意变化。
- 已采用表演方案中的目标、节拍、动作因果、关键反应和首尾状态是否被完整承接，没有被镜头设计重新解释。
- 静态分镜、动态时间线和逐镜方案是否使用同一批 `V` 编号。
- 总时长、镜头数和分镜表格是否互相一致。

## V 编号与版本

- `V` 表示从确认的镜头计划开始贯穿生成和剪辑的稳定镜头，不是某个生成文件。
- 同一镜头的叙事功能不变，只修改构图、动作细节或技术实现时，保留 ID 并递增版本，如 `V03 v02`。
- 镜头功能根本改变时，将旧镜头标为“停用”，新分配一个从未使用过的 ID。
- 删除或停用的编号永不回收；不同 `V` 镜头不能因为内容相似而合并编号。
- 生成结果用所属镜头 ID 加结果版本记录，不把每次失败升级成新镜头。

## 项目写回

项目模式下，逐镜方案初次输出时仍是待确认草案。用户明确采用后：

1. 复制 [assets/shot-plan-template.md](assets/shot-plan-template.md) 的结构，创建或更新 `镜头规划/Sxx_镜头方案.md`。
2. 更新 `C_视觉生成.md` 的“镜头规划索引”。
3. 在“生成结果索引”建立或更新同一批 `V` 计划行；还没有生成文件时，take 字段留空，技术可用性写“待生成”。
4. 更新 `C_视觉生成.md` 的“最近交接”。
5. 不修改 `A_总控.md`、`B_故事剧本.md` 或 D 主文件。

镜头规划索引的“当前问题”只记录尚未解决且会阻碍镜头方案执行的问题。逐镜表演、提示词、资产定稿、生成等正常后续工作写入“最近交接”的“仍然待定”和“建议下一步”，不得伪装成镜头方案问题；没有实际问题时写“无”。

若用户只说暂停而没有采用逐镜方案，可以在最近交接中记录“待定草案尚未写入镜头方案”，不要把它标成采用。若写回路径或编号冲突，停止写入并说明冲突，不覆盖不明内容。

用户要求直接生成图片、视频或最终提示词时，先完成当前镜头规划边界内的交付，再切换到相应 Skill；不要在本 Skill 的镜头字段中夹带冗长模型提示词。
