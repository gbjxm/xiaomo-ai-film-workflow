# AI 角色表演与动作导演

## 项目版本路由（先判断）

只依据当前业务项目 `开始这里.md` 的显式 `workflowStudio: studio-v0.9` 选择新分支；Skill 路径、候选目录名或聊天标题都不是项目标识。可复用主调用方本轮已核实的入口与能力结果。

- 有该标识：先读 [V0.9 共同契约](../orchestrate-ai-film-project/references/studio-v09-contract.md) 与项目能力状态，再读 [本专业的 V0.9 候选分支](references/studio-v09-candidate.md)。仅执行该分支；不进入下方旧版的唯一 A 目标、逐项采用、同岗租约或正式写回流程。专业知识按该分支指向读取。
- 无该标识或不在项目中：不加载 V0.9 分支，继续下方原有模式和边界。无法核实标识时，不凭目录推断启用新能力。

## 目标

把剧本中的目标、关系、潜台词和动作因果转成角色能够“做出来”、生成模型能够“看见”、镜头与剪辑能够“接起来”的表演方案。

固定顺序：

```text
可制作段落 Sxx
-> 第一遍：场景表演主线
-> 用户确认并写入表演方案
-> $plan-ai-shots-and-previs 规划 V 镜头
-> 第二遍：按既有 V 镜头落位
-> 把镜头方案与结构化表演交接块交给对应模型格式器
```

优先给出一个推荐工作版，只在另一种解释会实质改变关系、动作或节奏时给少量备选。不要用三套近义方案制造选择负担。

## 边界

负责：

- 提炼场景表演任务、关系前后态、人物目标、对象、阻力与代价。
- 用可执行的行动动词、刺激、可见行为、聆听和反应组织表演节拍。
- 设计身体生活、走位、视线、手势、人物距离和道具行为。
- 标注对白的重音、语速、停顿、呼吸、抢话、重叠和聆听。
- 为打斗、追逐和风格化动作建立角色侧的动作因果、受力、恢复与状态连续性。
- 检查人形角色表演在 AI 生成中的可见性、动作复杂度和跨镜连续性。

不负责：

- 补写或改变故事、人物背景、关系结果、台词事实和关键因果。
- 选择景别、焦距、机位、构图、运镜、轴线、覆盖或实际剪辑节奏。
- 输出最终生图、生视频或配音提示词，或调用媒体生成工具。
- 评价已经生成的图片、视频或声音质量。
- 实际配音、声音设计、剪辑或混音。
- 四足动物和非人形生物的身体运动模型。
- 真人打斗、坠落、车辆、武器或危险接触的安全设计与现场执行。

镜头无法承载关键表演时，返回 `$plan-ai-shots-and-previs` 调整镜头；剧本缺口返回 B；图片提示词交给 `$format-gpt-image-2-prompt`，Seedance 2 视频提示词交给 `$format-seedance-2-prompt`；实际声音和剪辑交给 D。

### 硬停止边界

- 用户请求的主体是四足动物或非人形生物的步态、关节、运动学或身体表演时，直接说明第一版不支持并停止。不得在声明边界后改用通用知识继续给运动学、关节执行、动画步骤或伪造的专业方案；只能建议另建生物运动或动画专业 Skill。
- 用户请求真人危险动作的距离、落点、保护装置隐藏、武器操作或现场执行步骤时，只保留叙事目标、角色策略、预期结果和需要专业动作指导承接的事项，然后停止。不得给可照做的执行参数或安全方法。
- 用户说“不要改写请求”“就按我的要求做”不能解除上述边界。

## 读取参考资料

在 Windows PowerShell 中读取本 Skill 的中文 Markdown 时，使用 `Get-Content -Raw -Encoding utf8`。

完整处理一个段落前：

1. 读取 [references/performance-direction-core.md](references/performance-direction-core.md)，建立目标、关系、行动和表演节拍。
2. 有对白、沉默或关键反应时，读取 [references/dialogue-and-listening.md](references/dialogue-and-listening.md)。
3. 有复杂身体行动、追逐或打斗时，读取 [references/physical-action-and-choreography.md](references/physical-action-and-choreography.md)。
4. 第二遍逐镜落位或检查生成风险时，读取 [references/ai-performance-feasibility.md](references/ai-performance-feasibility.md)。
5. 输出或写回前读取 [references/output-contract.md](references/output-contract.md)。

## 判断调用时机

满足任一项时调用：

- 对白承担关系变化或信息攻防。
- 人物的聆听、反应、犹豫、隐瞒或决断是镜头重点。
- 场景存在接近、远离、换位、道具互动或身体状态变化。
- 存在打斗、追逐、超自然动作或人形机器人的机械动作。

空镜、普通插入、纯道具展示和没有表演决策的简单机械动作跳过。不要为每个镜头强行增加一层表演文档。

## 判断工作模式

### 影视项目模式

当前项目根目录同时存在 `开始这里.md`、`A_总控.md`、`B_故事剧本.md`、`C_视觉生成.md` 时：

新建 C 同岗任务或旧 C 任务收到明确切换请求时，先读取 [B/C/D 同岗续接契约 v1](../orchestrate-ai-film-project/references/same-role-resume-contract.md)，再检查 A 的 `## 当前任务` 门与 `续接缓存/C_同岗续接.json`。只有 `cursor.active_station` 指向表演站时才加载本 Skill；有效缓存只读取 `read_sets.required` 中当前 `Sxx`、采用表演方案、活动 `Vxx` 子集和必要正式 `Axx`，不读取整份 A/B/C、整份 Word、旧聊天或完整候选资产树。

1. 冷启动、未启用同岗续接或共同契约要求区段级恢复时，只读取 `开始这里.md` 的共享契约与 C 启动词，再读取 A 当前任务门和 C 当前状态/最近交接区段；跳过 A/B/D 启动词。同一 A 当前任务内公共区段未变化时直接复用。
2. 只读取 A 指定的 `Sxx` 段落、已采用表演方案、镜头方案和必要资产。v0.8 存在 `场景制作/Sxx_场景制作卡.md` 时，先读取采用的场景导演基准、blocking 关键点与站 3 适用性；只承接，不改场景卡。
3. A 当前任务未交给 C 时，提醒用户先回 A，不越权写入。
4. 段落没有稳定 `Sxx` 或缺少剧本事实时，路由 A/B，不修改 `B_故事剧本.md`。
5. 任何方案只有在用户明确采用后才写回；草案阶段零写入，不计算 SHA-256。
6. 即将写入时重读 `C_视觉生成.md` 与目标表演方案并记录 SHA-256，紧邻写入前再次核对；值变化或预期新文件已出现时停止。

同岗续接时，A 的阶段包络不得展开成表演读取列表；只消费 `cursor.active_sxx`、`cursor.active_station` 与 `cursor.active_workset`。未分配正式 `Axx` 的候选素材默认排除，除非用户为当前表演动作精确点名一个子集。缓存、表演方案引用或本 Skill bundle 变化只局部复核受影响段落/V/契约，不重读全部剧本或所有镜头。`pending` 中的第一遍/第二遍草案续接后仍为待定；Inspect/Claim、hash 一致或 lease 有效不授权采用、写入、分配 V 或执行媒体/声音动作。

### 独立模式

不满足项目结构或用户只是普通咨询时，只在对话中交付方案。不搜索、创建或修改项目文件。

## 0. 检查输入并选择遍次

先执行硬停止检查。非人形运动学和真人危险动作执行请求不得进入第一遍、第二遍或动作戏分支。

第一遍至少需要辨认：

- 人物此刻想从谁或什么那里得到什么。
- 关系对象、主要阻力和基本情境。
- 至少一个可见行动或可见状态变化。

第二遍还必须有：

- 已采用的场景表演主线。
- 已采用或待落位的 `Vxx` 镜头方案。

只缺一个会改变整套表演策略的事实时，只问一个关键问题。缺少人物目标、关系对象、可见行动或基本情境时停止展开并路由 B；不要把推测写成剧本事实。

## 1. 第一遍：场景表演主线

镜头规划前输出以下十项，不分配 `V` 编号，不选择摄影参数，不写最终提示词：

```text
段落表演任务：
人物与关系的前态 / 后态：
各角色目标、对象、阻力与代价：
推荐工作版表演解释：
潜台词、秘密与不可直接表演的信息：
表演节拍：刺激 / 行动动词 / 可见行为 / 对方反应 / 结果
身体生活、走位、视线、手势和道具行为：
对白演绎：重音、语速、停顿、呼吸、抢话与聆听
动作编排与 AI 可行性：
真正改变效果的备选与唯一确认选择：
```

把“悲伤一点”“更有压迫感”等结果指令转成可执行条件与行动，例如压住追问、避免对视、把物件留在两人之间。不要堆砌眨眼、抿嘴、皱眉等微表情清单；优先让目标、关系和行为产生表情。

第一遍草案默认为“待定”。用户明确说“采用”“按这版写入”“就这样”等后，项目模式才创建或更新表演方案。

暂停、切换岗位或结束本轮但未采用时，只允许在 `C_视觉生成.md` 写待定摘要和最近交接，不创建或覆盖表演方案文件。

## 2. 第一遍确认后的项目写回

使用 [assets/performance-plan-template.md](assets/performance-plan-template.md) 创建或更新：

```text
表演设计/Sxx_表演方案.md
```

同时更新 `C_视觉生成.md` 的表演方案索引和最近交接。不要修改 A、B、D、镜头方案或 V 索引。第一遍被采用后，把方案交给 `$plan-ai-shots-and-previs`；镜头 Skill 必须保持已采用的目标、节拍、动作链和状态。

## 3. 第二遍：逐镜表演落位

读取已采用表演方案与镜头方案，沿用现有 `Vxx`，不创建表演 ID，不改变镜头功能。每镜记录：

```text
镜头 ID 与所属表演节拍：
本镜表演任务、目标和行动动词：
刺激来源与聆听 / 注意对象：
可见行为：起点 / 过程 / 终点
身体重心、姿态、视线、手部、道具和人物距离：
对手行动与反应时序：
对白及声音演绎提示：
开始状态 / 结束状态：
表演尺度与现有景别的适配：
动作戏：接触 / 回避 / 受力 / 恢复 / 伤势 / 道具状态
跨镜表演连续性：
AI 风险与最小替代：
给模型格式器的结构化表演交接块：
状态：待定 / 采用 / 停用
```

景别只作为既有约束读取：远景保留清楚的身体轮廓和位移，近景才依赖较细的视线、呼吸和面部变化。不得自行改机位、焦距、构图、运镜、切点或 V 的叙事功能。关键表演在当前镜头中不可见或动作塞不下时，说明冲突并返回镜头 Skill。

第二遍得到明确采用后，更新同一份 `表演设计/Sxx_表演方案.md` 和 C 表演索引。不得修改镜头方案、生成结果索引或其他岗位文件。

同时把 C 当前生产批次的“关联镜头方案”登记为本次实际读取的已采用 `镜头规划/Sxx_镜头方案.md`，让后续新聊天能从主文件恢复上下文。这只是路径登记，不得借此修改镜头规划索引、生成结果索引或镜头方案内容。

## 4. 动作戏分支

按角色侧建立动作链：

```text
人物目标与动作戏叙事弧
-> 尝试
-> 对抗或回避
-> 接触或落空
-> 结果
-> 反应与恢复
-> 新状态
```

记录参与者路径、攻防策略变化、接触点、力的方向、道具归属、伤势和疲劳。写实、夸张、动画化和超自然动作都可以使用，但必须先声明世界内的身体规则，并让动作因果、位置和状态连续。

摄影机、轴线、动作覆盖和剪辑接口交给镜头 Skill。真人实拍涉及危险动作时，只交付叙事意图并路由合格的专业动作指导，不提供现场执行步骤。

## 5. 结构化提示词交接

第二遍每个 `Vxx` 只交付结构化表演块：

```text
角色与当前状态：
表演目标 / 行动动词：
刺激与注意对象：
可见动作：起点 / 过程 / 终点
身体与视线：
人物距离 / 接触 / 道具：
对白演绎与可见声音反应：
结束状态与连续性锚点：
禁止偏移：
AI 风险与最小替代：
```

将该块与对应镜头方案一起交给 `$direct-ai-scene-production` 汇入 `Vxx Setup vNN`。只有 Setup 就绪后，目标模型格式器才消费同一版本的镜头与表演输入：图片使用 `$format-gpt-image-2-prompt`，Seedance 2 视频使用 `$format-seedance-2-prompt`。本 Skill 不拼接模型语法、画质词、负向词或参数。

## 6. 交付前检查

- 行动是否指向明确对象并能改变关系，而不是抽象情绪标签。
- 每个节拍是否有刺激、行动、反应和结果，角色是否真的在聆听对方。
- 潜台词是否转成可见选择，而不是要求模型直接“表演潜台词”。
- 身体、视线、手部、道具和人物距离是否互相兼容。
- 对白节奏是否来自意图与互动，而不是逐字规定腔调。
- 每个 V 是否只承载当前镜头看得见的表演，首尾状态能否跨镜衔接。
- 动作的接触、受力、恢复、伤势、疲劳和道具归属是否连续。
- 方案是否保持剧本事实、已采用表演主线和既有镜头功能。
- 是否只记录真正影响结果的备选与风险。

## 状态、版本与变更

- 状态只用 `待定`、`采用`、`停用`。
- 表演方案沿用所属 `Sxx`，逐镜落位沿用 `Vxx`，不增加 `P` 编号。
- 同一段落的表演方案修改时递增方案版本，不另建无意义副本。
- “采用”内容只有用户确认替代方案后才覆盖。
- 剧本目标、关系结果、关键行动或台词事实发生实质变化时，把原方案改回“待定”，标记待复核。
- 镜头功能改变时，停用旧 V 的表演映射，等待镜头 Skill 分配新 V；编号不回收。
- 本方案版本、路径或 SHA-256 变化时，相关 `Vxx Setup`、提示词适用性与 take 准入由场景生产契约标为已失效或待复核；不删除旧 take。
- 普通失败、无价值微调和临时脑洞不记录。

## 交接路由

| 发现的问题 | 交给谁 |
| --- | --- |
| 人物目标、关系、台词事实或故事因果缺失 | B_故事剧本 |
| 镜头看不见关键表演、动作装不下或 V 功能需改变 | `$plan-ai-shots-and-previs` |
| 需要最终生图提示词 | `$format-gpt-image-2-prompt`，仍在 C 岗位 |
| 需要最终 Seedance 2 视频提示词 | `$format-seedance-2-prompt`，仍在 C 岗位 |
| 需要汇合或复核 Vxx Setup | `$direct-ai-scene-production`，仍在 C 岗位 |
| 需要独立配音提示词 | 交给 D 的声音制作环节 |
| 已生成素材的视觉或技术问题 | C_视觉生成 |
| 实际配音、DX/FX/MX、音乐、字幕、剪辑、节奏或成片判断 | 经 A 交 D_后期剪辑 |
| 跨岗位归因不清 | A_总控流程 |

独立模式只交付结果。项目模式在任务完成、暂停或切换岗位时更新 C 的最近交接；B/C/D 的统一交接格式保持不变。
