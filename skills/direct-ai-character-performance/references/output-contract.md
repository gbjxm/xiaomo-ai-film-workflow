## 两遍工作顺序

```text
第一遍场景表演主线（待定）
-> 用户明确采用
-> 写入表演设计/Sxx_表演方案.md 与 C 索引
-> 镜头 Skill 读取采用方案并建立 V 镜头
-> 第二遍按既有 V 落位（待定）
-> 用户明确采用
-> 更新同一表演方案与 C 索引
```

“采用”“按这版写入”“就这样”属于明确确认；“先看看”“可能”“不一定”不属于确认。暂停时可以把有保留价值的内容记为待定，但不得伪装成采用。

## 第一遍固定输出

```text
段落表演任务：
人物与关系的前态 / 后态：
各角色目标、对象、阻力与代价：
推荐工作版表演解释：
潜台词、秘密与不可直接表演的信息：
表演节拍：刺激 / 行动动词 / 可见行为 / 对方反应 / 结果
身体生活、走位、视线、手势和道具行为：
对白演绎：重音、语速、停顿、呼吸、抢话与聆听
动作编排与 AI 可行性：
真正改变效果的备选与唯一确认选择：
```

限制：

- 不分配 V 编号。
- 不选择景别、焦距、机位、构图、运镜或覆盖。
- 不输出最终模型提示词。
- 不创建采用文件或索引，直到用户确认。
- 没有真实分歧时写“无关键分歧，请确认是否采用工作版”。

## 第二遍逐镜字段

只使用镜头方案已有的 V 编号：

```text
镜头 ID 与所属表演节拍：
本镜表演任务、目标和行动动词：
刺激来源与聆听 / 注意对象：
可见行为：起点 / 过程 / 终点
身体重心、姿态、视线、手部、道具和人物距离：
对手行动与反应时序：
对白及声音演绎提示：
开始状态 / 结束状态：
表演尺度与现有景别的适配：
动作戏：接触 / 回避 / 受力 / 恢复 / 伤势 / 道具状态
跨镜表演连续性：
AI 风险与最小替代：
给模型格式器的结构化表演交接块：
状态：待定 / 采用 / 停用
```

没有动作戏时，“动作戏”字段可省略。没有对白时，声音字段只保留会改变可见反应或节拍的声音。

## 项目模式门槛

只有根目录存在以下文件才执行项目写回：

```text
开始这里.md
A_总控.md
B_故事剧本.md
C_视觉生成.md
```

写回前确认：

- A 当前任务交给 C。
- 段落已有稳定 Sxx。
- 第一遍或第二遍对应方案已被用户明确采用。
- 第二遍使用的 V 均来自既有镜头方案。
- v0.8 已读取当前场景制作卡的采用导演基准和站 3 适用性；旧项目没有该契约时不补建。
- 待写文件没有无法解释的冲突。
- 已记录 `C_视觉生成.md` 与潜在表演方案文件首次读取时的 SHA-256；新文件记录预期不存在。
- 写前 SHA-256 复核未发现并发修改；发生变化时必须停止，不覆盖。

不满足时只在聊天中交付或路由，不修复 A/B/D。

## 项目写回

方案文件：

```text
表演设计/Sxx_表演方案.md
```

首次采用第一遍时，按 [../assets/performance-plan-template.md](../assets/performance-plan-template.md) 创建文件。第二遍确认后更新同一文件，不另建逐镜文件。

C 表演方案索引：

```text
| 段落 ID | 方案文件 | 状态 | 方案版本 | 关联镜头 | 当前问题 |
```

- 第一遍采用但尚无镜头时，关联镜头写“待规划”。
- 第二遍采用后，填写实际 V 范围或离散 V 列表。
- 修改同一方案时递增版本，如 `v02`。
- 方案状态只用待定、采用、停用。

同时更新 C 的“关联表演方案”和“最近交接”。第二遍采用后，还必须把 C 当前生产批次的“关联镜头方案”登记为本次实际读取的已采用镜头方案路径；这里只登记路径，不改变镜头方案或 V 状态。禁止修改：

- `A_总控.md`
- `B_故事剧本.md`
- `D_后期剪辑.md`（未迁移的既有项目可保留旧 D 主文件名）
- `镜头规划/` 中的方案文件
- C 的镜头规划索引和生成结果索引
- 已有媒体、提示词卡和无关资产

## 版本与失效

- 使用所属 `Sxx` 和现有 `Vxx`，不创建表演专用 ID。
- 剧本的目标、关系结果、关键行动或台词事实实质变化：方案递增版本并回到待定，标“待复核”。
- 只改措辞或不影响执行的说明：可在当前版本修正。
- V 的技术实现改变但功能不变：保留 V 映射，复核表演尺度和状态。
- V 功能改变或被停用：停用旧映射，等待镜头 Skill 的新 V，不回收编号。
- 采用表演方案版本、路径或 SHA-256 改变：相关 `Vxx Setup`、提示词适用性和 take 准入结论进入失效或待复核；旧文件和真实 take 保留历史。
- 采用内容不能被未确认候选覆盖。
- 草案阶段零写入；暂停或切换岗位只能写 C 的待定摘要和最近交接。

## 镜头 Skill 接口

第一遍表演方案被采用后，`$plan-ai-shots-and-previs` 必须读取它并保持：

- 角色目标、对象和主要阻力。
- 场景表演任务与关系前后态。
- 已采用的表演节拍、行动链和关键反应。
- 人物与道具的开始、结束和必要中间状态。

镜头 Skill 决定摄影机、空间基准、覆盖、V 编号和剪辑接口；不得重新解释或代写表演。若表演与空间或生成约束冲突，应显式返回 C 讨论，不静默覆盖。

## 模型格式器接口

v0.8 先把下列内容连同本方案精确版本、路径和 SHA-256 交给 `$direct-ai-scene-production`，成为 `Vxx Setup vNN` 的表演输入。Setup 就绪后调用 `$format-gpt-image-2-prompt` 或 `$format-seedance-2-prompt` 时同时提供：

1. 对应 V 镜头方案。
2. 同一 V 的结构化表演交接块。
3. C 已采用的视觉与资产固定项。

本 Skill 不拼接最终提示词。模型格式器不得把待定备选混入当前采用版，也不得补写未确认信息。

## D 读取接口

D 可以只读已采用表演方案中的：

- 对白重音、语速、停顿、呼吸、抢话与聆听。
- 动作结果、反应、恢复和连续性锚点。
- 场景表演任务与关系变化。

D 用它指导实际配音、声音和剪辑，但不能回写表演方案。发现成片层面的表演问题时写入 D 自己的文件，并经 A 路由 C/B。

## 独立模式

- 不搜索或猜测项目路径。
- 不创建表演设计目录、方案文件或 C 索引。
- 第一遍不虚构 V；第二遍只使用用户提供的 V。
- 交付后说明下一步接口即可，不代做镜头规划或最终提示词。
- 非人形运动学请求只输出边界和正确路由，不提供任何关节、步态或动画执行方案。
- 真人危险动作执行请求只输出叙事意图和专业动作指导交接，不提供距离、落点、保护装置、武器操作或现场步骤。
