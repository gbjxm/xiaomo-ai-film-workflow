# V0.9 资产与镜头结果接口

本分支支持候选输入核对、准备结果记录结构，以及对用户已提供真实证据的只读审查。共同契约和能力文件控制执行范围；候选与采用文本按实际能力使用 SaveDraft/Adopt，已采用输入先 Resolve；无 V1 发布标识时本分支不执行生成；入口另有唯一 `workflowRelease: 1.0` 时，明确授权的图片请求按共同契约 [V1 原生图片工具](../../orchestrate-ai-film-project/references/studio-v09-contract.md#v1-原生图片工具) 执行，视频仍保持原方式。不自动分配 batch/take，不能用旧 Vxx Setup 流程绕过能力限制。

## 两类对象，不制造镜头 ID

| 对象 | 来源与职责 | 结果记录约定 | 审查重点 |
| --- | --- | --- | --- |
| Axx 资产 | C1 基础或状态设计，必要时附 C2 场景用途 | 输入绑定 Axx 及资产/状态版本；执行坐标为 Axx-Bnn-Tnn | 身份、比例/尺度、几何、材质本色、状态与参考污染，是否能承担预期复用用途 |
| Vxx 镜头 | C2 当前镜头/表演/光色整案及参考职责 | 输入绑定 Vxx 及相应 Setup 版本；执行坐标为 Vxx-Bnn-Tnn | 可见事件、表演/接触/恢复、空间与声画连续性、画面信息和相邻镜头接口 |

以上坐标是专业结果记录约定，文本运行时不自动生成媒体或分配编号。已有真实坐标可照实引用；没有正式对象时用本稿局部标签作为候选试验记录，不为资产补造 Vxx，不为试验分配 Axx。batch/take 仍是执行坐标，不新增影视稳定 ID。

资产输入不要求先有镜头 Setup；镜头输入才使用镜头 Setup 的职责。两类都需要明确用途、当前设计版本、参考职责及验收目标。候选输入完整只说明可提交用户审阅，不能标成冻结 Setup 或正式准入。

## 记录接口最小内容

给每个需要记录的真实对象保留：对象类型与实际 ID/局部标签、用途、输入设计和精确复制层版本、实际参考及职责、工具/模型与已知参数、真实输入/输出位置、batch/take（如已有）、实际可见差异、限制、用户决定和下一步。不存在的值明确记未取得，不能补成功路径、日期、参数或 hash。

在明确启用的 V0.9 项目用上述字段整理完整候选，通过 SaveDraft 保存；明确采用的真实结果记录由所属 C1/C2 准备文本经 Adopt 提交。只读咨询不计算无关媒体 hash；正式证据仍需实际核验。文本事务核验文本版本，不能替代媒体审看或把编造的路径/hash变成事实。

## 精确复制层与实际媒体

C1/C2 明确提交的整合候选可以检查是否自包含、参考职责是否冲突、显示意图是否具体；格式器的复制层保持原样，诊断和候选状态位于框外。缺少专业内容返所属 C 专业；纯编排错误返格式器，本 Skill 不重写创意。

没有媒体时只能检查方案和输入结构，结果状态保持“等待执行/等待媒体”，不能给画质、动作效果、已准入或可剪结论。媒体可访问时实际查看/核听相关内容，区分可见事实、生成偏差、创作解释与修正假设；参考声明不等于已检查素材。文件不可读则报告具体证据缺口。

## 结果反馈与相邻责任

- 资产问题返 C1：身份、材料、结构、尺度或状态不对；镜头对该资产的用途不成立时同时交 C2 调整用途。
- 镜头问题返最接近证据的专业：表演/动作、摄影光色、参考职责、模型限制；C2 统合最小返修，不因一次失败推翻整案。
- 用户实际组接的节奏或声画问题交 D 判断，C 自检和独立审查都不能替代真实组接证据。

“推荐/备选/停用”先作为待用户决定的审查建议。用户明确决定后，能力开启时经 Adopt 提交对应文本；能力关闭时仅保留决定。后续消费以 Resolve 返回的快照为准，中断按 ResumeSync 回执区分采用与视图同步。正式 C 准入仍需真实证据，不得把建议或文本提交自动变成准入通过。

## 生成原片的整理与取用

用户需要把新下载的生成视频按片段归位、区分多条结果或查找可用区间时，交 `organize-ai-film-media`，复用已有对象/局部片段名和真实结果意见。一条生成视频可包含多个镜头，也可只贡献部分区间；不为文件归类补造 V 编号。整理工具只维护机械文件索引，C 的正式生成事实、审查建议与采用仍由本专业记录；归位后保存真实返回路径，不把“已复制”当作准入。
