# AI 媒体生成与结果审查

## 项目版本路由（先判断）

只依据当前业务项目 `开始这里.md` 的显式 `workflowStudio: studio-v0.9` 选择新分支；Skill 路径、候选目录名或聊天标题都不是项目标识。可复用主调用方本轮已核实的入口与能力结果。

- 有该标识：先读 [V0.9 共同契约](../orchestrate-ai-film-project/references/studio-v09-contract.md) 与项目能力状态，再读 [本专业的 V0.9 候选分支](references/studio-v09-candidate.md)。仅执行该分支；不进入下方旧版的唯一 A 目标、逐项采用、同岗租约或正式写回流程。专业知识按该分支指向读取。
- 无该标识或不在项目中：不加载 V0.9 分支，继续下方原有模式和边界。无法核实标识时，不凭目录推断启用新能力。

只负责“核对就绪 Setup → 原样记录已采用提示词 → 独立执行授权门 → 逐 take 事实 → C 准入审查 → 功能化 coverage 与最小返修路由”。提示词卡使用 [提示词卡模板](assets/prompt-card-template.md)，默认适配器见 [manual-copy 契约](references/manual-copy-adapter.md)，真实 batch/take 使用 [生成记录模板](assets/generation-record-template.md)。

## 进入项目模式

没有项目目录时只给方法或检查框架，不写文件、不声称执行。

新建 C 同岗任务或旧 C 任务收到明确切换请求时，先读取 [B/C/D 同岗续接契约 v1](../orchestrate-ai-film-project/references/same-role-resume-contract.md)，再检查 A 的 `## 当前任务` 门与 `续接缓存/C_同岗续接.json`。只有 `cursor.active_station` 指向数字拍摄/生成或场记审查站时才加载本 Skill；有效缓存只加载 `read_sets.required` 中当前 `Vxx Setup`、提示词卡、点名 take/生成记录和必要正式 `Axx`，不读取整份 A/B/C、整份 Word、旧聊天、完整候选资产树或全部媒体。

项目模式依次执行：

1. 冷启动、未启用同岗续接或共同契约要求区段级恢复时，只读取 `开始这里.md` 的共享契约与 C 启动词，再读取 A 当前任务门和 C 当前状态/最近交接区段；跳过 A/B/D 启动词。同一 A 当前任务内公共区段未变化时直接复用。
2. 只读取 A 指定的关联 `Axx/Vxx/Sxx`、必要资产、色卡、表演、镜头、场景制作卡、当前 `Vxx Setup vNN`、已有生成记录，以及以下两种提示词来源之一：用户明确采用的模型格式器复制层，或状态为采用且仍适用的既有提示词卡。
3. v0.8 的 Vxx 必须先核对 Setup 执行有效性为 `已冻结`，并验证其精确版本、实际输入路径/hash、Profile、工具限制与输出规格。缺一项、冲突、路径/hash 不符或 Setup 已失效时停止；旧项目没有该契约时按项目版本兼容，不补建。
4. 新复制层必须能确认对象 ID、用途、Setup、来源格式器、目标工具、适配器和输入文件；既有提示词卡必须包含对象 ID、用途、持久状态、执行有效性、版本、Setup、来源格式器、目标工具、适配器、固定约束、变量内容、最终提示词、关联 take 和下一步。缺少会改变执行或追溯结果的字段时，只问一个关键问题。
5. 代码块外的补充建议、诊断状态和解释不属于提示词来源，不得写入提示词卡或提交给生成工具。
6. 区分“Setup 已冻结”“采用提示词”“采用生成方案”和“授权执行生成”。任一前置状态都不能替代真实执行授权。
7. 在建立提示词卡或执行 `manual-copy` 前，对格式器复制层做失败关闭检查：代码块不得依赖 `Sxx/Axx/Vxx/Setup`、岗位名、项目版本、路径、SHA-256、项目基准名称或“见上文/沿用基准”等内部引用；多参考输入必须有职责、允许继承、禁止继承、优先级和唯一活动状态。内部追溯元数据继续保存在复制层外，不因该检查删除。
8. 最终场景、人物入景、电影静帧或视频镜头必须有上游已经确认的 prompt-ready 显示意图，覆盖当前用途所需的光影、质感、氛围与色感；中性资产/结构测试须有明确用途与中性理由。仅有器材名、抽象电影词或负面约束不合格。缺少显示意图或仍有未展开内部引用时不得在本 Skill 补写，返回 `$direct-ai-scene-production` / `$cinematic-palette-architect` 的外部自包含组装层；内容已经完整、只存在忠实编排或代码块格式问题时才返回对应图片/视频格式器。

同岗续接时，A 的阶段包络不得展开成生成读取列表；只消费 `cursor.active_sxx`、`cursor.active_station` 与 `cursor.active_workset`。未分配正式 `Axx` 的候选图和未点名媒体默认排除；只有采用的正式对象或用户为当前审查精确点名的 take 子集才可读取。缓存、Setup/提示词卡引用或本 Skill bundle 变化只局部复核受影响 V/take/契约，不扫描所有生成记录或媒体。`pending` 中的格式器草案、未采用提示词和审查建议续接后仍为待定；缓存里的 `authority.observed`、Inspect/Claim、hash 一致或 lease 有效都不构成提示词采用、项目写入或真实生成授权。

## 提示词卡原样记录

- 图片提示词只接受 `$format-gpt-image-2-prompt` 的复制层，Seedance 2 视频提示词只接受 `$format-seedance-2-prompt` 的复制层；不得重新调用另一套格式规则。
- 只有用户明确采用复制层后才建立或升级提示词卡。复制层中的文字、栏目、顺序和约束必须逐字保存，不得补写、删减、润色、压缩或改成另一种模板；Setup 元数据写在复制层外。
- 失败关闭检查未通过时，不建立新的提示词卡版本、不提交工具、不输出可执行 `manual-copy`；只报告最近责任层和一个最关键缺口。已存在历史卡片保持原样，不得把不合格复制层覆盖为当前版本。
- 提示词卡沿用现有 `Axx` 或 `Vxx`，本 Skill 不分配稳定对象 ID。同一对象和用途不变时提升版本；对象或用途改变时返回上游确认。
- 使用提示词卡模板记录 Setup、来源格式器、关联色卡、实际输入文件路径/hash 和完整复制层，并更新 `C_视觉生成.md` 的提示词卡索引和最近交接。
- 明确采用提示词只授权记录卡片，不授权生成。用户随后授权执行时，再进入执行路由。

## 执行路由

### 有已授权且可用的工具

- 在工具权限范围内提交采用提示词卡。
- 每次执行先分配下一个 batch 坐标 `Vxx-Bnn`；每个真实输出分配 `Vxx-Bnn-Tnn`，保留真实工具名、时间、实际参数、输入文件路径/hash、输出路径/hash 和工具返回状态。
- 工具失败时原样记录失败，不补造输出。

### 没有工具或没有执行授权

- 使用 `manual-copy` 输出可直接复制的提示词、输入文件清单、设置项、建议批次数量、`Vxx-Bnn-Tnn` 命名规则和验收标准。
- 明确标记“等待人工执行”；不得写“已生成”“生成成功”或虚构结果路径。
- 用户带回文件或真实生成日志后，再进入审查。

## 结果审查

只审查真实可访问的图片、视频或完整生成日志。逐个 take 核验路径和 SHA-256，并按四层记录证据：

1. 创作目标：内容、情绪、动作和叙事信息是否满足 `Sxx/Vxx`。
2. 连续性：角色、场景、道具、空间、动作和跨镜状态是否满足 `Axx` 与表演/镜头约束。
3. 单文件技术可用性：时长、帧率、音轨、画面稳定、肢体、口型、焦点、运动、遮挡、编码、首尾把手和可用接口。
4. 可修范围：单次重试能否解决，还是必须返回上游。

问题只能归入以下一个主责任层；必要时列一个次责任层：

| 层级 | 判定依据 | 返回 |
| --- | --- | --- |
| 故事 | 剧本目标自相矛盾或无法在该时长呈现 | B，经 A 调度 |
| 资产 | 身份、材质、尺度或固定连续性缺失 | `$design-ai-film-assets` |
| 表演 | 意图、动作、反应或节奏不可执行 | `$direct-ai-character-performance` |
| 镜头 | 景别、机位、时长、运动或覆盖不足 | `$plan-ai-shots-and-previs` |
| 提示词 | 已有要求未清楚传给工具 | 图片返回 `$format-gpt-image-2-prompt`；Seedance 2 视频返回 `$format-seedance-2-prompt` |
| 模型限制 | 输入明确但工具能力或随机性仍无法满足 | 换批次、简化或适配器方案 |
| 剪辑 | 单镜可用，问题可能在选择、节奏、声音或衔接解决 | 经 A 路由 `$edit-and-finish-ai-film` |

不得因一次失败升级为全故事重写。先提出影响面最小、能被下一次生成验证的返修。

### C 准入与 coverage

每个真实 take 只标：

- `推荐`：C 证据显示最符合当前目标，优先交 D 比较；
- `备选`：有明确用途或限制，仍可交 D 独立选择；
- `停用`：存在可定位的创作、连续性或单文件技术阻塞，不进入常规 D 选择。

C 准入不等于 D 入片选择；推荐不强制 D 使用，D 不得静默使用停用 take。C 的结论最多为“当前 C 准入自检通过，可交 D 组接候选”，不得写“已经证明可剪”或“客观覆盖完成”。

coverage owed 必须按 `叙事信息 / 关键反应 / 动作阶段 / 空间基准 / 必要插入 / 声音或口型接口` 描述，写明 `S/V、现有素材为何不可替代、最近责任站和所需证据`。禁止只写“缺近景”“重做”“再来几条”。

## 写入门与交接

- 格式器草案、结果诊断和只读审查阶段零写入，不计算 SHA-256。
- 用户明确采用并即将写入时，重读所有目标并记录 SHA-256，紧邻写入前再次核对；发生变化或预期新文件已出现时停止。
- 采用复制层后，只写对应提示词卡、`C_视觉生成.md` 的提示词卡索引和最近交接。
- 生成或审查阶段，用户明确采用审查结论后，只写 `C_视觉生成.md` 的生成结果索引、当前 Setup/coverage 摘要、当前生成问题、最近交接，以及 `生成记录/Vxx_生成记录_vNN.md`。C 交 D 素材清单由 `$direct-ai-scene-production` 汇总。
- 暂停或切换时只写 C 的待定摘要和最近交接，不把结果或返修升级为采用。
- 不分配 `Sxx/Axx/Vxx/CUTxx`；batch/take 只是执行坐标。不得写 B/D 文件、修改正式时间线或执行剪辑。
- 交接必须列出 Setup、提示词卡、生成记录和每个 take 的精确版本/路径/hash、推荐/备选/停用、实际差异、功能化 coverage、主责任层、最小返修、下一 Skill，以及是否仍等待人工执行。
- 导演/资产/色卡/表演/V/输入/Profile/限制任一锁定输入变化时，把旧提示词适用性和相关 take 准入结论标为失效或待复核，保留旧文件；不得静默沿用。
