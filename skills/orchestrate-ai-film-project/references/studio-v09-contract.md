# 小陌工作室 V0.9 共同契约

本契约适用于项目入口显式声明 `workflowStudio: studio-v0.9` 的工作室协议；产品 V1 在相同协议下另以唯一 `workflowRelease: 1.0` 选择下文发布差量。Skill 所在目录、机器安装版本、聊天名称都不能替代项目标识。无标识时原 v0.8/旧项目契约保持不变。

## 版本入口与当前可执行范围

命中 V0.9 后，先读项目工作室能力.json。字段描述实际实现状态，不是用户权限开关。早期 false/false 项目只支持隔离候选设计；runtime_schema=xiaomo.studio-runtime/v1、workset_runtime=true、adoption_transactions=true 时，使用 [工作集与保存接口](studio-runtime-v1.md)。media_execution 只描述工作室运行时内置媒体功能，保持 false；独立达芬奇工具按本页“D 独立达芬奇原生工具”分支判断，不改该字段。

- 六部门候选咨询、前期联合设计、完整稿、候选提示词、知识证据和独立审查按实际任务组织，不逐专业索要采用。
- 在当前明确启用的 V0.9 项目中以 Create/SaveDraft/Inspect 管理各自工作内容；用户采用后由所属专业准备文本，用 Adopt/ResumeSync 保存与恢复，消费 Resolve 返回的不可变采用版本。不以旧单 C 脚本替代。
- 相应工作集或采用事务能力为 false 时保留候选和明确决定，不伪报自动保存、采用事务或接管成功。普通元数据读取、文件存在或 Claim 都不能变成采用证据。
- 日常制作只读项目入口、能力、当前工作集和必要专业材料；维护 HANDOFF、备份与升级历史不是日常读集。
- 无 V1 发布标识的项目，C 的实际生成仍由用户操作；V1 图片执行按下文“V1 原生图片工具”，视频保持原分支。D 组接与后期可接回用户结果，或按下述独立达芬奇分支执行。软件能力通过、正式安装和项目接入不等于真实影片效果已验证。旧项目只在明确接入后启用本契约。
- V0.9 分支不执行旧正文的 A 唯一目标岗、逐专业采用、单岗位缓存或旧写回步骤；专业知识按需复用。

## 项目资料目录

入口另有 `workflowDocsLayout: production-docs-v1` 时，先按 [制作资料路径约定](studio-project-layout-v1.md) 解析各专业资料位置；这只改变列明目录的物理位置，不改变专业职责或采用语义。无标识项目保持原目录，不因安装升级搬迁。读取引用与生成后续保存请求时使用真实路径。

## 六部门、专业责任和任务

| 部门 | 责任 | 最小交付 | 所有权 |
| --- | --- | --- | --- |
| A 制片统筹 | 作品目标、范围、资源、进度、依赖及里程碑 | 制作约束和当前有效指针 | A 总控记录 |
| B 编剧开发 | 人物、因果、剧情、对白和故事层连续性 | 故事候选及改动理由 | B 剧本与 S 对象 |
| C1 美术与资产 | 视觉世界、角色、场景空间、服化道、材料和状态 | 资产设计与实际参考职责 | C 资产对象及其专业正文 |
| C2 导演与视听制作 | 从前期至后期持续统合观众体验、调度、表演、摄影灯光、节奏和生成意图 | 项目导演基准及整合片段方案 | C 场景、表演、镜头和提示词对象 |
| D 剪辑与声音后期 | 前期剪辑/声音咨询、真实组接诊断、影片完成和 QC | 前期接口或实际后期结果 | D 后期、CUT、组件及 Master |
| E 发行与复盘 | 发行包装、资格、封面、真实发布与反馈 | 精确发行包及复盘 | E/PUB 与发行素材 |

用户保留最终创作决定。A 处理制作组织，C2 处理创作整合；C2 在资产定稿前参与，不是等 C1 全部结束才启动。C1/C2 是原 C 的部门标签，不新增影视稳定 ID。部门不等于一个永久聊天；多个工作内容可分别开短任务。用户要求新开/续接时才创建可见任务；内部专业分工用受限子代理。

V1 入口（唯一 workflowRelease: 1.0）另支持用户明确要求的六岗位批量初始化：由 `start-ai-film-project` 的[岗位任务初始化](../../start-ai-film-project/references/role-task-launch.md)生成并执行完整启动包。当前任务为 A，仅补缺失的 B/C1/C2/D/E 可见待命任务；这不启动业务、不新建或接管工作集、不恢复旧派岗门禁。空任务不执行 PrepareHandoff；仅接替同一个已有工作集才使用工作集交接。脚本准备成功与真实建岗、待命回执分别验收；没有原生任务工具时不能用子代理替代。

## 三层事实与候选模式

1. 项目共同基准：明确用户事实、采用的故事/资产/风格、接口、不可改项和实际制作限制。
2. 当前工作稿：本片段/资产完整候选、参考职责、依据、剧情差量及下一步。候选可完整创作，不能继承为采用。
3. 本次聊天：只加载必要事实、工作稿和本次差量；不复制整片历史、全部资产或所有知识主题。

用户说“设计这段”即可开始专业候选，不需要先取得每项表演或镜头策略的采用。未指定的拍法、灯光、动作、对白等由所属专业提出；原剧情的变化列为候选差量。明确不可改的事实仍保留。只有无法从当前资料恢复且会改变任务身份或违反硬约束时，问一个决定性问题。

没有正式 S/A/V 时使用本稿内的“片段/角色/镜头一”等局部标签。已有正式 ID 可引用，不分配新的稳定 ID，不冻结 Setup，不把候选通过或演练当成 B 阶段完成、C 准入或 D 可剪证明。

## 创作理由随稿交接

换任务、跨专业或新工作集，以及用户明确要求承接已有讨论进入新项目时，由交出材料的当前专业整理影响接收方下一步选择的理由。正常同任务修改只同步相关变化，不增加交接问卷、逐项确认或额外台账。

**理由随当前完整稿保存。** 在已有的意图、差量、依据或下一步区段，按需写明表达目标与观众体验、当前选择及有据理由、已否决方案及当时条件、必须保留/允许调整/未决定的部分，以及必要来源与状态。用户明确表达、专业建议、人物行动动机和未知信息分别说明；不能从终稿倒推作者意图，或把人物动机、助手建议记成用户决定。只保留会影响接收任务的可读内容，不复制整段聊天或把普通局部反馈升级成全项目规则。

正文是理由的主要载体，现有 metadata 只保留简要提示或出处，不新增字段约定。局部提交 metadata 时从当前值合并明确差量，保留未点名的参考职责、不变量和取舍；本接口接收整体 metadata，不能只传改动的一项而抹掉其余内容。旧理由仅存于 metadata 时，实际读取 state 并对照当前稿和来源；有据且仍适用的部分在下一次既有保存中补入正文，不为整理背景另开写入事务或提升采用版本。

| 交接类型 | 交出与接收动作 |
| --- | --- |
| 同工作集换任务 | 按已有能力保存完整稿，再办理本工作集交接。接收方实际读取完整稿、state 和相关依赖；Inspect 成功或 metadata 摘要哈希不代表已读取理由。缓存缺失仍从保存稿与状态恢复。 |
| 跨部门或新工作集 | 上游随专业材料给出与目标任务相关的理由和精确出处；接收专业据此形成自己的完整工作稿并登记实际依赖。Create 不自动继承来源内容，不通过转移旧工作集租约代替新工作集。 |
| 旧讨论进入新项目 | 仅在用户明确要求承接时，当前前台整理已提供或精确指定的最小来源内容，与原启动词并列交付；接收专业按目标能力保存到现有工作稿。必要理由在目标项目内可读，不能只留不可访问的旧链接或登记越界文件依赖。来源身份与历史采用状态只是出处，不自动迁入旧编号、新项目采用身份或外部执行授权。 |

**接手后用于下一步判断。** 首次实质工作用一两句话说明当前表达目标对下一步选择的影响，然后继续任务；首次仅确认恢复保持轻量，不每轮复述。理由与材料未变时复用已读结果，只有对象、来源或决定变化才定点复核。来源确实缺失时保留未知，不全量搜索旧聊天补造理由；只有缺口影响当前关键选择时问一个问题，其余可继续的工作照常推进。

**决定变化只更新相关范围。** 用户明确改方向后，保留原理由的历史出处，让相关旧理由退出当前约束；因旧片长、资源等条件否决的方案不成为永久禁令。仅探索另一候选时，原采用决定仍有效。局部采用只提交点名内容及其成立所必需、已呈现的理由，其余候选、否决记录和未知留在候选稿；采用记录引用整稿不等于整稿全部采用。下游读取采用对象时同时取得影响当前执行的理由及其状态，不能把只拿到正文当作理由已完整交接，也不为补背景改写已采用正文。

## 前期联合设计与资产/镜头接口

先从故事目标提取事件、观众理解和情绪路径，再让 C1、表演、摄影及 D 前期咨询检查设计能否共同成立。形成一个推荐整案供用户集中审阅，不逐部门会签。

- 基础资产：人物身份/材料本色、场景几何/出入口/可用光源、道具形态及用途。
- 状态资产：故事阶段引起的服装、发型、伤损、道具及环境变化。
- 镜头参考：本镜机位、构图、人物状态、光影、运动起止及剪辑接口。

图片按用途路由：角色/场景设定归 C1；分镜、镜头关键帧和机位示意归 C2。场景母图不锁所有机位；棚拍背景/棚拍光不自动进入镜头；参考未显示的空间必须标假设或待验证。

生成前 Look 由 C2 整合摄影/配色意见，C1提供材料本色和场景条件，D判断后期接口。写出具体光源、方向、光质、反差、曝光、色彩落点及成像质感；不要只写机型、滤镜名或“电影感”。基础资产和带本镜 Look 的图分开，避免强光影妨碍后续用途。最终匹配与调色仍归 D。

## 专业协作和知识使用

C2 先明确共同创作意图、当前最难的问题和不可改项；按实际问题选择专业，不固定全开所有 Skill。复杂片段通常可并行咨询资产/空间、表演/动作、摄影/光色；摄影初案须等待空间和动作结果对齐后才能定逐镜。需要改变故事的部分交 B 给候选意见。D 可在任何前期任务中提供受限咨询，不必切换 A 当前岗或接管媒体。

使用当前可用子代理，模型和推理等级继承父任务；不修改全局配置。每个专业只接共同约束、相关材料及明确问题，返回具体决策、依据、与其他专业的依赖/冲突和未决项，不返回完整聊天或泛泛专业长文。主代理整合，子代理不并发改共享主文件。并发槽不足时按依赖分批，不伪称已独立协作。

新片段的重要专业判断先读[知识桥契约](knowledge-bridge-contract.md)，由工作室主动用现有知识桥 `--review --query --question --material` 检索。按当前实际检查项取证，读取返回的必读完整段落、条件和反例；引用必须影响具体判断。各专业分配所需证据，避免重复读整库。C1/C2 调用现有桥时统一使用 `--role C`，在 stage 中注明 C1/C2 与专业任务；不向旧桥传入不支持的角色枚举。同一问题/对象/知识快照未变时复用。库外或缺据明确标为专业推断/待验证，不编造来源；当前平台能力另核验官方信息。不得写知识树正文或正式关系。

## 整体审查与交付

整合后由没有参与该稿创作的子代理审查：只给原始需求、必要上下文/参考事实、完整候选及其版本；不给作者的“已通过”自评。不可获得独立审查时明确该项未完成，不把自检写成独立审查。

审查先复述观众从画面能够得到的事件链，再定位实际问题：动机/因果断点、可绕行障碍、空间或视线冲突、不可见反应、受力与动作阶段、时间过载、参考污染、剪辑或声音接口缺失。每项指出具体镜头/动作、后果和最小修正。创作方定点修复，复核发现项和相邻依赖；存在阻断时不能交“可直接生成”结论。

当前稿只维护一份可编辑整案，交付至少包含：

- 整段导演意图、剧情候选差量及关键取舍；
- 必要资产、真实已有参考与待制作素材的区分、各参考职责；
- 人物与空间首尾状态、逐镜动作/反应、摄影光色、声音及前后接口；
- 可复制候选提示词，及未解决的关键限制；
- 精简知识依据和独立审查的具体处理结果。

外部复制层不含项目内部 ID/路径/hash、“沿用上文”等依赖；只引用真实存在且已明确职责的外部素材标记。没有图片时可给文生候选，不虚构图片编号。平台上传标记先按当前交付目标统一约定，再交格式器；已有标记约定不得在局部修改或续接时回退。

格式器只忠实编排 C2/C1 已整合的本版候选输入，不再创造剧情。候选声明放复制框外，避免污染生成提示词。时间段顺序递增、不重叠；同镜延续和实际切镜写清。用户只修改一处时，以上一版完整稿为基线，仅重做受影响专业及依赖，完整返回，不顺手重设计。

## 既有项目的保真接入

接入保留已有剧本、素材、稳定编号、采用版本和真实制作状态。已有采用事实可按准确原采用证据导入运行时，必须标为迁移导入，不能冒充本次新创作采用。单一旧文件内已有多个正式编号时，保留其原文件结构和编号映射，不为迁移拆分剧本。

项目入口明确列出的兼容基线可以保存尚未转入运行时的既有采用输入：必须给精确不可变快照、原路径/区段、hash、原版本及采用证据，以 file 依赖读取。它与运行时新采用索引的范围必须明确；不得把空索引理解为没有历史采用，也不得把待定稿导入为采用。发生新的采用或原文件变化后重检相应依赖，不静默沿用旧基线。

## 生成视频整理工具

`organize-ai-film-media` 按“片段—完整生成原片—源时间区间”整理用户点名的文件，不要求一文件对应一镜头，也不要求先选出一条整段赢家。用户明确尚未导入剪辑软件的新增文件可复制归位；已导入或状态不明的文件保持原路径。工具不处理生成、转码、剪切或时间线，不改变 media_execution。

该工具独占资料目录 `生成记录/素材整理/` 下的机械索引（有 production-docs-v1 时在90_制作资料下）。这不是正式 C 生成记录、准入或 D 使用表，不向采用索引提交创作对象，不分配影视编号；索引内部键只服务文件定位。已有专业意见与使用记录保留来源，不另建第二份权威台账。原片时间区间与时间线位置分开，复制/登记成功不代表实际审看、可剪或采用。

## 实际制作与记录约定

未声明 V1 发布标识的项目仍由用户执行 C 的外部生成；V1 图片使用下节独立工具分支，视频生成保持原方式。D 后期默认使用经实际核验且获得本次执行授权的独立达芬奇原生工具，也可按用户当次选择接回手工结果。采用设计/提示词不授权生成、上传、剪辑、封面改写或发布。真实结果到来后检查实际可见内容；没有媒体不声称画质、动作或剪辑效果已验证。

先对影响较大的未知做少量试样，保留预期、输入、实际结果、耗时/费用及差异；不强制每个简单镜头试样，不用一次成功代表全片。资产结果绑定 Axx，镜头结果绑定 Vxx，batch/take 为各自执行坐标；不为记录资产而制造 Vxx。没有正式对象的试验仅作本工作稿的候选证据。

场记持续维护真实状态和差异；独立审查针对具体方案/媒体发现问题。D 可用用户实际组接进行早期诊断，正式 CUT、Lock、Master/QC 和 E 发行条件仍须真实证据。

## V1 原生图片工具

仅当当前项目入口另有唯一 `workflowRelease: 1.0` 时启用本节；产品版本不改变 `studio-v0.9` 协议或文本运行时 schema。无此标识的旧项目保持原生成分支。未知、重复或冲突的发布标识停止该次执行，不从机器版本补齐。

用户明确要求生成或编辑图片，当前设计、用途、必要参考和输出范围足够，且原生工具真实可用时，由当前 C 前台按需调用 `produce-and-review-ai-media` 承接执行与记录，默认使用已有 Codex 原生图片能力。用户指定其他工具时遵从当次选择；只有确认方案、采用提示词、讨论改法或要求检查，不触发图片执行。缺口只问会影响本次执行的问题，已有授权和输入不重复确认。

- C1/C2 负责设计与专业判断，格式器只转换已整合输入，执行方使用实际核定的复制层；工具接口必需的适配若改变画面含义，应回到当前专业讨论，不能暗改创意。编辑前实际查看用户指定原图，不根据文件名猜图。
- 该调用是独立工具动作，不由 Create/SaveDraft/Adopt 生成图片，`media_execution` 仍为 false。工具不可用、失败或只返回部分结果时说明事实；不自动重试产生额外投入，不擅自转付费平台或扩大批量。
- 记录实际工具、输入版本、参考职责、真实返回文件和可核实参数；未暴露的模型版本或参数记为未知。按项目已有路径约定保存可用产物，检查实际图片后再给专业判断；生成成功不等于采用或准入通过。
- 独立图片调用不扩张视频生成、D 剪辑、E 封面、上传或公开发布权限，也不将人物/场景/镜头图片的授权转授其他用途。用户暂停时保留当前事实，不继续执行。

### D 独立达芬奇原生工具

D 保持 `edit-and-finish-ai-film` 一个主入口及原有正式记录所有权，按需调用 `grade-film-in-resolve` 专业调色与 `davinci-resolve-mcp` 技术接口，不增加部门或第二套状态。工具接口不决定创作，专项/工具技能不创造 CUT 编号；D 主流程的 CUT/Lock/组件与 Master 规则不变。

`media_execution` 不控制独立 Resolve 官方 API/MCP 调用。只有本次所需接口真实可用、用户已授权该动作及输入/工程/输出范围时，才执行独立调用；false 不误挡已满足条件的动作，true 不自动授权。后台操作不占键鼠，不借机启用 Computer Use，也不默认用外部 FFmpeg 调色代替原生工程。API 文档、安装或连接成功不证明所有 Color/Fusion/渲染功能可控，实际支持范围与效果分别记录。

调色默认在同一原生工程内持续调整用户指定的一版，明确测试时才制作原版与三个候选，方向按影片决定。原生保存、恢复点、工作稿和导出不自动成为采用；正式采用后才由 D 按已有契约更新相应 PIC/调色指针与实际受影响的 Master/QC 依赖。该分支不打开工作室运行时内置媒体功能、不改变其他岗位生成规则，不授权项目迁移、C 生成、封面改写、上传或公开发布。

## 工作集运行与采用

运行接口唯一说明见 [工作集与保存](studio-runtime-v1.md)。工作集是上下文范围，影视对象是版本范围。C1/C2 各存完整稿、运行登记和短缓存；同对象提交另检查版本、所属专业、依赖与稳定编号。

“采用这版”指向当前呈现的精确整稿；局部采用按点名范围处理，并兼作对应记录授权。脚本先写齐不可变内容和 manifest，再原子发布采用索引；普通 Markdown 和缓存是可重建视图。视图待同步须如实报告并恢复，不能把半套视图当作一致事实。

原稿、用户手改和失败请求保留；恢复复用已明确的采用证据。同事务重复请求不重复升版，异内容不能复用旧 ID。其他片段的依赖变化只标需复核，不自动重写创作。

只有实际能力通过本批验证后才报告运行成功；影片质量、耗时改善和正式迁移仍以后续证据为准。
