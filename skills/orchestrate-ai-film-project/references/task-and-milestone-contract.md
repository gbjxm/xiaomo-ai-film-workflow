# 任务与里程碑契约

## 单一任务

首次分派、跨岗位或边界变化的任务必须回答：谁做、用什么做、这次不做什么、做到什么算完成、写到哪里、哪些外部动作需要另行授权。若发生合法暂离或返回，还必须记录来源任务、返回岗位、恢复对象与精确版本、恢复条件和往返次数。缺一项就保持待定。

任何时刻只有一个“当前任务”和一个 A 权威执行目标。交互前台是用户当前停留并对话的岗位任务，A 权威执行目标是获准推进正式阶段工作的唯一岗位；普通情况下二者相同。暂离不是并行任务：重大串行路由时 A 先把原任务的恢复字段冻结，再把权威执行目标改为临时岗位，原交互前台暂停正式写入；临时任务满足恢复条件后，再由 A 把权威执行目标切回记录的返回岗位。

同一岗位续办且输入、不做事项和写回位置都未变化时，只写增量动作、增量输入和完成标准；岗位内部追问不往返 A。重大跨岗位返修必须经 A，并使用上述恢复字段；下述后台所有权微补丁不改变当前目标岗位，不使用恢复字段。

## 阶段任务与变更分级

A 给 B/C/D/E 的首次任务以完整阶段结果为完成门，不以岗位内部的工具或微步骤为完成门：

| 阶段 | 阶段目标 | 留在本岗位的小幅修改 | 必须回 A 的重大变化 |
| --- | --- | --- | --- |
| B 故事 | 从点子或现有材料连续到 [B_STAGE_READY v1](b-story-stage-ready-contract.md) `PASS` | 同一故事核心与场景功能内的骨架→剧本、对白措辞、动作、节奏、时长压缩、专业自检和 Sxx 版本调整 | 改核心事件、人物动机、关系结果、制作功能、项目目标/里程碑、授权边界，或需跨岗位处理 |
| C 视觉 | 从采用 Sxx 连续到精确 C 交 D 素材清单 | 同一 Sxx 与镜头叙事功能内的资产、色卡、表演、镜头、Setup、提示词、take、准入与最小返修；符合微补丁条件时由 B 在后台维护同一 Sxx | 改稳定 ID、故事或镜头制作功能、阶段目标/里程碑、授权边界，需多名上游所有者，或微补丁条件不成立 |
| D 后期 | 从 C 接管连续到采用 CUT、Lock、组件、Master、QC 与恢复证据 | 同一 C 交接、故事事实、剪辑目标和既有授权/Profile 内的入出点、节奏、采用 take、声音、字幕/GFX、Online、调色、组件与 Master 版本 | 需要新源画面、改故事事实或剪辑结构目标、改 Profile/阶段目标/授权边界，或需跨岗位处理 |
| E 发行 | 从精确 QC Master 连续到包装、封面、唯一最终包、检查、人工回执或复盘的当前子阶段完成 | 同一 CUT/Master/平台/主要传播承诺内的标题、正文、标签、封面、包与检查版本；E 内 Skill 连续切换 | 改 CUT/平台/主要承诺，修改 Master/组件，触及权利/安全/首映投稿，或需跨岗位处理 |

判断时同时核对目标岗位、采用的上游稳定 ID/核心事实、不做事项、阶段目标与完成标准、写回范围、当前里程碑和外部动作授权边界；这些任务包络均未改变才可留在本岗位。当前任务明确预列但仍待用户决定的 TTS、生成或剪辑授权留在本岗位等待；用户拒绝后若必须改变任务包络，才回 A。阶段内预期创建首个 `Sxx/Axx/Vxx/CUTxx` 是正常进展，不因“出现新 ID”本身回 A。仅当前台岗位尚未冻结/锁定的内部依赖需要随同一稳定 ID、同一制作功能的小修重绑时，可走后台所有权微补丁并由 A 同步指针；若触及已冻结/锁定下游，或影响扩散到前台与唯一所有者之外的第三岗位精确绑定，仍必须回 A 处理传播。

岗位仍只写自己的文件，不能用“本岗位中控”越权修改 `A_总控.md` 或其他岗位正文。阶段完成时提交一次最小交接；A 核验精确版本后再切换岗位。

### B_STAGE_READY 唯一完成门

B 与 A 必须共同读取并只使用 [B_STAGE_READY v1](b-story-stage-ready-contract.md)。B 未 `PASS` 时留在原 B，不生成外部完成包，也不提交正常阶段交接；`PASS` 后按固定顺序定稿 B、计算 B hash，再从 [JSON 模板](../assets/b-stage-ready-packet-template.json) 按 [固定 Schema](../assets/b-stage-ready-packet.schema.json) 新建不可变 `剧本/阶段完成包/B阶段完成包_vNN.json`，最后只以该包路径/版本/hash 交 A 一次。A 的审查对象是该外部包；先用 `scripts/validate_b_stage_ready.ps1 -ProjectRoot <项目根> -PacketPath <包路径> -ExpectedPacketSha256 <交接 hash>` 只读验收，只有返回 JSON 中 `valid: true` 才继续。验收范围限定为：字段/遗漏、当前版本与 SHA-256、用户创作采用/B 记录写入/制作释放三项独立决定、Sxx 映射、阻塞项、权利/安全状态和原 A 任务包络。A 不重新逐场审对白、人物、因果、结构、节奏或其他创作细节，也不得临时增加共享契约或 A 原任务包络之外的完成标准。完整性通过后直接派 C。

只有字段、定位、hash、覆盖计数或映射等机械缺项时，A 保持当前交互前台，把同一 `handoff_id` 的精确缺项交原 B 后台刷新；这不是新阶段交接，也不要求用户切换任务。需要补做专业判断、取得新的用户决定、改变故事/释放范围或处理权利安全取舍时，不得伪装成机械刷新，结果回到 `NOT_PASS`，并按既有重大变化规则处理。

用户创作采用只决定内容；B 记录写入只允许 B 落账；制作释放才允许为精确范围分配/升版 Sxx、同步必要 A 指针并在完整性通过后派 C；TTS、文档编辑、图片/视频/声音生成、剪辑、导出、封面、上传和发布仍逐类另验授权。任何前一门都不能推导后一门。

## 后台所有权微补丁

后台所有权微补丁采用“单一交互前台＋受限后台所有者”：用户留在当前交互前台完成一处小幅上游修订，不要求切换任务或复制交接文本。A 权威执行目标保持为交互前台；文件所有者只获得精确差量的记录权限，不获得完整阶段权限。它不是岗位切换、第二个当前任务或内容审批；文件所有权不变。

机械差量默认按 [同一前台轻量岗位适配器](micro-patch-adapter.md) 在当前一次回复内完成，不新建完整所有者/A 代理任务。独立任务只用于需要新专业判断或无法保证适配器写入白名单的降级情形。

只有以下条件全部成立才可使用：

1. 分别存在可定位的用户采用决定证据与记录写入授权证据，后者覆盖本节限定的完整原子写入范围。不能把建议、候选或推断当作采用，也不能把采用自动解释为写入授权；同一条消息只有明确要求“修改、更新、写入或记录”时才可同时充当两项证据。用户明确称重大时不得降级。
2. 只涉及当前前台岗位和一名上游文件所有者；目标对象已有稳定 ID，补丁前后稳定 ID 与制作功能不变。
3. 请求明确列出项目根、来源任务 ID、交互前台、A 权威执行目标、A 当前任务版本与 `A_总控.md` SHA-256、所有者岗位与文件、稳定 ID 与当前版本、预期所有者文件 SHA-256、用户决定定位、记录写入授权定位、精确差量、必须保持不变的事实、已知下游影响、受影响执行坐标、授权边界和一轮恢复条件。
4. 所有者能在一轮内以受限后台所有者模式完成：只读精确对象、必要索引、目标文件 hash 和不变量，默认跳过常规专业 references；只改自己的精确记录、完成版本与索引更新并给出可验证回执。若必须重新进行专业开发、加载完整知识链或调用第二名所有者，微补丁不成立。
5. 不改变项目目标、里程碑、任务边界、外部动作类别、权利或安全条件，不触及已冻结/锁定下游；影响不得扩散到当前前台与唯一所有者之外的第三岗位精确绑定。

执行顺序固定为：

1. 交互前台先只读预检，确认条件和两项证据成立后，把最小请求发送给唯一文件所有者；用户继续停留在原任务，A 权威执行目标仍是该交互前台。
2. 所有者核对来源任务 ID、A 当前任务版本/hash 与自己的预期 SHA-256 后，进入受限后台所有者模式。匹配后只执行已采用且已授权写入的差量，保持稳定 ID、提升必要版本，验证不变量，并返回旧→新版本、新 SHA-256、实际改动、保持项、下游影响、受影响执行坐标和验证结果。
3. A 只核对该回执与自己当前任务，更新精确输入版本/hash、受影响执行坐标和一行同步状态。A 权威执行目标保持为原交互前台，不展开暂离/恢复，不重复要求用户采用或授权同一原子写入，也不替所有者判断专业内容。
4. 交互前台收到 A 同步结果后，重读 A 指针和所有者精确新版本，只在自己的写入范围内更新引用、失效或待复核状态，然后继续原阶段。

本流程的原子写入范围严格限定为三部分：所有者的精确记录、A 的版本/hash 指针、交互前台自己的引用与失效/待复核状态。任何第二名所有者记录、专业扩写、媒体文件、正式生成/剪辑/封面动作或其他岗位正文都不属于本原子写入。

所有者写前 hash 不符时零写入停止。若所有者已经完成采用写入但 A 指针同步失败，保留所有者新版本与回执，前台岗位暂停依赖写入、冻结和媒体生成，只恢复 A 指针同步；不得自动删除、覆盖或回滚已采用版本。A 已同步但前台重绑失败时，保留真实 A/所有者状态并让前台岗位从回执恢复。所有者任务不唯一、协调工具不可用、回执不完整、影响扩展到第二名所有者或一轮不能完成时，停止微补丁并按重大变化回 A。

微补丁只授权所列采用与文件写入；不授权 TTS、媒体生成、剪辑、封面制作、安装、迁移、上传或公开发布。外部动作仍按原独立确认门执行。

“必须回 A”是逻辑授权边界，不等于要求用户切任务。用户已给出重大方向且路线唯一时，A 切换权威执行目标并可在后台建立正式暂离/恢复链；原交互前台暂停正式工作，此时仍记录来源任务、返回岗位、恢复对象、恢复条件和往返次数。只有需要用户重新选择创作目标、范围、权利/安全取舍或新增外部动作授权时，才把 A 作为交互前台。

## 条件性后期预设

| 情况 | A 的动作 | 完成/恢复条件 |
| --- | --- | --- |
| 普通短片、规格明确且无已知高风险 | C 引用默认后期 Profile | 不新增 D 往返 |
| 规格不明、对白/音乐先行、口型同步、VFX、多版本输出、非默认时基/画幅、特殊字幕 | 暂派 D 建立 `后期预设卡 vNN` | 卡的路径、版本、SHA-256 和适用范围已明确，且早于首个受影响 Setup 锁定/生成 |
| 风险在 C 站 1–4 才显现 | 冻结 C 恢复对象，C→A→D | D 完成预设后 A 按原精确版本恢复 C |

后期预设不是生成或剪辑授权，也不要求每个项目机械发生。A 只保存后期预设卡指针，不复制时基、画幅、命名、把手、声音/VFX/字幕专业正文。

## C↔D 一轮最小返修

1. C 交付 `C 交 D 素材清单 vNN`；A 只登记精确路径、版本与 SHA-256，再派 D。
2. D 建立自己的接管快照并用真实媒体判断实际可剪性。C 的准入结论不能关闭“素材可后期”门。
3. D 返回 C 时必须提交：CUT 时间点、Sxx、Vxx、功能性缺口、现有素材不可替代原因、最小责任站、返回依据、期望补齐接口。
4. A 把返回岗位写为 D，把恢复对象写成精确 D 接管快照/CUT 版本，把恢复条件写成新版 C 清单路径、版本、SHA-256 与补齐接口。
5. C 只回最小责任站；镜头功能不变时保留 Vxx 并升 Setup/take，功能改变才停用旧 V、建立新 V。
6. C 返回新版清单后，A 恢复 D 做差量接管与 Reconform，并把 `C↔D 返修往返次数` 加一。

默认上限为一轮。往返次数达到 1 后仍需再次回 C，任务保持待定并停止，等待用户/A 决定；不得把默认调度上限当成生成或剪辑授权。

## 最小读取

优先读取目标岗位最近交接。只有交接明确引用某个稳定 ID 或文件时才继续读取对应证据。已经在同一任务中读取且没有外部修改迹象的内容直接复用；交接无法支持判断时，只请求一项最关键的缺失信息。

## 项目版本兼容

- 入口声明 v0.8 时，才启用 Setup、C/D 快照、组件、精确 Master 和恢复链契约。
- v0.75 项目仍按其原有 E/CUT 契约运行；不得无迁移授权补写 v0.8 字段。v0.7 或更早项目没有 E 时，按其原有终点运行，不得根据本机已安装版本补建 E。
- 旧项目的迁移必须是独立、明确授权的维护任务。

## 里程碑门

| 里程碑 | 最小证据 |
| --- | --- |
| 故事可制作 | 外部 `剧本/阶段完成包/B阶段完成包_vNN.json` 的路径/版本/SHA-256 已核验，包内为 `B_STAGE_READY v1 PASS`，其 B/权威正文版本/hash、专业自检证据、用户决定、释放 Sxx 与制作边界均通过只读校验器及 A 完整性验收 |
| 视觉可生成 | 采用资产、镜头、提示词卡及可检查的生成目标 |
| 素材可后期 | `C 交 D 素材清单 vNN` 精确路径/版本/SHA-256、D 接管快照及真实媒体粗拼证据；C 准入本身不足 |
| 后期成片完成 | 采用 `CUTxx vNN`、绑定该版的 Picture Lock、`Master vNN` 路径/SHA-256/Output Profile、PIC/AUD/TEXT/GFX 版本与合法状态、精确绑定表、自动＋人工 QC、限制/风险决定、恢复验证和权利证据 |
| 发行已就绪 | 采用 `PUBxx`、绑定上述精确 Master 与组件的真实最终封面、唯一最终发布包与输入 SHA-256、明确首映/投稿决定、检查结论“已就绪待人工发布” |
| 公开发布已登记 | 真实平台、账号、实际标题/正文/封面/可见性、可访问链接或明确回执、发布时间及与计划差异 |
| 单片发行复盘完成 | 真实数据来源与时间窗、事实、样本限制、主要与替代假设、下一次单一调整 |

后三个里程碑按实际任务逐个关闭，不把包装采用写成发布成功，也不因等待发布或数据而长期占用同一个 A 任务。

## E 任务分段

1. **发行准备**：输入采用 `CUTxx vNN`、QC 通过的精确 Master、组件绑定、平台与首映/投稿资格决定；目标为一个有唯一最终发布包且达到“已就绪待人工发布”的 PUB。
2. **发布登记**：输入 PUB 与用户带回的真实平台回执；登记实际发布字段和与计划差异。
3. **发行复盘**：输入 PUB、观察窗口与真实数据；只形成一组下一调整。

跨岗位问题只分派给最接近证据来源的岗位。单次生成失败或单条发行数据不得直接回滚整条故事线。

## E 返回 D 与失效

E 若提出新视频画幅、重编码、烧录字幕/字幕版、音轨版或成片修复，A 必须保存原 E 任务作为恢复对象，按 `E→A→D→A→E` 串行派工；E 不修改 Master。D 交付新 Master 后，A 重跑后期完成门，满足后才恢复 E。

Master 路径、版本、SHA-256、Output Profile 或绑定的 CUT/PIC/AUD/TEXT/GFX 任一变化，旧最终发布包及就绪检查均失效。旧文件保留历史，不得原地改写或静默沿用。
