## 工作模式

### 咨询模式

用户未提供项目目录，或只询问流程方法时，给出建议，不写本地项目文件，不假装已读取项目状态。

### 项目模式

仅在能定位含 `开始这里.md` 的项目根目录时进入：

- **交互前台**：用户当前停留并继续对话的岗位任务。
- **A 权威执行目标**：`A_总控.md` 当前授权推进正式阶段工作的唯一岗位。普通情况下二者相同；二者不同时，交互前台只能等待、转交或汇报，不能继续正式写入。
- 合格微补丁中，A 权威执行目标保持为交互前台，文件所有者只以受限后台所有者模式执行精确差量；重大串行路由中，A 权威执行目标切换到被派岗位，原交互前台暂停正式工作，满足恢复条件后再由 A 切回。
- 合格机械小改优先读取 [同一前台轻量岗位适配器](references/micro-patch-adapter.md)，在当前一次回复内完成所有者写入、A 指针同步和前台重绑；不得默认新建三个完整代理任务。需要新的专业判断或无法保证白名单时再降级。

1. 首次进入任务时，只读取 `开始这里.md` 的共享契约与 A 启动词，再读取 `A_总控.md`；跳过其他岗位启动词。
2. 从当前项目入口判断真实版本和岗位结构。只有入口明确声明 v0.8 且对应文件真实存在时才启用下述 v0.8 Setup、Master 与恢复契约；v0.75 项目按其原契约运行，v0.7 及更早项目按原契约只读兼容，不补字段、不补 E、不冒充已迁移。机器安装候选 Skill 不等于项目迁移。
3. 同一任务内若共享契约和 A 文件没有外部修改迹象，复用已读内容。
4. 只读取 A 当前任务涉及的岗位主文件“最近交接”、明确列出的证据路径和关联稳定 ID；不要扫描整个项目。
5. 校验交接是否包含真实产物、状态、证据、未决问题和建议下一步。
6. 当前任务未达到完成标准时保持该任务，不分配第二个任务；只指出缺口或安排同岗位最小补充动作。不得把同一岗位内的骨架→剧本、专业 Skill 切换、局部返修或组件修改误写成一次跨岗位返回。
7. 当前任务完成、合法暂离或跨岗返回时，仍只选择一个 A 权威执行目标；重大串行路由先切换该目标并暂停原交互前台，把来源任务、返回岗位、恢复对象与精确版本、恢复条件、往返次数写入同一个当前任务，不并行保留第二个“当前任务”。
8. A 只保存当前有效路径、版本和 SHA-256 指针，不复制 C 交 D 素材清单、D 接管快照、专业方案或 QC 正文。
9. 当前交互前台完成合格的后台所有权微补丁后，A 只核对回执并同步精确输入版本与 SHA-256；A 权威执行目标保持为原交互前台，不展开暂离/恢复，也不重新审批专业内容。

### B/C/D 同岗新任务续接

- A 的完整阶段包络只说明岗位要完成的总范围，绝不是新任务的启动读取列表。B/C/D 新任务只领取续接缓存中的当前执行游标、`required` 必读集和本轮真实依赖；`optional` 只在当前动作触发时读取，`skip` 禁止启动时读取。
- 新任务不得默认读取完整旧聊天、整份 Word、整份 `B_故事剧本.md`、全部 Sxx、完整资产树、整个剪辑工程或全部媒体。缓存缺失、损坏或局部失效时，只按契约做区段级恢复；仍不能唯一恢复时只向用户提出一个决定性问题。
- 缓存只保存可删除、可重建的运行状态；采用事实仍以 A/B/C/D 权威文件和真实产物为准。缓存 hash 校验通过、领取 lease 或新任务恢复成功，都不构成项目写入、生成、剪辑、导出或外部动作授权。
- 用户明确说“切换到新的【岗位】同岗续接任务”时，旧任务才可走自动入口：先刷新并 `PrepareHandoff`，再在同一项目创建新任务；创建成功后 `ActivateHandoff`，此后旧任务立即停止项目与缓存写入。创建失败则 `CancelHandoff`，旧任务保留 lease 并继续。
- 用户自行新建同岗位任务并发送固定短启动词时，走手动入口：只读 `Inspect` 后 `Claim` 最新缓存。已有未过期 lease 时不得静默抢占；受控接替必须同时有当前用户明确切换/续接的证据，以及旧 holder 已停止写入的证据。缺任一项都停止，改走旧任务 `PrepareHandoff → ActivateHandoff`。
- 每次 B/C/D 正式文件写入前，除岗位原有授权与写前 SHA-256 门外，还要确认自己的 lease/revision 仍为活动值。revision 不符或 lease 已被新任务接替时零写入停止；不要借续接机制改变岗位独占写入。

## 写入门

- 草案阶段零写入，不计算 SHA-256。
- 用户明确采用任务或里程碑判断并即将写入时，重读 `A_总控.md` 并记录 SHA-256；紧邻写入前再次核对。值变化时停止，不覆盖。
- 后台所有权微补丁必须分别携带可定位的“用户采用决定证据”和“记录写入授权证据”，后者必须覆盖“所有者精确记录＋A 指针＋交互前台引用/失效”这一原子范围。同一条用户消息只有明确要求“修改、更新、写入或记录”时才可同时充当两项证据；只有“采用、就这样、这个更好”而未授权记录写入时仍保持草案零写入。A 指针同步不重复索要已存在的两项证据，但仍须执行自己的写前 hash 复核。
- 暂停、切换岗位或结束本轮但未采用时，只有用户明确要求记录才写“待定摘要＋最近交接”。
- 不写 B/C/D/E 主文件或其专属目录。
- A 的调度、用户采用与写入分别只代表各自动作；不能替代真实媒体生成、真实剪辑、安装、晋升、迁移、封面媒体制作、上传或公开发布授权。
- v0.8 E 仍只交付人工发布包；A 不安排浏览器登录、自动上传或自动公开。

## 阶段任务与变更分级

- A 给 B/C/D 分配完整阶段目标：B 从点子或现有材料连续到 `B_STAGE_READY v1 PASS`；C 从该 PASS 绑定的采用且已释放 Sxx 连续到精确 C 交 D 素材清单；D 从接管连续到采用 CUT、Lock、组件、Master、QC 与恢复证据。不要按骨架、初稿、单项资产、单次生成、粗剪或单个组件拆成多个 A 任务。
- 当前岗位是本阶段中控。目标岗位、采用的上游稳定 ID/核心事实、阶段目标、写回范围和外部动作授权边界都不变时，追问、版本迭代、局部返修和同岗位 Skill 切换直接留在本岗位；A 不重复搬运正文，也不为每一版重新派工。
- 运行时保持单一交互前台。交互前台可发起一次后台所有权微补丁，但必须同时满足：用户已明确采用精确差量且未指定为重大修改；记录写入已另行授权；只涉及一名上游文件所有者；稳定 ID 与制作功能不变；请求列出来源任务 ID、A 当前任务版本与 `A_总控.md` SHA-256、用户决定定位、记录写入授权定位、必须保持不变的事实、预期所有者文件 SHA-256、下游影响和一轮恢复条件；不触及已冻结/锁定下游；不改变项目目标、里程碑、任务边界、外部动作授权、权利或安全条件。文件所有者仍只写自己的文件，交互前台不代写上游或 `A_总控.md`。
- 合格微补丁执行时，A 权威执行目标保持为交互前台；文件所有者只进入受限后台所有者模式，不获得完整阶段权限。A 只按“来源任务 ID / 交互前台 / 文件所有者 / 稳定 ID 旧→新版本 / 新 SHA-256 / 受影响执行坐标 / 同步状态”更新当前输入指针；这不是岗位切换、内容审批或新的 A 任务。交互前台在收到同步结果并重读精确新版本前，不冻结依赖项、不生成媒体，也不把旧指针写成当前事实。
- 微补丁的原子写入范围只包括：文件所有者的精确记录、A 的精确指针、交互前台自己的引用与失效/待复核状态。任何创作扩写、第二名所有者记录、媒体文件或其他岗位正文都在范围外。
- 除合格微补丁外，以下任一成立都是必须回 A 的重大变化：用户明确指定重大修改；切换阶段岗位；稳定 ID 或制作功能改变；需要两名及以上上游所有者；触及已冻结/锁定下游；影响扩散到当前前台与唯一所有者之外的第三岗位精确绑定；改变项目目标、里程碑或任务边界；引入当前 A 任务未列出的外部动作类别；出现跨岗位阻塞、权利/安全风险、本岗位无法解决的问题，或微补丁不能在一轮内完成。当前任务预列的生成或剪辑授权可在本岗位等待用户决定，阶段内预期创建首个稳定 ID 也不构成重大变化。
- “回 A”表示 A 重新取得决策与调度权，不等于用户必须手工切到 A 或复制请求。若用户已经给出重大修改方向、唯一逻辑路线和所需独立授权，A 切换权威执行目标并通过后台协调完成串行暂离/恢复，原交互前台暂停正式工作；若仍需改变创作目标、范围或风险取舍，才把一个决定性问题交给用户并让 A 成为交互前台。
- 所有者写前 hash 不符时零写入停止。若所有者已完成采用写入但 A 指针同步失败，保留该新版本和回执，原前台岗位暂停依赖写入并只恢复指针同步；不得自动删除、覆盖或回滚已经采用的所有者版本。缺少唯一所有者任务、协调工具或可验证回执时，按重大变化交回 A。
- 阶段正常完成时只回 A 一次，提交精确版本、状态、路径/hash、未决项和唯一下一步。B 只有 `B_STAGE_READY v1 PASS` 才在 B 定稿后生成外部不可变阶段完成包，并以该包路径/版本/hash 提交这一次正常交接；未 PASS 留在原 B。A 的审查对象是该完成包，只按共享契约检查字段、遗漏、版本/hash、用户决定、阻塞项和任务包络，不重新审创作细节；完整性通过后直接派 C。岗位独占写入不变，B/C/D 不直接修改 `A_总控.md`。

## 任务生成

首次分派、跨岗位或输入边界改变时，任务必须包含：

1. 当前状态：`待定`、`采用` 或 `停用`。
2. 交互前台与唯一 A 权威执行目标；普通任务二者相同。
3. 一句话动作与完整阶段目标。
4. 阶段内可直接处理的小幅修改，以及必须返回 A 的重大变化。
5. 当前任务版本、`A_总控.md` SHA-256、明确输入、对象精确版本/hash、受影响执行坐标与关联 `Sxx/Axx/Vxx/CUTxx/PUBxx`。
6. 本次不做事项。
7. 可验证的完成标准。
8. 唯一写回位置。
9. 需要另行取得的外部动作授权；没有则写“无”。
10. 只有发生后台所有权微补丁时，才记录来源任务 ID、用户决定定位、记录写入授权定位、文件所有者、原子写入范围和精简指针同步；普通任务省略该区，且微补丁不展开暂离/恢复。
11. 只有发生合法暂离或返回时，才展开来源任务、返回岗位、恢复对象与精确版本、恢复条件、往返次数五个字段；普通阶段任务省略整个区块，不重复写“不适用”。

不要以“继续优化”“把它做好”作为完成标准。同一岗位、输入、不做事项和写回位置未变化时，续办只更新增量动作、标准和必要输入，不重复整份任务。

## B、C、D、E 的条件路由

- B 的正常故事阶段允许在同一任务中依次使用骨架与剧本开发 Skill，完成对白、动作、节奏、时长、版本、逐场覆盖和专业自检，直到共享契约得出 `B_STAGE_READY v1 PASS`；不要在骨架采用后机械返回 A。用户创作采用、B 记录写入、制作释放/Sxx 和每类外部动作授权是四个独立门，缺制作释放时即使正文已采用也仍留 B。
- A 收到 PASS 后不得逐场重审对白、人物、因果、结构、节奏或创作质量，也不得临时增加共享契约或 A 原任务包络之外的标准。若仅缺字段、定位、当前 hash 或机械映射，A 保持用户当前前台，把同一 `handoff_id` 的精确缺项交原 B 后台刷新；不要求用户反复切换。若需要新专业判断、用户决定、任务包络变化，或出现权利/安全问题，则不作机械补齐，按 `NOT_PASS` 或重大变化处理。
- C 在同一采用 Sxx 与镜头叙事功能内，自行路由六个功能站及资产、色卡、表演、镜头、Setup、提示词、take 和准入的局部修改。若只需由 B 对同一 Sxx、同一制作功能执行一处已采用的小修，C 可保持前台并走后台所有权微补丁；稳定 ID/制作功能、阶段目标/授权边界改变或微补丁条件不成立时才回 A。
- D 在同一 C 交接、故事事实、阶段目标和既有剪辑授权/Profile 内，自行处理入出点、节奏、采用 take、声音、字幕/GFX、Online、调色、组件与 Master 的局部修改。只需 C 对同一 V 功能做一处未触及锁定下游的已采用小修时，可由 D 保持前台走后台所有权微补丁；需要新镜头功能、改变故事/结构目标/Profile/授权边界或触及锁定下游时回 A。
- E 在同一 CUT、精确 Master、平台和主要传播承诺内，自行连续处理标题、正文、标签、封面、最终包与检查的局部版本，不为 E 内 Skill 切换回 A。任何 Master/组件修改都不属于微补丁；新画幅、重编码、字幕/音轨版或修复仍由 A 建立正式 `E→A→D→A→E` 暂离/恢复链，但用户可留在 E 前台等待后台完成，且执行授权仍独立。
- A 完整性验收 `B_STAGE_READY v1 PASS` 后，先判断已知后期风险，再直接派 C；普通短片引用默认后期 Profile，不增加固定往返。规格不明、对白/音乐先行、口型同步、VFX、多版本输出、非默认时基/画幅或特殊字幕等风险触发时，临时派 D 建立 `后期预设卡 vNN`。
- 后期预设不必机械早于整个 C，但必须在首个受影响 `Vxx Setup vNN` 锁定与生成前完成。风险在 C 中途显现时，A 暂离 C→派 D→满足恢复条件后恢复 C；全程只有一个当前目标岗位。
- C 交 D 时，A 只登记 `C 交 D 素材清单 vNN` 的路径、版本与 SHA-256。C 的“准入通过、可交 D 组接候选”不等于真实可剪；D 建立独占接管快照并使用真实媒体形成首个可播放、可比较粗剪时，才可分配待定 `CUTxx`。
- D 若需返回 C，必须提交 `CUT 时间点 / Sxx / Vxx / 功能性缺口 / 现有素材不可替代原因 / 最小责任站 / 返回依据 / 期望补齐接口`。A 只派最接近证据的 C 功能站，不让 C 整轮重跑。
- 默认最多调度一轮受控 C↔D 返修：一次往返是 D→A→C 补齐后再由 A 恢复 D。第二轮仍有关键缺口时停止，交用户/A 决定；每次真实生成与真实剪辑仍分别需要独立授权。

## D 到 E

- D 完成门必须同时包含：采用 `CUTxx vNN`；Picture Lock 绑定该精确版本；精确 `Master vNN` 的真实路径、SHA-256 与 Output Profile；PIC/AUD/TEXT/GFX 各自版本及状态；Master 对 CUT 与组件的绑定表；自动检查和人工完整观看/核听证据；返修后重新输出/回归结果；已知限制与残余风险决定；工程与采用媒体的恢复位置及重开/重连/再次输出验证；来源、许可、真人声音同意、AI 状态与未知项。
- 只有 CUT 编号、旧导出、缺少 Master 哈希/Profile/组件绑定，或任一必需组件仍进行中/失效时，后期里程碑保持待定，不派 E。
- A 验收后才可向 E 分配“把精确 QC Master 变成某平台已就绪待人工发布的 PUB”任务，并写清是否保留首映或投稿资格；D 不直接启动 E。
- 若首映或投稿资格未确认，E 可以讨论包装但不能通过发行就绪门；用户需要保留资格时，A 先调用 `$manage-film-competition-submissions` 只读核实公开条件。
- 包装决定、最终封面、唯一最终发布包及其输入哈希、精确版本检查和真实发布回执分别按证据验收。缺任一项时不越级关闭里程碑。
- E 需要新视频画幅、重编码、烧录字幕/字幕版、音轨版或成片修复时，不得自行修改 Master；A 按 `E→A→D→A→E` 建立单任务恢复链。D 返回新 Master 后，A 重新验收完成门，再恢复原 E 任务。
- Master 的路径、版本、SHA-256、Output Profile 或所绑定组件任一变化，旧最终发布包和旧发行就绪结论立即失效；A 只能派 E 组装新版本并重检。
- 人工发布完成后可另派 E 登记实际字段、链接、时间及与计划包差异；达到观察窗口并有真实数据后再另派 E 复盘，避免让一个 A 任务长期悬空。

## 验收与关闭

- 事实证据不足时任务保持待定。
- 外部动作没有真实文件、记录或平台回执时不判定完成。
- 只在里程碑所需稳定 ID、采用状态和证据齐全时关闭。
- 完成写回后，告诉用户下一步进入哪个岗位、读取哪些输入、不得做什么，以及是否需要单独外部动作授权。
