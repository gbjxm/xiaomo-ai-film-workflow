## 集中目录

所有持久数据位于 `<workflowRoot>/投稿管理/`：

```text
投稿管理/
├─ 参赛者档案.md
├─ 作品档案.md
├─ 比赛数据库.csv
├─ 比赛档案/
├─ 投稿策略.md
├─ 行动看板.md
├─ 投稿历史.md
├─ 变更日志.md
├─ 主办方问询.md
└─ 模板/
   └─ 比赛档案模板.md
```

不要在单个项目中创建 `competitions/` 或复制数据库。集中目录可以引用项目相对路径，但不得移动、重命名或改写项目文件。

## 身份与作品档案

参赛者档案区分“用户确认、文件证据、未知”。至少记录：在校/毕业状态及有效期、年龄范围、国籍/居住地、院校与专业、个人/团队、指导教师、跨校组队、预算、出行、语言、跨境支付和证件可提供性。

作品档案每部作品至少记录：项目路径、真实/测试属性、类型、阶段、版本、时长、画幅、分辨率、语言、字幕、团队、AI 使用、完成度、公开/展映/投稿历史、版权证据、首映状态、投稿版本和证据路径。未知值写“未知”，不用空白暗示完成。

## 比赛数据库

CSV 使用 UTF-8，固定字段顺序：

```text
competition_id,year,name_zh,name_en,organizer,status,verification_state,time_window,registration_deadline,submission_deadline,deadline_timezone,beijing_deadline,official_url,submission_url,eligible_projects,eligibility_gate,ai_policy,premiere_risk,rights_risk,fee_original,fee_cny_estimate,recommendation,risk,confidence,last_verified
```

字段约束：

- `status` 只能取十项比赛状态。
- `verification_state` 只能为 `已核实` 或 `待核实`，它不是比赛状态。
- `time_window` 只能为 `0-60天、61-180天、年度关注`。
- `recommendation` 只能为 `S、A、B、C、暂缓、不建议`。
- `risk` 只能为 `低风险、中等风险、高风险、不建议参加`。
- `confidence` 只能为 `高、中、低`。
- 日期只写 ISO 日期；更精确的时间、分阶段费用和规则证据进入详细档案。
- `eligible_projects` 使用项目稳定名称，以 `|` 分隔；未知时写“待确认”。

## 比赛详细档案

每场比赛使用 `比赛档案/<competition_id>_<简短名称>.md`，至少包含：

1. 基本信息和本届官方来源。
2. 注册、提交、补交、结果、展映及颁奖时间。
3. 参赛者资格。
4. 作品与材料要求。
5. AI 政策及待确认问题。
6. 版权、公开、首映和授权条款。
7. 费用、奖励与真实价值。
8. 推荐作品、单元、缺口、工作量和成本。
9. 硬性门结果、十二项评分、风险和置信度。
10. 与其他比赛的冲突和推荐顺序。
11. 投稿步骤、确认邮件和官方联系方式。
12. 核实日期、证据链接及规则冲突。

引用官方规则时只摘录支持判断所需的短句，其余用准确转述，并附链接。

## 状态与稳定 ID

比赛状态只能为：

`候选、推荐、准备中、已提交、入围、获奖、未入围、已截止、已放弃、已归档`

状态含义：

| 状态 | 含义 |
| --- | --- |
| 候选 | 已发现但尚未成为正式行动目标，可同时处于待核实 |
| 推荐 | 官方关键信息已核实且通过硬性门 |
| 准备中 | 用户已采用并开始准备材料 |
| 已提交 | 有平台或邮件回执证明提交完成 |
| 入围/获奖/未入围 | 有官方结果证据 |
| 已截止 | 本届有效提交窗口关闭 |
| 已放弃 | 用户主动停止或资格/风险导致放弃 |
| 已归档 | 不再参与当前行动，但保留历史 |

不得用“已报名”替代“已提交”；只有真实提交回执才进入已提交。

ID 格式为 `CMP-YYYY-NNNN`。年份取比赛届次年份；四位序号由脚本在同年已有最大值上加一。ID 一经分配不得更改、回收或用于另一场比赛。续届比赛使用新 ID，并在详细档案中关联往届。

去重至少比较本届年份、官方 URL、官方名称和主办方。名称翻译不同不构成新比赛；同一赛事不同独立单元原则上共用比赛 ID，在详细档案内区分单元。

## 报告结构

每次只读报告固定为九部分：

1. **本期战略结论**：日期、范围、读取作品、候选/有效数量、最重要三个判断、优先作品和紧急事项。
2. **作品投稿路线概览**：作品、阶段、可投稿形态、最优方向、首选/次选、最大缺口、公开建议和当前动作。
3. **未来 60 天优先机会**：只列硬性门通过且已核实的 3–10 个机会；不足则少列。
4. **详细比赛档案**：按推荐等级和战略顺序说明规则、限制、风险、来源及核实日期。
5. **比赛冲突矩阵**：冲突比赛、条款、作品、风险、推荐顺序和是否暂缓公开。
6. **未来 60 天行动日历**：日期、作品、比赛、具体动作、前置条件、紧急度和状态。
7. **待确认与风险**：AI、首映、资格、版权、费用、官方冲突及必要的中英文问询草稿。
8. **中长期机会**：61–180 天和年度关注，严格区分本届事实与往届线索。
9. **本次变更记录**：新增、截止、规则/AI/费用/首映/推荐/作品完成度/投稿状态变化。

表格之外保留关键解释，不把完整规则压进一行。每个推荐必须有下一步行动。

## 增量更新和并发保护

1. 研究前对可能写入的全部文件生成 SHA-256 快照；不存在的目标记录为“不存在”。
2. 对话中先给只读结果，等待用户明确采用或明确要求写入。
3. 写前重新生成快照；任何已读文件变化、预期新文件出现或目录被替换都停止写入。
4. 只增加新档案或修改本次确认涉及的字段；不顺手重排、批量格式化或删除旧记录。
5. 状态变化追加到投稿历史和变更日志，不覆盖历史事实。
6. 写后运行验证器并记录结果；验证失败不宣布完成。
7. 自动报名、支付、发信、上传、签署授权、公开作品均不属于本地写入授权。
