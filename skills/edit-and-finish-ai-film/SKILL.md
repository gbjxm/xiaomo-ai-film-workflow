# AI 影视剪辑与成片完成

## 版本路由

- 项目入口显式声明 `workflowStudio: studio-v0.9` 时，先读 [V0.9 工作室共同契约](../orchestrate-ai-film-project/references/studio-v09-contract.md) 和项目 `工作室能力.json`，再读 [本专业 V0.9 分支](references/studio-v09-collaboration.md)。该分支优先于下文的项目门禁、逐步确认和写回规则；按实际能力选择可执行范围，不落入旧保存流程。
- 没有该标识时完全沿用下文原 v0.8/旧项目或独立咨询行为，不因机器版本、Skill 位置或部门名称启用 V0.9。

维护同一条可追溯后期基线：`C 交接清单 → D 接管快照 → CUTxx vNN → Picture Lock → PIC/AUD/TEXT/GFX → Master → QC → 恢复 → A`。本 Skill 是唯一 D 主入口，按任务调用专业 reference、`grade-film-in-resolve` 调色子能力与 `davinci-resolve-mcp` 技术接口；不增加部门或第二个正式记录所有者。

## 进入与任务深度

没有含 `开始这里.md` 的兼容项目目录时，不建立项目正式记录；默认提供咨询或通用方案。用户明确指定独立达芬奇工程、输入与执行范围时，可交 `grade-film-in-resolve` 或技术接口执行授权内的独立任务，不虚构 C 接管、CUT、锁画或项目采用。

进入项目后：

1. 首次进入或同岗新任务先只读取 `开始这里.md` 的 D 段、`A_总控.md` 的 `## 当前任务`，以及入口点名的 D 同岗续接缓存；未启用续接补丁、缓存缺失或按共同契约需要恢复时，才读取 `D_后期剪辑.md` 的当前状态、采用索引与最近交接。第一阶段不得读取专业 references、打开工程或媒体。
2. 仅从项目入口确认工作流版本和补丁标识，不在第一阶段加载任何 reference。v0.8 使用本契约；无相应标识的既有 v0.8 项目继续按原规则，旧项目不补建 E、不迁移、不把新状态写进旧项目。
3. 同岗续接的第二阶段以 A 当前任务为门：目标岗位不是 D 时立即停止，references、工程与媒体读取数均为 0；目标岗位是 D 且入口声明 `workflowPatch: same-role-resume-v1` 时，才读取 [同岗续接共同契约](../orchestrate-ai-film-project/references/same-role-resume-contract.md)，并按有效活动方案的精确必读集继续。缓存模式、revision、lease 和共同恢复只服从该引用，下文只补 D 的媒体与工程差异。A 的完整阶段包络不得直接变成媒体或 reference 读取列表。入口声明 `workflowPatch: single-foreground-micropatch-v1` 时才启用既有后台路由。
4. 只读状态查询且续接快照有效时，只核对活动方案、接管快照、CUT、组件与 Master 的精确指针/hash，不重开工程、不重连媒体、不重新播放或核听；新开聊天本身不构成接管、恢复验证或 QC 复看。
5. 先选最轻深度：单点纠错默认只给“症状 → 根因 → 最小修改 → 观察点”；局部方案只展开触发分支；完整后期或执行交接才使用 [后期方案模板](assets/edit-package-template.md)。
6. 规格不明、对白/音乐先行、口型同步、VFX、多版本输出、非默认时基/画幅或特殊字幕等风险出现且 A 派 D 时，读取 [后期预设与接管](references/post-preset-and-ingest.md)，用 [后期预设卡模板](assets/post-preset-template.md)；普通项目引用默认后期 Profile，不增加固定往返。
7. 只有入片、切点、声画或其他结论确实依赖真实画面/声音时，才打开并检查对应媒体。清单、缩略图、波形描述或旧报告不能替代需要发生的实际观看/核听，也不能反过来迫使纯状态查询播放媒体。
8. A 权威执行目标不是 D 时，只有入口已启用既有后台补丁且收到符合共同契约的 D 后台所有者请求，才可进入受限微补丁模式；该路径不是同岗续接。先读 [同一前台轻量岗位适配器](../orchestrate-ai-film-project/references/micro-patch-adapter.md)，只读 A 指纹、D 精确对象/索引/hash 与不变量，默认跳过无关 references。否则零写入停止。

同一 A 后期阶段任务内，本 Skill 是 D 的阶段中控：只要 C 交接、故事事实、剪辑结构目标、阶段目标、写回范围和既有剪辑授权/Output Profile 未改变，入出点、节奏、采用 take、声音、字幕/GFX、Online、调色、组件与 Master 的局部版本调整都留在 D，不返回 A。需要新源画面、改变故事事实或剪辑结构目标、改变阶段目标/Profile/授权边界、切换岗位或出现 D 无法解决的跨岗位阻塞时才回 A；D 仍不得写 A/B/C/E 文件。

用户所在聊天是交互前台，不改变岗位或文件所有权。仅当 [共同微补丁门](../orchestrate-ai-film-project/references/task-and-milestone-contract.md#后台所有权微补丁) 全部成立，包括不触及已冻结/锁定下游时，才按轻量适配器在当前回复完成唯一所有者、A 指针和 D 重绑；否则交 A。后台路由只节省交互，不授予生成、剪辑、声音处理、转码、导出、覆盖文件或其他外部动作权限。

D→C 还必须记录 C 交 D 清单版本/hash、D 接管快照版本/hash、目标 take 是否被当前 CUT 使用、CUT/Lock 影响、是否需要 Reconform和媒体生成授权状态。take 已被采用 CUT 使用、任一下游已冻结/锁定或字段无法判断时，不得走微补丁，改由 A 正式路由。

## 达芬奇原生工具与调色子能力

- D 默认以达芬奇后台原生 API/MCP 为后期主工具；调用 [davinci-resolve-mcp](../davinci-resolve-mcp/SKILL.md) 读取当前实际接口与能力。工具层负责连接、对象定位和原生操作，不决定剪辑或调色的创作目标。当前版本支持什么就执行什么，不从 GUI 有某功能推断 API 全控。
- 涉及调色、逐场匹配或 Look 续调时，调用 [grade-film-in-resolve](../grade-film-in-resolve/SKILL.md)。其专业判断与本次已授权原生执行仍属于 D；主入口、接管、CUT/Lock、组件、Master/QC 和正式记录所有权不变。
- 默认在同一指定工程内持续调整用户指定的一版。只有用户明确要求测试时，才保留原版与三个候选，默认同一约 20 秒代表片段，用户指定范围优先；方向按影片决定，不套固定风格。恢复点用于保住既有工作，不要求每次反馈重建工程。
- 后台操作不占键鼠、不启用 Computer Use，不默认把外部 FFmpeg 滤镜处理作为调色实现。Color/Fusion/渲染的具体能力、DRX 覆盖与恢复、LUT 的局限，按专项技能和真实测试判断。
- V0.9 `media_execution` 指工作室运行时内置媒体功能，保持项目原值；独立达芬奇工具需要实际可用和本次用户执行授权。工具安装、运行时字段或文本采用均不能互相替代这两项条件，也不扩张 C 生成、上传和发布授权。
- 工程保存、恢复点与必要工作稿可支持执行续办，但不自动改写采用状态；只有用户正式采用后，D 才按现有契约更新对应调色/PIC 与实际受影响依赖。专项和工具技能均不分配 CUT；纯调色变化不提升 CUT。

## 独立授权门

把讨论、采用、记录写入和外部执行分开：

- 采用后期方案不等于授权修改时间线；写入项目记录不等于实际剪辑。
- CUT 创建、用户采用 CUT、Picture Lock、组件冻结、Master 绑定或 QC 结论都不反向授予真实剪辑、声音处理、转码、导出或覆盖文件的权限。
- 没有独立剪辑执行授权时，只给诊断、方案或用户明确要求的 `manual-copy`；状态写“未授权/等待人工执行”，不得写“已粗剪、已锁画、已冻结、已导出或已通过”。
- 获授权后只在授权的工具、输入、输出和处理范围内执行，记录真实工具、命令或人工动作、路径、版本、失败与结果。执行事实不自动等于用户采用。
- 来自其他岗位的后台微补丁必须同时携带采用证据与记录写入授权；它不继承或扩大剪辑、转码、导出等执行授权。缺少记录写入授权时零写入，缺少外部执行授权时只完成已授权记录动作并等待用户决定。
- 同岗续接只恢复状态和权限边界，不继承旧聊天中的临时执行许可。实际继续剪辑时必须重新获得本次独立执行授权，打开活动方案绑定的精确工程版本，并按绑定表重连精确媒体；不得从目录、软件最近项目或“最新文件”猜测目标。

## D 状态脊柱

### 接管与真实粗剪

1. A 正式派 D 后，按 C 清单重新核验真实路径、SHA-256、可打开性、批次、代理/派生关系、工程版本、滚动组接和参考导出，建立 D 独占接管快照。
2. 不重命名、覆盖或修改 C 原始媒体。代理、转码、稳定化和修复件只能作为 D 派生文件，并保存完整派生链。
3. C 的推荐 take 只是准入意见；D 记录精确入片 take 与入出点。不得静默使用 C 已停用 take。
4. 用户在 C 阶段手工形成的滚动组接、静态/动态预演或仅有方案的时间线只作参考，不占 CUT。只有 D 使用真实媒体形成首个真实、可播放且可比较的粗剪时，才从 D 索引最大值递增分配待定 `CUTxx`。

### CUT、Lock 与组件

始终分开记录：

```text
CUT 创建 ≠ CUT 采用 ≠ Picture Lock ≠ 组件冻结 ≠ Master 绑定 ≠ Master QC 通过
```

- 同一剪辑功能内，只有顺序、切点、时长或采用媒体变化才提升 `CUTxx vNN`；剪辑方向或结构目标根本改变才新建 `CUTxx`，旧编号停用且不回收。
- Picture Lock 必须由用户对精确 `CUTxx vNN` 单独确认。CUT 升版后旧 Lock 仍是历史事实，但新版不继承锁画。
- PIC/AUD/TEXT/GFX 分别使用 `未触发 / 进行中 / 已冻结 / 已失效 / 不适用＋原因`。未触发分支不强制展开详细表。
- 组件内容变化不自动提升 CUT；只使受影响组件、依赖它的 Master 和该版 QC 失效。PIC 只有在画面顺序、切点、时长、采用媒体或 PIC 自身内容变化时受影响。
- Master 只能绑定一个精确 CUT 版本以及 PIC/AUD/TEXT/GFX 的精确版本、路径、SHA-256 或合法不适用原因，并记录 Master 版本、真实路径、SHA-256 与 Output Profile。任一绑定输入变化都使该 Master 和 QC 就绪结论失效；若该基线已被 E 绑定，旧封面来源基线须待复核，旧最终发布包与旧发行就绪结论同时失效，D 交接必须列出传播范围。

## 返修与失效范围

- 用 D 的精确素材使用表判断 take 变化：未被当前 CUT 使用，不污染 CUT；已使用才进入 CUT 升版、差量接管与 Reconform。旧媒体、旧 CUT 和旧 Lock 作为历史保留，不覆盖。
- C 清单、take、CUT 或 PIC/AUD/TEXT/GFX 的变化只沿活动方案中记录的真实依赖传播；同岗新任务不得递归扫描目录寻找“最新版”，也不得因目录中出现无关文件而使整个后期基线失效。
- D 只有在现有素材无法承担关键叙事功能、人物反应、动作阶段、空间基准、必要插入或声音接口时才经 A 返回 C。证据必须包含 `CUT 时间点＋Sxx/Vxx＋功能性缺口＋现有素材为何不可替代＋最接近证据的责任站`；能用入出点、匹配、声音、VFX/Online 或纯后期修复解决的，不退 C。
- 新 C 媒体返回后建立差量接管，不覆盖旧素材或旧 CUT；按实际使用关系 Reconform。
- 若后期修整会改变角色身份、场景事实、镜头功能或需要新源画面，经 A 返回 C；纯匹配、既有元素合成、画外字幕/GFX、声音、Online 和最终调色留在 D。

## 写入与完成门

- 只写 `D_后期剪辑.md`、版本化 `后期方案/`、D 专属派生资产、工程、参考导出和 Master；不写 A/B/C/E，不生成替代媒体，不修改 C 原件，不分配 S/A/V/PUB。

- D 主文件严格只维护五类摘要；逐镜、声音、字幕、派生、素材使用、Master 绑定和 QC 明细放入版本化后期方案，不复制专业正文。
- 只有采用 `CUTxx vNN`、该版 Lock 状态、冻结或合法不适用的四组件、精确 Master 路径/版本/hash/Profile、自动检查、人工完整观看/核听、限制决定、恢复验证及权利证据都真实齐全，才向 A 交付 D 完成证据。
- D 的 QC 只判断影片本体，不判断标题、发行封面、平台字段或发布授权。交 A 后停止；不建立 PUB、不写 E、不直接启动 E，也不发布。
