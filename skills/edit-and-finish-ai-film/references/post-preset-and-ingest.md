# 后期预设与素材接管

## 条件性后期预设

普通短片直接引用项目默认后期 Profile。只有规格不明、对白/音乐先行、口型同步、VFX、多版本输出、非默认时基/画幅、特殊字幕或其他接口风险出现，且 A 暂派 D 时，才使用 `assets/post-preset-template.md` 建立一页 `后期预设卡 vNN`。

预设至少确认：

- 时基、帧率、画幅、分辨率、时间码和同步基准；
- 命名、版本、镜头把手、代理/原件边界和参考导出；
- 声音、口型、音乐、VFX、色彩、字幕与多版本接口；
- 输出 Profile、未决项、责任岗位和首个受影响 Setup 的完成门。

后期预设不要求机械发生在 C 之前，但必须在首个受影响 `Vxx Setup` 锁定和真实生成前完成。采用预设不授权生成、剪辑、转码或导出。

## 首次接管快照

A 正式派 D 后建立 D 独占、版本化的接管快照。引用而不复制 C 清单正文，并核验：

1. C 交 D 素材清单的路径、版本、SHA-256 和当前有效性；
2. 精确 S/A/V、场景卡、Setup、提示词卡和生成记录版本；
3. 每个推荐、备选、停用 take 的真实路径、SHA-256、批次、时长、帧率、音轨和可打开性；
4. 首尾把手、动作/反应/空间/声音接口、实际差异、限制与欠 coverage；
5. 现有工程版本、用户手工滚动组接、参考导出及其路径/hash；
6. 默认 Profile 或采用的后期预设卡。

缺失、hash 不符、不可打开、清单过期或必要版本冲突时，接管保持阻塞/待确认。不要把 C 的“准入自检通过”当作素材已被 D 入片或已证明可剪。

同岗新任务先按 [共同续接契约](../../orchestrate-ai-film-project/references/same-role-resume-contract.md) 验证 A 锚点、活动方案和接管快照。有效快照上的纯状态查询复用已记录证据，不重新核验 take，不打开工程或媒体。只有进入首次或差量接管任务时，才以精确 C 清单和上一接管快照比较变化集：首次接管把清单点名的 take 视为首次变化集；后续只核验新增、内容 hash 变化或绑定元数据变化的 take，未变化项沿用原快照证据。不得扫描 C 目录、按修改时间或文件名猜测“最新素材”。

变化集的路径、SHA-256、媒体属性和可解码性按当前任务需要核验；只有 D 要决定入片、切点或声画关系时，才实际打开、观看或核听对应媒体。状态恢复、hash 比对和清单差量本身不触发全量播放。

## 原件与派生链

D 不重命名、覆盖、移动或修改 C 原始媒体。代理、转码、稳定化、降噪、修复、重采样或其他处理件只能写入 D 专属位置，并逐项记录：

```text
源 take ID＋源路径＋源 SHA-256
→ D 派生文件路径＋派生 SHA-256
→ 处理工具/参数/日期
→ 用途、所服务 CUT 与当前状态
```

无法回溯源 hash 的派生件不得进入冻结组件或 Master。代理不替代原件的留存与权利证据。

## 差量接管与 Reconform

新版 C 清单或媒体返回时：

1. 新建接管快照版本，不覆盖旧快照、旧媒体或旧 CUT；
2. 只核验精确清单比较得出的新增或变化 take、Setup、清单和派生关系，未变化项复用上一快照证据；
3. 用精确素材使用表判断当前 CUT 是否实际引用变化 take；
4. 未引用时记录变化但不污染 CUT；已引用时按 `edit-cut-and-picture-lock.md` 提升 CUT 版本并 Reconform；
5. 更新受影响组件、Master 与 QC 状态，不一刀切废弃无关成果。

每次差量接管都保持旧快照与旧绑定为历史证据。
