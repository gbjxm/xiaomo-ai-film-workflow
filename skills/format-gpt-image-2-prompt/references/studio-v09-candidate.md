# V0.9 整合候选的图片格式化

本分支只改变允许的输入来源和候选交付衔接，不增加创作权。项目入口与能力结果可由 C1/C2 本轮核实后传入；若需自行核对，仅读取入口及能力文件用于路由，不读取项目创作正文、历史或附件画面来补写内容。

## 明确提交的输入

C1/C2 须明确调用 `$format-gpt-image-2-prompt` 并提交本版完整整合内容、用途、稿件版本和必要素材职责。内容可以是候选，不要求用户逐条确认或已分配 Axx/Vxx；“接受本版输入”不等于把候选认作采用。独立/无标识使用仍执行旧正文的显式调用及用户确认要求，保留 explicit-only policy。

输入中有两版冲突创意、未展开的项目引用、缺失参考职责或只有局部差量而没有上版全文时，返回 C1/C2 一个最关键的缺口，不从文件或图片自行填空。上游内部补齐后再格式化，由 C2 集中处理真正需要用户决定的问题。

## 忠实复制与参考职责

复用主文件的“忠实转换规则”“首次整理”“修改模式”“基础设定”“氛围与画质”“注意事项”及诊断和字符上限；在本分支，这些章节的明确输入是 C 提交的这一版整案，不进入旧项目的采用或写回步骤。

- 基础资产、状态资产和镜头参考按 C 标注的用途原样编排；不把场景母图机位、人物棚拍光或色卡版式推广为最终镜头约束。
- 使用提交包内已核实的素材标记及职责，保持允许/禁止继承和优先级；不自动改编号，不以本地路径代替上传标记。未提供图片时可编排已有文生内容，不能制造参考图。
- 仅调整已有信息的顺序、标点与必要连接词；不因为主文件诊断发现缺项就补写相机、光线、氛围、材质、构图或动作。内部依赖仍由 C 在提交前展开。
- 定点修改须取得上版完整复制层和明确差量，保留其余成像、主体、空间、素材及限制；完整返回，不以摘要代替正文。

## 框外状态与返回

复制框外标注“候选提示词｜本稿版本”，代码块保留原有三段式结构；框内不插入“未采用”、内部编号或状态说明。诊断槽位继续区分实际缺口、可选增强和已足够；“已足够”只表示当前文字信息足够，不证明采用或真实效果。

诊断中新增的创意建议只能返上游成为下一版候选输入，不能偷偷并入本版复制层。格式器完成后把精确复制层、稿件版本和诊断返 C1/C2，不自行建立正式提示词卡；C1/C2 根据实际能力通过 SaveDraft/Adopt 保存，消费已采用文本先 Resolve；格式器不执行事务或媒体动作。
