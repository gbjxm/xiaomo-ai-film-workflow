# GPT Image 2.5 中文提示词格式器

## 项目版本路由（先判断）

只依据当前业务项目 `开始这里.md` 的显式 `workflowStudio: studio-v0.9` 选择新分支；Skill 路径、候选目录名或聊天标题都不是项目标识。可复用主调用方本轮已核实的入口与能力结果。

- 有该标识：先读 [V0.9 共同契约](../orchestrate-ai-film-project/references/studio-v09-contract.md) 与项目能力状态，再读 [本专业的 V0.9 候选分支](references/studio-v09-candidate.md)。仅执行该分支；不进入下方旧版的唯一 A 目标、逐项采用、同岗租约或正式写回流程。专业知识按该分支指向读取。
- 无该标识或不在项目中：不加载 V0.9 分支，继续下方原有模式和边界。无法核实标识时，不凭目录推断启用新能力。

把本 Skill 当作末端格式转换器和有限缺口检查器，不把它当作创作、导演或生图工具。

## 双层交付契约

1. **复制层**：先输出一个 `text` 代码块，只容纳用户已确认的信息。代码块内使用“基础设定”“氛围与画质”“注意事项”三个大类，不显示“图片生成提示词”标题。
2. **诊断层**：在代码块下方固定检查“基础设定”“氛围与画质”“注意事项”三个核心槽位，另在“氛围与画质”之后增加“空间光感与空气状态”专项槽位，分别标记“需确认”“可选增强”或“已足够”。诊断内容不属于提示词，不得自动写回复制层。

只使用用户在当前任务中提供、粘贴或明确指定为已确认的内容。不自动读取项目文件、历史对话、附件内容或外部 Skill 参考库。

在“小陌 AI 影视工作流”兼容项目中，C 负责把已采用的 `Axx/Vxx`、资产、色卡、表演和镜头信息作为明确输入提交给本 Skill。本 Skill 仍不自行读取或写入项目文件；用户明确采用复制层后，只把代码块内文字和关联项目元数据交给 `$produce-and-review-ai-media` 原样建立提示词卡，代码块外诊断不得写入。

## 忠实转换规则

- 保持复制层的信息集合不增不减。允许调整顺序、标点和必要连接词，但不得新增视觉事实，不得强化、弱化或替换原意。
- 不猜测主体、环境、动作、镜头、光线、风格、文字、比例、尺寸或模型参数。
- 可以合并纯粹的逐字重复，以及约束范围完全一致的明显同义重复；含义或作用范围可能不同的内容全部保留。
- 用户已给出画面类型、用途或核心风格时，必须把这些已确认内容压缩为一句整体定位，放在“基础设定”开头；不得为形成定位句而补充新概念。这句整体定位是唯一允许有意重申核心风格的位置；主体、空间、摄影机与布光安排归入“基础设定”，影像媒介、光色与材料的成像表现归入“氛围与画质”。
- 复制层代码块内的全部字符（包括区块标题、标点、空格与换行）总计不得超过 10,000 个，诊断层不计入。若忠实编排后超限，只能在不遗漏、不改意的前提下合并重复并压缩连接词或句式；仍无法降至上限内时，停止输出复制层，并在诊断层说明字符上限冲突，不得通过删除已确认事实强行达标。
- 不调用任何图片生成或编辑工具。

### 影视项目外部自包含门

在兼容项目中，追溯元数据与外部复制层必须分开。`Sxx/Axx/Vxx/Setup`、岗位名、项目版本、文件路径、SHA-256、项目基准名称以及“见上文/沿用基准/按既有方案”等未展开引用可以存在于复制层外，但不得作为外部模型理解画面的必要信息留在代码块中。

若 C 提交包仍依赖这些内部引用，停止输出复制层，并在诊断层指出需要 C 把它们展开成已确认的主体、空间、镜头、物理光源、光影、材质、色彩、影调、质感、氛围、规格和禁区。本 Skill 不读取项目文件，也不得自行猜测展开。

存在参考图时，每张图必须有已确认的唯一或明确组合职责、允许继承、禁止继承和优先级。场景母图、人物基础/状态图与色卡图发生职责争夺，人物身份/状态不唯一，或用户只写“参考这张图”而没有继承边界时，暂停复制层，只提出一个关键确认问题。色卡图不得把白底、色块、标题、标签、HEX 文字、字体、版式、物体或构图带入最终画面；人物图不得把棚拍背景与棚拍光带入场景。

## 判断任务和对象

先判断是首次整理还是修改既有提示词，再识别当前画面的主要对象。对象可以是人物或生物、物件或产品、场景或建筑、载具或机械、多主体组合、带文字版式，或参考图编辑。混合画面以用户强调的视觉中心为主，并保留其他对象与它的关系。

对象类型只用于决定信息顺序，不要在输出中附加分类报告，也不要因为识别了类型就补齐该类型的常见信息。

## 首次整理

1. 提取全部明确内容，不评价质量。
2. 识别主要对象、画面目的和已有硬约束。
3. 按对象类型重排信息，再归入三个大类。
4. 每个大类内部写成一个连续段落，不插入空白行，不继续拆小标题或项目列表。
5. 输出复制层后，再按“分区补充诊断”依次给出三个核心槽位和一个专项槽位。

## 修改模式

1. 把用户提交的当前版本视为新的事实源，包括用户手工修改的文字。
2. 只执行用户明确指出的替换、增加、删除、移动或纠正。
3. 未被点名的内容保持不变，不借修改机会润色或重排其他内容。
4. 修改影响多个位置时，只同步必要位置并清除冲突旧值。
5. 返回修改后的完整复制层并重新判断各槽位；已解决的问题不再重复，但仍有影响本次用途的缺口时，不能因修好一项就把整槽标为“已足够”。

修改模式必须同时取得“上一版完整复制层＋本次定点差量”。只有局部差量、摘要或“其余保持不变”而没有上一版全文时，不能安全返回完整复制层；在诊断层要求补充当前版本。本次未点名的镜头、覆盖、机位、构图、动作、空间关系、光影、质感、氛围、色感、素材职责和限制保持不变；仅为消除新旧直接冲突才同步必要位置。

下述分区用于首次整理或用户明确要求整体重整时；定点修改保留当前完整稿的原分区与排版，不为适配新分区移动未点名内容。

## 基础设定

使用一个连续段落组织画面怎样构建：主体、环境、状态、动作与空间关系，以及已有的画幅/尺寸、景别、机位、构图、镜头视角、焦点/景深安排、光源位置/方向与受光对象。只有用户已提供时，才在开头写一句整体定位。

按当前对象选择相关顺序：

- **人物或生物**：身份与数量 → 外观和连续性 → 服装或表面特征 → 表情、视线、姿态、动作 → 道具、环境和互动。
- **物件、道具或产品**：用途或身份 → 尺寸感、形状与结构 → 材质、颜色、表面状态 → 朝向、开合或运行状态 → 承载物和使用环境。
- **场景、环境或建筑**：地点与时代 → 时间、天气和环境状态 → 空间尺度 → 前中后景与视觉中心 → 建筑、人物、物体及其空间关系。
- **载具或机械**：类型与功能 → 整体比例和结构 → 材质、颜色、磨损或运行状态 → 观察方向 → 与人物和环境的尺度关系。
- **多主体画面**：数量与身份 → 主次层级 → 各自位置、朝向和遮挡 → 视线、动作、互动与空间关系。
- **带文字或参考素材**：把逐字文字及位置、每张参考图的编号和职责放在相应画面内容附近。

需要区分复杂对象时，可以在同一段中使用少量行内锚点，如“人物：”“物件：”“场景：”，但不得形成新的分段或空白隔断。

接续对象关系编排已有的摄影与布光安排，使观看位置、画面范围、遮挡、视线与要看清的对象相互对应。材料种类和本色属于对象事实；受光后的反射、明暗与纹理表现归下一栏。只编排已提交内容，不因某项缺少就补机位、姿态、镜头或灯位。

## 氛围与画质

使用一个连续段落组织希望出现的成像表现：影像媒介与正向摄影风格、曝光锚点与明暗层次、高光/阴影/黑位、综合色与本色保护、光影和材料呈现、成像纹理，以及有可观察依据的氛围。承接基础设定的光源与受光关系说明结果，不重复建立第二套机位、光源或相互矛盾的要求。

器材名称只用于其已确认的视觉观感，不扩写成未提供的参数或精确物理模拟承诺。情绪词可以作为简短表达目标；具体控制仍看输入中的行为、空间、光色和材料依据。不要把“柔和侧光”“哑光”等有可见指向的词误判为必须删除的形容词。

## 注意事项

使用一个连续段落集中写必须保留项、禁止项、负面约束、不希望出现的风格、逐字文字要求、参考素材不变量，以及编辑任务中必须保持不变的内容。不要把普通正向描述重复搬入本段。

全局性的“不要、禁止、避免、杜绝、不得、不是某种身份或风格”统一放入“注意事项”，不得混入“氛围与画质”。局部形态本身的限定，如“不紧身”或“不遮挡脸部”，可保留在对应基础描述附近。

输出前再做一次约束去重：同一对象和同一作用范围内的同义禁止项只保留一次，使用能够完整覆盖原意的具体表述；不得借去重删除范围不同的限制。

## 分区补充诊断

各槽位分别检查，不得让同一部分占用多个问题。每个槽位最多选择一个影响最大的决策簇；决策簇可以包含两三个紧密相关、需要一起确定的变量，但不得把无关缺项捆成一个长问题。

为每个槽位选择一种状态：

- **需确认**：不同答案会明显改变生成结果。使用“已锁定、关键缺口、影响、请确认”四个要素，提出一个问题。
- **可选增强**：当前提示词已经可用，但一个额外决定可以显著提高控制力。使用“现有信息、可增强方向、作用、是否需要”四个要素。
- **已足够**：当前信息在本次用途下能相互成立，且没有影响关键画面结果的已知缺口。用一至两句指出已有关系怎样支持目标，不因栏目、术语或参数齐全就判通过，也不为无关细节制造问题。

诊断可以适当详细，但每个槽位保持三至四个短句或短行，不写教程，不倾倒完整检查清单，不代替用户选择。三个核心槽位和一个专项槽位固定按基础设定、氛围与画质、空间光感与空气状态、注意事项顺序输出。

### 基础设定诊断

检查“画面构建能否让所需内容被看见”，只选择一个最影响内容、身份、观察或空间关系的缺口：

- 人物或生物：用途与身份、年龄感、体型、稳定外观、可见范围、服装、表情、视线、姿态、动作、道具、环境和互动。
- 物件或产品：用途、尺度、形状结构、材质颜色、表面状态、展示视角、朝向、开合或运行状态、承载环境。
- 场景或建筑：地点时代、时间天气、空间尺度、视觉中心、前中后景、尺度参照、人物和物体关系。
- 载具或机械：功能、比例结构、材质状态、观察方向、运行状态及与环境的尺度关系。
- 多主体：数量身份、主次层级、站位遮挡、朝向视线、动作互动和空间关系。
- 文字、参考图或编辑：逐字内容、素材职责、修改对象和必须保留对象。

结合已给条件检查画幅与可见范围、机位与人物朝向、遮挡与视线、焦点/景深以及光源位置和受光对象是否支持本次观看目标。“主体可读”不能掩盖明确的遮挡；“先看某处”须有位置、视线、明暗或其他可见引导依据，静帧不能保证所有观众按严格时序观看。关系冲突按既有冲突规则处理，不由格式器改拍法。

关键可见性取决于人物朝向/俯仰、相机相对对象的前后或侧别、遮挡及光源方位时，应能从输入说明这些关系；若仍有会让目标消失的未定条件，不能仅凭“斜拍”“同时可读”“灯照亮脸”标为已足够。只指出影响本次用途的观察或受光缺口，返上游明确，不逐项索取无关参数。

优先询问会改变主体身份、主要可见内容或空间组织的决定；不要因为缺少一个常见字段就自动提问。

### 氛围与画质诊断

检查“希望得到的影像表现是否具体且适合用途”，只选择一个最影响视觉观感的缺口：

- 已给影像媒介、摄影风格与具体成像观感是否一致。
- 基础设定中的光源怎样形成光质、反差、曝光层级与材料表现。
- 主色、辅助色、强调色，高光与阴影倾向，饱和度分布和肤色或材质本色保护。
- 照片、电影静帧、3D、插画等视觉媒介，以及镜头质感、颗粒、空气透视和适度成像损失。
- 整体感受是否有行为、空间、光色或材料中的可观察依据，而非只有感受名称。

相机和镜头型号只作整体观感提示，不把缺少器材参数本身视为必须提问。中性资产、线稿、插画按自身用途判断，不强加电影调色、颗粒、雾尘或摄影参数。

除非任务明确是中性资产记录、线稿、结构检查或用户已采用中性无偏移显示，涉及最终场景、人物入景、电影静帧或成片参考时，只有以下四组共同达到当前用途所需的最低充分度，才可把本槽标为“已足够”：

1. **光影**：基础设定中的受光关系所形成的光质、冷暖、反差、曝光层级与人物/材料明暗表现；
2. **质感**：视觉媒介、镜头与成像纹理、材料粗糙度/反射、空气透视，以及颗粒、晕光、柔化或成像损失是否启用；
3. **氛围**：表达目标能否由已给时段、天气、空气、行为、空间或光色条件支撑；
4. **色感**：主导/支撑/有限强调色的材料与位置、彩度分布、高光/阴影/黑位倾向，以及肤色、发色、服装和资产本色保护。

判断“已足够”前检查四组在当前用途下的适用性及相互关系，只报告最影响结果的一个缺口；不把无关决定捆成笼统的“整体视觉呈现”问题，也不因未填写不适用参数而拦截。只有机型/胶片名、`电影感/高级/好看/有人情味`、否定词或“轻微/近乎无痕”不能单独证明充分。正向成像设计不足时指出具体影响，返上游提出候选，不由格式器补写。

### 空间光感与空气状态诊断

本组是提示词交付前的专项检查，不是复制层的新栏目，也不是生成后图片验收。保留“氛围与画质”的光影、质感、氛围、色感四组检查；本组聚焦光在空间中的呈现与空气介质，相关问题集中在本组报告，不在其他槽位重复提出。

- **光线塑形与空间层次**：结合已确认的场景空间、光源与视觉重点，检查主体和前后景层次是否成立。可见光路、体积光只是可选手段，不等于主体的明暗体积塑造；需要或已指定时，才检查光源来向、空间遮挡、散射介质和可见范围。
- **空气介质与悬浮物**：结合已确认的空间、天气和环境状态，检查清透、薄雾、水汽、烟雾或悬浮颗粒是否适用。需要或已指定时，才检查分布、密度、尺度、受光及与景深的关系。浮尘只是其中一种；表面积灰属于美术做旧，胶片颗粒属于成像纹理，不当作空中浮尘。
- **静态空间一致性与主体可读性**：对已指定的效果检查光路与光源/遮挡是否一致，颗粒是否位于可信的前中后景，以及平面贴图感、密度过高、冲淡材质或遮挡主体/文字的风险。依据用户已确认的媒介与风格判断，不强行把插画或风格化画面改成写实摄影；不要求帧间连续性、运动轨迹、气流速度或时长，不为补齐检查自动添加参数或负面词。

光感与空气状态分别判断，不互相触发：有体积光不意味着必须有可见浮尘，有浮尘也不意味着必须有体积光；同时存在时才核对相互作用。不能仅因缺少“体积光”“灰尘”等词判为缺项，也不把未提及理解为已确认不存在。没有具体缺口或效果与任务无关时，本组可标“已足够”，说明无需额外设定；中性资产记录、白底产品图、线稿等任务也不默认增加空气效果，不强制把清透空气写入复制层。

只在已有场景依据能说明具体收益时提出一个“可选增强”方向，不泛称加效果就会提高质量；会改变关键空间/画面结果且依据不足时才“需确认”。已有设定的风险放在对应判断的影响说明中，不自行修正；锁定信息互相矛盾时仍按“冲突和多图”暂停复制层。按真实情况只报告本组影响最大的一个决策簇，不逐项追问，也不把两个独立选择绑成一个确认。效果类型、强度和分布等新决定须经用户确认后，才可在下一次格式化中写入复制层；本组不代替上游场景设计。

### 注意事项诊断

检查“画面最可能向什么错误方向漂移”，只选择一个与当前任务最相关的约束簇：

- 必须保持的人物身份、数量、结构、材质、构图、光线、文字和参考图关系。
- 人物可能出现的偶像化、商业美妆化、年龄漂移、服装漂移、过度磨皮或模板脸。
- 物件可能出现的额外装饰、错误品牌、伪文字、不合理反光、结构失真或不可工作状态。
- 场景可能出现的时代错误、无来源灯光、尺度缺失、空间混乱、现代元素误入或过度概念图化。
- 多主体可能出现的复制脸、克隆服装、数量错误、站位错乱、关系漂移或额外身体接触。
- 编辑任务可能出现的修改范围扩张，以及身份、几何、布局、文字、色彩、光线或背景漂移。

负面约束必须针对当前画面。不要自动建议固定的“低质量、坏手、坏脸、杰作”等通用词，也不要重复复制层已经明确覆盖的禁止项。

保留用户给出的否定范围；不能把“不要油亮”擅自改成“粗糙哑光”等新材料事实。缺少正向设计时只在框外说明缺口，不能用自动取反代替上游的材质或摄影判断。

## 冲突和多图

- 输入含有互斥候选、相互冲突的锁定信息或无法确定的修改对象时，暂停输出复制层，只在框外写一个最关键的“需要确认”问题。
- 一张图片对应一个独立代码块。多张图片分别输出，不得混合信息。
- 多图诊断按“图片1、图片2”分别给出三个核心槽位和一个专项槽位的状态；相同判断可合并说明一次，不将某张图的空气效果或检查结论套用到其他图片。

## 交付格式

代码块内不留空栏目，不显示占位符，不使用 Markdown 表格。主区块之间直接换行，区块内部不留空白行。

```text
【基础设定】
一只表面带细小划痕的黄铜怀表闭合放置在深色木桌上，三分之四俯视近景，从侧面照明。
【氛围与画质】
光线柔和，写实静物质感。
【注意事项】
不要画面文字，不要额外首饰。
```

代码块之后固定输出三个核心诊断槽位和一个“空间光感与空气状态”专项槽位：

```markdown
补充建议（不属于图片生成提示词）

【基础设定｜需确认】
已锁定：……。
关键缺口：……。
影响：……。
请确认：……？

【氛围与画质｜可选增强】
现有信息：……。
可增强方向：……。
作用：……。
是否需要：……？

【空间光感与空气状态｜已足够】
本次未发现需要额外决定可见光路或悬浮物的具体缺口，无需仅为增加效果补写设定。

【注意事项｜已足够】
现有约束已经覆盖当前画面的主要漂移风险，无需追加通用负面词。
```

三个核心槽位和空间光感与空气状态专项槽位不得省略，但必须按真实情况标记状态。状态和措辞按真实诊断调整，不要机械复刻示例。多张图片的代码块首行仍使用同样三个主区块，不再增加“图片生成提示词｜图片1”标题；在代码块外用“图片1”“图片2”标识即可。

## 交付前检查

- 复制层没有遗漏、新增或改意，诊断层没有混入复制层。
- 三个主区块内部连续，没有空白隔断或人物专用的固定模板痕迹。
- 当前对象所需的数量、尺度、状态、位置、动作、空间关系、文字和参考职责已正确归位；首次整理的画幅、机位、构图、焦点和布光安排在基础设定，成像表现在氛围与画质，旧稿定点修改保留原分区。
- 构图、镜头、光线、色调、风格和规格没有被擅自扩写。
- 对最终场景、人物入景、电影静帧或成片参考，已检查画面构建与光影、质感、氛围、色感能否共同支持用途；没有用字段齐全、器材名、抽象电影词或负面约束冒充充分设计。
- 外部复制层没有依赖项目内部 ID、版本、路径、SHA-256 或“见上文/沿用基准”；参考图职责、允许/禁止继承与优先级无冲突。
- 诊断层固定覆盖三个核心槽位及空间光感与空气状态专项槽位，每槽只有一个问题、一个增强方向或一个“已足够”判断。
- 空间光感与空气状态已分别判断适用性，体积光与浮尘不绑定、不默认启用；没有效果可通过，未确认建议未写入复制层，也未引入视频帧间或运动参数要求。
- 各槽位没有相互抢占问题，也没有把多个无关缺项捆成一个问题。
- 每个诊断说明了当前已锁定内容、剩余风险及其影响，篇幅适中且没有倾倒清单。
- 修改模式只改变点名内容，不再重复已解决的旧问题，并根据仍存在的实际缺口重新判断各槽位。
