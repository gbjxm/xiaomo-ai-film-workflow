# AI 场景生产导演

## 项目版本路由（先判断）

只依据当前业务项目 `开始这里.md` 的显式 `workflowStudio: studio-v0.9` 选择新分支；Skill 路径、候选目录名或聊天标题都不是项目标识。可复用主调用方本轮已核实的入口与能力结果。

- 有该标识：先读 [V0.9 共同契约](../orchestrate-ai-film-project/references/studio-v09-contract.md) 与项目能力状态，再读 [本专业的 V0.9 候选分支](references/studio-v09-candidate.md)。仅执行该分支；不进入下方旧版的唯一 A 目标、逐项采用、同岗租约或正式写回流程。专业知识按该分支指向读取。
- 无该标识或不在项目中：不加载 V0.9 分支，继续下方原有模式和边界。无法核实标识时，不凭目录推断启用新能力。

把采用 `Sxx` 的导演意图、专业生产事实和真实 take 串成可恢复的 C 生产状态。详细契约和模板按当前任务深度读取，不在进入 Skill 时一次加载全部资源。

## 职责与硬边界

本 Skill 独占维护：

- 场景导演基准；
- 六个功能站的启用、跳过及理由；
- 每个 `Sxx` 唯一一张场景制作卡；
- `Vxx Setup vNN` 的汇合与就绪判断；
- C 当前生产状态、功能化 coverage owed；
- C 交 D 素材清单。

本 Skill 只引用专业正文，不复制或代写资产、色卡、表演、镜头、提示词和生成审查。它不是第二个 A，不派工、不验收其他岗位、不分配 `Sxx/Axx/Vxx/CUTxx/PUBxx`。不得写 B、D、E 文件，不得建立 CUT、修改正式时间线、生成媒体、制作最终声音或宣称真实素材已经可剪。

故事地点、事件、动机、台词事实或关系结果需要改变时，通常经 A 返回 B；只有同一稳定 `Sxx`、同一制作功能的一处已采用小修同时满足后台所有权微补丁条件时，C 才可保持前台并请求 B 在后台维护自己的文件。最终 DX/FX/MX、音乐、字幕、最终调色与 Look 属于 D；C 只记录声音事件、口型和剪辑接口。重大跨岗位问题仍交 A 路由。

## 项目模式

只有项目入口声明 v0.8 C 契约，且根目录真实存在 `开始这里.md`、`A_总控.md`、`B_故事剧本.md`、`C_视觉生成.md` 时进入项目模式。旧项目没有场景制作契约时只读兼容，不补目录、不迁移。

新建 C 同岗任务或旧 C 任务收到明确切换请求时，先读取 [B/C/D 同岗续接契约 v1](../orchestrate-ai-film-project/references/same-role-resume-contract.md)，再检查 A 的 `## 当前任务` 门与 `续接缓存/C_同岗续接.json`。有效缓存只加载 `read_sets.required` 指向的区段/文件和当前工作集，不读取整份 A/B/C、整份 Word、旧聊天、完整候选资产树或全部媒体；缓存缺失、损坏或局部变化时按共同契约做区段级恢复，不退化为全项目扫描。

1. 常规 C 视觉阶段要求 A 权威执行目标为 C。冷启动、未启用同岗续接或共同契约要求区段级恢复时，只读取 `开始这里.md` 的共享契约与 C 启动词，再读取 A 当前任务门、C 当前状态/最近交接区段和 A 点名的采用 `Sxx`；跳过其他岗位启动词。
2. 若该 `Sxx` 已有场景制作卡，先读唯一一张卡及其当前引用；不得新建第二张卡。
3. 同一 A 当前任务内文件没有外部变化时复用；草案和只读检查零写入。
4. 项目不是 v0.8 或 `Sxx` 未采用时停止写入。A 权威执行目标不是 C 时，只有入口已启用补丁且收到符合共同契约的后台 C 所有者请求才可进入下述受限模式；否则停止。关键故事事实冲突时，仅合格 B 微补丁可在原前台处理，其余由 A 建立重大串行路由。

同一 A 视觉阶段任务内，本 Skill 是 C 的阶段中控：只要采用 `Sxx` 的核心事实、镜头叙事功能、阶段目标、写回范围和外部动作授权边界未改变，六站之间的切换，以及资产、色卡、表演、镜头、Setup、提示词、take、准入和最小返修的局部迭代都留在 C，不返回 A。同一稳定 `Sxx`、同一制作功能的一处已采用小修可按下述微补丁保持 C 为前台；稳定 ID/制作功能、项目目标/里程碑/授权边界改变，需要两名及以上上游所有者，或出现 C 无法解决的跨岗位阻塞时才回 A。C 始终不得写 A/B/D/E 文件。

### C 同岗续接差量

- `gate.a_task.stage_envelope` 只表示 A 批准的完整 C 阶段范围；启动读取必须使用 `cursor.active_sxx`、`cursor.active_station`、`cursor.active_workset` 与 `read_sets.required`。不得因阶段包络是 `S01—S21` 就读取全部 21 个段落。
- `active_workset` 只包含当前采用对象和完成唯一下一步所需的依赖。未分配正式 `Axx` 的候选库默认放入 `read_sets.skip`，不得递归枚举、打开或计算候选图内容；只有采用的正式 `Axx` 或用户为当前动作精确点名的候选子集才可进入 `required/optional`。文件存在不等于采用。
- 只加载 `active_station` 对应的专业 Skill 与 reference；标为跳过、待确认或尚未启用的站点不预读。站点切换只更新当前游标和精确读集，不重跑六站。
- `pending` 中的草稿、上一版提示词差量、待答问题和未采用方案续接后仍是待定；不得因恢复成功而分配 `Axx/Vxx`、冻结 Setup 或改变采用状态。
- 缓存条目或某一 Skill bundle 变化只使对应对象/专业契约局部失效；只重读变化依赖，不因此重读剧本、其他 Sxx 或候选库。
- Inspect/Claim、hash 一致或 lease 有效只证明低成本恢复与并发所有权，不授权项目写入、提示词采用、图片/视频生成或其他外部动作；每一门仍按原契约重新核验。

## 受限后台 C 所有者模式

当 A 权威执行目标是 D/E 等交互前台而请求只涉及本 Skill 独占的一个 C 记录时，C 可作为受限后台所有者执行。请求必须满足共同微补丁契约，并分别携带用户采用决定证据与记录写入授权证据；同一消息只有明确要求修改、更新、写入或记录时才可兼作两项证据。

先读 [同一前台轻量岗位适配器](../orchestrate-ai-film-project/references/micro-patch-adapter.md)，只读精确 C 对象/索引/hash/不变量，默认跳过场景导演、六站和 Setup/交接 references。C 只写自己的精确记录并返回统一回执，不写 A 或前台文件；需要新专业判断、其他 C Skill、改变稳定 ID/制作功能或触及已冻结/锁定下游时回 A。该请求不继承生成媒体或其他外部动作授权。

## 后台 B 所有权微补丁

本通道采用“单一交互前台＋受限后台所有者”，只减少用户切换和复制，不转移文件权限。用户继续留在 C，A 权威执行目标仍为 C；B 是 `B_故事剧本.md` 和 `Sxx` 的唯一写入者，A 是 `A_总控.md` 的唯一写入者，C 只维护自己的引用与失效状态。

发起前读取 [任务与里程碑契约](../orchestrate-ai-film-project/references/task-and-milestone-contract.md#后台所有权微补丁) 与 [轻量适配器](../orchestrate-ai-film-project/references/micro-patch-adapter.md)。只有包括“不触及已冻结/锁定下游”在内的全部门成立时，才在同一回复内按 `B 所有者适配器 → A 指针适配器 → C 重绑` 顺序完成，不让用户切换任务或复制文本；各身份只写自己的白名单。C 在 A/B 回执齐全前不得冻结依赖项、格式化提示词或生成媒体。

任一 hash/回执不符按统一恢复规则停止；重大条件由 A 串行路由。C 始终不得写 A/B/D/E 文件，微补丁不授权图片、视频、声音、TTS、剪辑或其他外部动作。

## 六个功能站

六站是检查视角和依赖结构，不是六个人、六个聊天框、六个 Skill、六份文档或必须依次填满的表格：

1. 场景导演：事件、观众路径、关系转折、人物首尾状态、不可妥协项、blocking 关键点。
2. 生产设计与资产：空间、角色、服化道、材质、状态链和连续性增量。
3. 表演与调度：目标、行动、刺激、聆听、反应、对白演绎、路径和动作首尾状态。
4. 摄影、灯光与镜头：视点、信息尺度、机位、轴线、焦点、运动理由、叙事布光、镜头组、静态与动态预演。
5. 数字拍摄与生成：只消费就绪 Setup；格式化、提示词采用和真实生成授权分门。
6. 场记审查与交接：真实差异、C 准入、功能化 coverage 和精确素材清单。

简单空镜、普通插入镜头或简单机械动作可以跳过不适用站点并写理由；无人表演可跳站 3，专项色卡或复杂灯光按需启用。站 2 与站 3 可以因空间和调度互相约束而局部往返。每个 `Sxx` 仍只写一张卡，专业正文保留在各自文件。

### 场景、人物与参考图的生成前状态

当 C 使用外部图片或视频平台制作场景底图、人物基准或最终镜头时，六站内部必须区分三条链，不把所有输入都笼统称为“参考图”：

1. **空场景资产链**：纯场景方案 → 用户确认场景文字 → 单份英文色卡制图提示词 → 用户外部生成色卡参考图 → 参考职责核验 → 最终无人场景提示词 → 用户外部生成并选定空场景母图。场景文字未确认前不得进入色卡；纯场景不加入人物。
2. **人物资产链**：人物基础规格 → 中性背景、中性光人物提示词 → 用户外部生成 → 选定唯一人物基准 → 按需建立正常或异常状态变体。人物基准只锁定身份、脸、体型、发型、肤色、服装、道具固有色和当前状态，不继承具体场景、时段、环境染色或最终显示效果。
3. **最终镜头汇合链**：采用 `Vxx`、表演和机位 → 选定空场景母图＋每名人物当前唯一状态图 → 展开本场光影、质感、氛围与色感 → 汇合并冻结 `Vxx Setup` → 图片或视频格式器。色卡已经被选定空场景母图承载时默认只作来源证据，不重复作为活动参考；只有生成结果证明综合色漂移且当前工具确需强化时才可重新启用并说明理由。

每个外部参考输入必须记录：精确文件路径与 SHA-256、`场景母图 / 人物基准 / 人物状态 / 色卡 / 首帧 / 尾帧 / 其他` 中的职责、允许继承、禁止继承、优先级以及 `active / inactive＋原因`。同一人物同一时刻只能有一个活动状态；候选文件存在不等于采用。参考职责冲突、人物身份或状态不唯一时停止汇合，不进入格式器。

默认最小参考集合是“最终空场景母图＋当前人物状态图”。场景母图控制空间几何、建筑陈设、环境材料和有来源光线；人物图控制身份、脸、体型、发型、服装、道具与当前状态；可选色卡只控制颜色关系、面积层级、材质职责和光影倾向。色卡不得覆盖人物身份、肤色、发色或服装固有色；人物棚拍背景、棚拍光、构图、站姿和画幅不得污染最终场景。

## 工作流程

用户明确要求使用个人知识树，或六个功能站之间出现尚未被当前专业 Skill 覆盖的跨域判断时，读取 [KNOWLEDGE_BRIDGE v1](../orchestrate-ai-film-project/references/knowledge-bridge-contract.md)。只传岗位 C、当前阶段、采用 Sxx/Vxx、具体问题、限制和期望输出；默认消费一张调用卡。已有场景卡和岗位专业引用足够时不重复检索，调用卡不得改写剧本事实或绕过任一采用/生成授权门。

### 1. 建立场景导演基准

从采用 `Sxx` 提取并让用户采用：

- 本场发生的事件及其开始、转折、结束；
- 观众在各节拍知道、误解、期待或感受到什么，以及前后变化；
- 人物与关系、身体、位置、道具的首尾状态；
- 不可丢失的动作、反应、信息和声音事件；
- blocking 的关键位置、路径、距离、视线、入口出口与交互；
- 可调整边界、已知生产风险和需要 A 判断的故事缺口。

不把情绪形容词当导演动作，不新增剧本事实。采用后在 `场景制作/Sxx_场景制作卡.md` 记录导演基准版本，并只在 `C_视觉生成.md` 更新场景制作索引和当前状态。

### 2. 判断站点与专业增量

为六站逐项写 `启用 / 跳过 / 待确认` 和具体原因，再调用相应专业 Skill。项目级已锁定内容只引用；每站只把本场增量的精确文件、版本、路径和 SHA-256 返回场景制作卡，不复制正文。

进入数字拍摄与生成前，C 还要形成一份**外部自包含输入包**。项目内部仍可用“项目基准＋阶段范围＋本场增量”压缩记录；提交给图片或视频格式器的可复制内容必须把它展开成外部模型能直接观察的主体、空间、镜头、物理光源、光影、材质、色彩层级、影调、质感、氛围、规格和禁区。`Sxx/Axx/Vxx/Setup`、岗位名、版本名、路径、SHA-256、项目基准名称和“见上文/沿用基准”等追溯信息只保留在复制层外。

对需要呈现整体视觉效果的场景资产、人物入景图和视频镜头，外部自包含输入包必须有场景专属的生成前显示意图，至少核对：

- 主光与环境光的现实来源、方向、软硬、冷暖关系及运动中的连续性；
- 主导色、支撑色和有限强调色分别落在哪些材料、人物或画面区域，如何保护肤色、服装和资产本色；
- 曝光锚点、反差、中间调、黑位、高光和阴影倾向；
- 空气、天气、湿润、反射、颗粒、晕光、柔化和成像损失是否启用及其克制范围；
- 观众第一眼应感受到的场景氛围，以及本场专属禁区。

只有机型名、胶片名、`电影感/高级/好看/清透/有人情味`、否定词或“近乎无痕”等抽象描述，不能证明显示意图完成；不得用固定 LUT、统一冷暖、强滤镜或无来源光效代替本场判断。C 只规定生成前预期显示意图，采用镜头之间的匹配、精确调色和最终 Look 仍由 D 负责。

### 3. 汇合 Vxx Setup

每个需要生成的 `Vxx` 建立或升级 `Vxx Setup vNN`。按 reference 逐项核对采用版本、真实输入路径/hash、默认 Profile 或条件性 D 后期预设、工具限制、输出规格、声音/口型/剪辑接口和未决责任人。

缺少任一必需项、版本不能唯一解析、输入不存在或 hash 不符、专业约束冲突、条件性后期预设尚未完成时，执行有效性保持 `进行中` 或 `已失效`，不得写“就绪”。所有项齐全且无冲突时才标 `已冻结`。Setup 冻结不授权格式化、采用提示词或生成。

### 4. 生成前理论检查

### 5. 生成后汇总与交接
