# V1 岗位任务初始化

用于用户明确要求在已存在 V1 项目中“启动六岗位、建齐岗位、补齐岗位任务”，或执行脚本返回的六岗位启动包。仅想获得启动词时只交付，不执行创建；明确要求初始化则直接推进，不重复询问是否创建。

## 入口与读取

调用 `scripts/get_role_launch.ps1 -ProjectRoot <项目绝对路径>`。它只读取项目入口、能力与路径信息，返回一个完整 `launchPrompt`、五段 `standbyPrompts` 和六个 `roleTitles`，不创建目录、修改文件或创建 Codex 任务。不运行 `start_project.ps1`，避免给已有项目另建版本。`ReadRoot` 仅供新项目创建器内部校验临时副本，不是用户入口参数。

调用结果成功只证明启动包生成；不能报告任务已创建。向用户交付时原样展示 `launchPrompt` 一个代码块，不改写成“统一任务承担六岗位”，不拆成六次复制。新建 V1 项目也通过同一函数生成启动包，旧 v0.9/v0.8 分支保持各自行为。

实际执行先检查当前工具目录中的 Codex 原生项目、任务查询、改名、创建能力；工具名可能有命名空间，以真实 schema 为准，不凭名称伪造参数。工具不可用时保留状态，报告缺失能力，原样交付五段待命消息供手动创建；不能代用子代理、独立 CLI 会话、直接写入数据库或修改应用开关。任务工具恢复属于 Codex 环境排查，不由修改工作室能力或文本运行时实现。

## 创建与复用

按 `launchPrompt` 的项目归属、cwd 和重复任务条件执行；只能在用户指定的同一已注册本地项目创建可见任务。当前任务为 A，B/C1/C2/D/E 有唯一同岗任务则复用，缺失才创建；查询不完整时先定向补查，不能把未看见当作不存在。不同标题但可能属于同一岗位时先确认身份，不能按标题机械重复创建。已有任务只登记复用，不自动发消息、领取工作集或改变内容。

新任务的初始消息逐字使用对应 `standbyPrompts`，不附整个旧聊天、工作稿或其他岗位资料。创建为异步动作时，只用紧凑状态核对新任务的待命回复；`title/projectId/cwd` 与真实创建回执一致才报告已创建，收到待命回复才报告已待命。结果不明或失败时停止，不删除、不自动重试；再次执行仍先查询，不能重复创建。

初始化只建立岗位入口，不启动剧本阶段，不写专业文件，不创建或激活工作集，不执行生成、剪辑、导出或发布。当前 A 完成后等待用户具体请求；专业后续工作遵循项目现有 V1 契约与已确认设定。空的待命任务不使用 PrepareHandoff；真正接替同一已有工作集时才按共同契约交接，不恢复旧单岗续接或 A 派岗门禁。

## 验收范围

脚本回归验证覆盖新建和已有项目的启动包一致、V1 六岗位及五段独立短消息、两种工作资料布局、错误入口拒绝、零项目写入、旧版输出兼容。自动建岗还须真实工具调用及侧栏任务回读；用模拟工具或字符串检查只能证明对应层级，不能代替真实创建验收。
