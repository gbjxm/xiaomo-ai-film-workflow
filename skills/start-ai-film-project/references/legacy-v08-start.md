# 启动 AI 影视项目

## 目标

在五岗位开始工作前完成一次确定性项目初始化：

```text
项目名
→ 自动选择 <项目名>_vN
→ 复制并验证 v0.8 模板
→ 写入项目身份和五岗位启动词
→ 打开项目文件夹
→ 在聊天中交付一段轻量单提示词启动包
```

这只是启动工具，不是第六岗位。项目建立后按 A_总控、B_故事剧本、C_视觉生成、D_后期剪辑、E_发行复盘工作。

## 边界

- 只创建全新项目，不修改、升级、搬运或修复已有项目。
- 不主动读取或复制旧项目内容；旧材料必须由用户在新项目中重新确认采用。
- 不发展故事、人物、视觉、提示词、生成、剪辑、发行或复盘方案。
- 初次调用只创建文件夹并交付单提示词启动包，不直接创建 Codex 任务。
- 用户把启动包发送到新项目第一个任务后，该任务才作为 A 创建 B/C/D/E 四个独立待命任务；首轮只建立并核验任务拓扑，A 与待命任务都不加载岗位 Skill、不读取业务文件或检查空派工。用户第二条消息才进入 A 业务。
- 不使用子代理、工作树、项目外任务或第二个 A 代替五岗位任务。
- 不覆盖同名版本目录，不回收历史版本号，不迁移旧项目补建 E。

## 输入与定位

日常只需要项目名。用户没有给项目名时，只问一个问题：项目叫什么？

路径由工作流安装配置自动提供：

```text
项目父目录：<工作流根目录>\项目
权威模板：<工作流根目录>\工作流\项目模板\小陌AI影视项目模板_v0.8
```

脚本按固定顺序定位工作流：显式参数、本机安装配置、Skill 源码相对位置。三者都不可用时硬停止并提示运行根目录的 `安装工作流.ps1`。只有用户明确指定其他位置时才覆盖默认项目父目录；不要为类型、时长、平台或风格提前追问，这些由 A 后续处理。

## 执行

1. 确认请求是创建全新项目，而不是继续当前项目。
2. 调用 [scripts/start_project.ps1](../scripts/start_project.ps1)。Windows PowerShell 读取或运行中文脚本时保持 UTF-8。
3. 日常调用只传 `-ProjectName`：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "<本 Skill 目录>\scripts\start_project.ps1" -ProjectName "项目名"
```

4. 用户明确指定工作流、父目录时分别追加 `-WorkflowRoot`、`-ProjectsRoot`。只有测试或模板迁移核验才使用 `-TemplateRoot`；自动化测试追加 `-NoOpen`。
5. 非零退出时只说明脚本返回的问题，不手工补做半个项目、不覆盖冲突目录。
6. 成功时解析脚本返回的 JSON，不凭记忆重写路径或启动词。

## 交付

成功后：

1. 给出项目文件夹绝对路径，提醒用户在 Codex 中选择该文件夹。
2. 只展示 JSON 的 `launchPrompt`，放在一个完整代码块中，不重写、不拆分，也不另行展示五段岗位提示词。
3. 要求用户在该项目中新建第一个任务，并把 `launchPrompt` 作为第一条消息完整发送；当前任务成为 A，再创建 B/C/D/E 轻量待命任务。
4. 不自动进入 A，不替用户开始创作。

五段完整岗位提示词只写入新项目 `开始这里.md`，不再重复嵌入 JSON 或 `launchPrompt`。JSON 仅保留五段提示词的 SHA-256、B/C/D/E 四段短待命消息和轻量 `launchPrompt`。`launchPrompt` 含本机绝对项目路径，只用于当前聊天交付，不写入项目文件。

## 单提示词启动契约

- 当前任务首轮只建立任务拓扑，不创建第二个 A，也不读取 A 或其他岗位完整启动词；用户下一条消息才从 `开始这里.md` 读取 A 启动词并开始业务。
- 创建 B/C/D/E 时，初始消息必须逐字等于 `standbyPrompts.B/C/D/E` 的轻量待命消息。待命消息只要求确认待命；用户第一次进入该岗位后，任务才读取 `开始这里.md` 的共享契约与本岗位完整启动词。
- 只在绝对路径与 `projectRoot` 完全一致的已注册本地 Codex 项目中创建独立任务；不得使用子代理、fork、handoff、工作树或项目外任务。
- 不覆盖模型或推理等级。标题依次为 `B｜故事剧本`、`C｜视觉生成`、`D｜后期剪辑`、`E｜发行复盘`；接口支持时可在同一工具批次并行创建，否则按 B、C、D、E。
- 创建前做一次项目/任务前置查询，创建后做一次岗位拓扑核验。先由绝对路径取得唯一目标 `projectId`；B/C/D/E 只统计 `projectId` 与 `cwd` 都等于目标项目的任务，其他项目同名任务一律忽略且不得复用。每个岗位已有且仅有一个标准标题时直接复用；缺失时只创建该岗位；目标项目内同一岗位重复或无法在最近 50 条任务可见范围内确认时停止，不猜测。中断后重新发送同一启动包不得创建 `_v2` 项目或重复岗位任务。
- 任一步失败时不删除、不自动重试；保留已创建任务，报告已创建/已存在/缺失岗位，并只展示缺失岗位的短待命消息。
- 创建并核验完成后留在 A，立即结束首轮；不等待、汇总或继续操控 B/C/D/E，也不在同一长事务里开始 A 业务。

## 失败处理

- 项目名为空、非法、使用 Windows 保留名、末尾为点或空格、或自带 `_vN` 时停止。
- 模板缺失、结构不完整、复制校验不一致或目标冲突时停止；只允许清理本次创建的 `.creating-*` 临时目录。
- 资源管理器打开失败不回滚已验证成功的项目。
- `launchPrompt` 执行环境缺少独立任务创建能力时，A 保持有效，并展示缺失岗位的短待命消息供手动创建；完整岗位提示词仍由各任务第一次使用时从 `开始这里.md` 读取。
- 不删除、移动或重命名任何既有正式项目目录。

## 验收点

- 新项目文件夹使用历史最大版本号加一。
- 六个根 Markdown、`场景制作/`、五岗位内部生产目录、`发布包/`、流程改进日志目录、`续接缓存/`、`剧本/工作稿/`、`剧本/采用稿/`、`剧本/生产稿/`、`剧本/历史/`、`剧本/阶段完成包/` 和完整空资产目录来自 v0.8 权威模板。
- `续接缓存/B_同岗续接.json`、`C_同岗续接.json`、`D_同岗续接.json` 均符合 `xiaomo.same-role-resume/v1`、小于等于 6,144 UTF-8 字节、初始 revision 为 0、lease/handoff 为空，且明确 `cache_is_authority=false`、`resume_validation_grants_write=false`；首次岗位派工后只允许由同岗续接脚本原子初始化。
- `A_总控.md` 只预填基础项目名，其他创作字段保持模板状态。
- `开始这里.md` 包含项目身份、相对定位说明、`workflowResume: same-role-resume-v1`、`workflowScript: b-word-stage-ready-v1`、两种同岗续接入口和五段版本化启动词，不再含 `【项目名】`，也不持久化绝对路径。
- 五段任务标题为 A/B/C/D/E 标准标题；启动词逐字来自权威模板。
- JSON 包含 `rolePromptSha256.A/B/C/D/E`、`standbyPrompts.B/C/D/E`、`launchPrompt`、字符计数、绝对 `projectRoot` 和 `startFile`；不重复包含五段完整岗位正文。
- `launchPrompt` 不含 `ROLE_PROMPT` 全文块，UTF-8 字节与字符数都受绝对上限约束并显著小于已冻结旧启动包；四段待命消息都只做待命确认和首次使用路由，不点名或调用具体业务 Skill。
- 模板源文件和所有既有项目保持不变。
