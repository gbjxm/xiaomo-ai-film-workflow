# 已验证能力与未验证范围

核验日期：2026-09-16。以下分别记录受限 stdio MCP 与直接官方 SDK 的实测，不把一种入口的成功自动算作另一种入口通过。

| 范围 | 当前证据 |
|---|---|
| 本机连接 | Windows / Python 3.12.10，实际 stdio 会话读到 DaVinci Resolve Studio 20.3.0.10 |
| 工具清单 | 444 个上游注册工具中允许 143、移除 301；实际 list_tools 与策略一致 |
| 当前工程/时间线读取 | 本次实际会话完成产品名、版本、当前工程、当前时间线、时间线名、起止帧、视频轨道数、渲染状态共 9 次读取 |
| 禁用入口 | 同一真实会话拒绝脚本执行、表达式、项目删除、退出、页面跳转、云工程、Quick Export 共 7 类调用；没有调用这些原生方法 |
| 服务器保护 | 12 项离线测试通过，覆盖全部移除工具拒绝、协议分发、参数约束和保存命名框保护；未登记工程的拒绝分支使用 Mock 验证 |
| 本 MCP 基础变换、恢复与保存 | 在明确授权的隔离工程、指定时间线的一条视频片段上完成 Pan 0→1→0；中间读回 0.9999999999999999，恢复/保存后读回 0。完整 Inspector 属性字典、所在轨道片段结构恢复一致，前后均为 edit 页面；2 次属性写入＋1 次已登记工程保存，无新建/渲染/页面切换 |
| 本 MCP 尚待实际写入验收 | 素材导入、时间位置/剪切调整、CDL/颜色版本、LUT、DRX、MCP 路径渲染和保存后的重新打开。源码接口存在不等于这些链路已逐一通过 |
| 直接官方 SDK，独立于 MCP | Studio 20.3.0.10：CDL、Grade Version、工程保存关闭重开、原生渲染已做隔离验收；DRP 仅验证导出成功，尚未验证重新导入恢复。样本为 5 秒、120 帧、24 fps；4 个视频文件的解码哈希证明调色改变画面、重开后调色一致、恢复后匹配原版、声音保持一致。这是技术能力验证，不是主观风格质量或复杂影片验收 |
| 所有入口均未在本记录证明 | DRX/LUT 的实际应用效果、局部窗口/跟踪、OFX、Fusion 完整调色，以及跨场景风格泛用性 |

首轮真实读取对象是隔离验收工程及 120 帧、单视频轨道时间线。另一次 MCP 写入试验只在指定的 FCPXML 验证时间线 V2 片段上进行；首轮因 V1 空轨在写前停止，0 次写入，随后按真实视频轨清单定位后完成试验。该试验没有证明 FCPXML 或变速功能的完整正确性。各 MCP 测试会话均已关闭，没有另起常驻服务。

证据文件分层：MCP 使用 `stdio-readonly-smoke.json`、`stdio-write-roundtrip-v2.json`；直接 SDK 使用 `receipt-final.json`、`media-verification.json` 和 `probe_with_editable_grade.drp`。精确路径由该次维护验收报告保留，不把单次维护目录固定到日常 Skill 中。

机器复装、Resolve/依赖版本升级、允许工具变化后，针对受影响部分更新实测；不能永久沿用这个日期下的结论。新的成功回执应记录具体入口、版本、对象与输出，再更新对应行。
