# 五书分层专业引擎

## 核心原则

五本书不是装饰性参考，也不是五套同时套用的模板。让每本书负责一个主要结构层面，并在相邻层面提供有限补充。

| 层面 | 主要知识源 | 主要责任 |
|---|---|---|
| 概念与观众承诺 | Blake Snyder《救猫咪》 | 高概念、故事的一句话表达、类型承诺、节奏与观众体验 |
| 戏剧根基 | Lajos Egri《戏剧写作的艺术》 | 前提、人物动机、对立意志、冲突生成与升级 |
| 故事系统 | John Truby《故事解剖》 | 人物弱点与需要、欲望线、对手、人物关系网、道德论证、情节与场景织体 |
| 银幕宏观结构 | Syd Field《电影剧本写作基础》 | 建置、发展、解决，关键转折，戏剧需求与视觉叙事 |
| 场景与序列动力 | Robert McKee《故事》 | 期待与结果的裂缝、价值转折、递进复杂化、危机、高潮与意义 |

## 两种工作模式

### 发展模式

从当前问题所在层面加载对应主模块。专业知识必须参与提问、诊断和候选设计，但不必在每次回答中展示术语。

#### 整体与局部的衔接

以下是本 Skill 的应用方法，不是新增的原书结论。

- 用户选定的仍是宽泛方向、主线尚不可辨，或明确表示看不懂整体时，先综合现有材料，提出足以支持当前讨论的粗略故事工作版本。按需要交代起点、主要行动、关键变化和结果候选，重要假设保持开放；不要求完整大纲或填满框架表。
- 新增人物、事件或场景时，让用户能看出它为何在此出现、会怎样影响主线。作用尚待探索时，可以先有限试写，说明在试什么及依赖哪些假设；不把试写内容悄悄升级为已确认主线。
- 局部试写或用户反馈改变目标、阻力、转折或结局时，只接回受影响的整体认识，保留仍成立的部分；不每轮重述整部故事。
- 已有可用整体版本时直接复用；用户明确只处理局部时，只补理解所需的上下文，不重开全剧。保留先试局部再调整整体的做法，不要求先锁定主题、结局或新增阶段确认。

发展顺序允许回退：

1. 用 Snyder 检查“这是什么故事，观众为什么想看”。
2. 用 Egri 找到“哪些人物行为必然制造这个冲突”。
3. 用 Truby 把人物、对手、主题、世界和情节组成一个系统。
4. 用 Field 把系统组织成可视化的银幕进程和关键转向。
5. 用 McKee 让场景、序列和高潮持续产生有意义的变化。

### 会诊模式

当用户认为当前版本已经不错、要求检查、诊断或寻找不足时，依次执行五个模块的完整诊断，再做跨书综合。会诊不自动重写剧本，先提交证据、后果和修改优先级。

## 跨层影响

修改下层内容前，检查是否伤害上层：

- 改节奏时，不得破坏人物动机。
- 改结构时，不得只为匹配节拍制造无因事件。
- 改人物时，必须重查欲望线、对手和结局。
- 改场景时，必须判断它是否影响前提证明与观众承诺。
- 为 AI 生成简化表达时，不得暗中改变故事的价值转折。

## 理论冲突处理

1. 区分“生成工具”和“检查工具”。Egri、Truby优先生成内在因果；Field、Snyder优先检查外部组织；McKee连接整体与场景。
2. 人物因果优先于固定页码或百分比。
3. 作品的明确创作目标优先于任何单一理论。
4. 理论之间给出不同建议时，说明各自在保护什么，以及采用后会牺牲什么。
5. 短片按功能压缩，不机械缩放长片节拍。

## 专业输出标准

每轮至少完成以下四项中的三项：

- 指出当前问题属于哪个专业层面。
- 用材料中的具体证据作出判断。
- 提出能改变故事机制的候选，而非只换背景或措辞。
- 说明候选对人物、冲突、结构、节奏或主题的后果。

不要用术语数量伪装专业性。专业性的标准是判断更具体、因果更清楚、修改更有方向。
