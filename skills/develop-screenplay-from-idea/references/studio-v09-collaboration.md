# V0.9 跨专业故事候选

本分支用于 B 为联合设计提供故事、动作与对白候选；先完成主文版本路由。

## 专业开发

- 接收当前片段/骨架、导演目标、不可改项及点名的空间、表演、镜头或剪辑反馈。可主动补齐故事信息并提出剧情变化；用户明确禁止改动的事实保持不变。输入能支撑判断时直接完成本轮候选，不要求先采用表演、镜头策略或每一项故事补法。
- 按 `professional-story-engine.md` 确定本次主问题，再读对应专业模块及需要的 `screenplay-development.md` 或 `revision-loop.md`。联合设计不默认启动五书全量会诊；用户明确要求完整会诊时才按原专业会诊读取范围执行。
- 本分支替代 `conversation-protocol.md`、`first-round-protocol.md` 中仅因逐步确认而停顿的安排。用户要求先访谈时仍尊重其一问一答；缺失会改变任务身份或触犯不可改项的事实时，依共同契约询问。
- 交付本次范围内完整可读的故事候选，并列明原事实、候选差量、因果理由、前后状态及制作影响。对白、行为和反应须能在后续视听方案中落位；不要替 C 选择机位、代写最终模型提示词或把生成失败直接归为故事失败。

## 对其他专业的接口

C1/C2/D 可据本版候选继续试推资产、表演和声画关系，但必须保留其候选来源；意见冲突由 B 回修故事候选、C2 整合全段，不要求用户在内部每次往返前会签。局部改写只复核受影响因果、人物状态和相邻场次。

候选阶段不执行下文正式 Sxx 分配、Word 同步或 `B_STAGE_READY` 完成步骤。先读实际能力：完整候选交工作集 SaveDraft；用户明确采用后，B 按原专业语义准备文本，通过 Adopt 保存，已采用输入由 Resolve 提供。关闭能力时保留演练决定；不走旧微补丁/续接脚本，文本提交不代表 Word 同步或故事阶段完成。
