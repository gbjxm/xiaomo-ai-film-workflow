# 专业知识路由

## 基本规则

专业知识必须持续参与，但每轮只加载当前问题所需的主要模块。不要每次把五本书全部塞入上下文。

| 当前问题 | 主模块 | 必要时辅助 |
|---|---|---|
| 点子不清、缺少钩子 | Snyder | Egri |
| 一句话故事只写了背景 | Snyder | Truby |
| 主题抽象、人物不行动 | Egri | Truby |
| 冲突靠事故推动 | Egri | McKee |
| 人物关系和对手薄弱 | Truby | Egri |
| 欲望线、中段或情节松散 | Truby | McKee |
| 开端太慢、转折不清 | Field | Snyder |
| 内心无法视觉化 | Field | McKee |
| 场景只有信息没有变化 | McKee | Field |
| 高潮突然或没有意义 | McKee | Egri、Truby |
| 整体版本诊断 | 五书会诊 | AI适配最后执行 |

## 加载规则

1. 发展模式：默认一本主书，最多一本辅助书。
2. 跨层修改：加载被修改层和直接受影响层。
3. 五书会诊：加载五本模块和会诊协议。
4. AI生产问题：先判断是否真是故事问题，再决定是否加载编剧模块。
5. 用户指定某本书时：优先使用该书，但说明它是否适合当前问题。

## 诊断与生成的区别

- 诊断：指出现有材料哪里成立、薄弱或缺失，并给证据。
- 生成：提出改变故事机制的候选方案。

不要在用户只要求诊断时直接替换内容。不要在生成候选时假装理论只有唯一答案。

## 修改后的复查

| 修改内容 | 至少复查 |
|---|---|
| 一句话故事、类型承诺 | Snyder |
| 前提、人物信念、核心关系 | Egri + Truby |
| 欲望、对手、计划、结局 | Truby + Field |
| 主要转折和段落顺序 | Field + Snyder |
| 场景目标、结果或高潮 | McKee + 直接上游模块 |
| 为AI生成调整动作或场景 | Field + McKee + AI适配 |

只复查有实际影响的层面。整体稳定后再进行完整五书会诊。

## 证据规则

每个专业判断必须区分：

- 当前材料中的直接证据
- 基于理论的分析
- 尚未获得信息的开放项
- AI提出的候选

没有可靠资料时，不编造书中术语、章节、页码或作者结论。
