# 在达芬奇原生工程中调色

交付符合影片意图、镜头之间可信连续、可继续修改的调色工程及本次需要的原生导出。保持源媒体不变；每次修改都能说明改善了什么、牺牲了什么，以及如何复查。

## 进入与执行范围

- 先确定用户这次要讨论、只读诊断、修改已指定工程，还是明确做候选测试。讨论与诊断不修改工程或导出；已有明确执行授权直接推进，不重复询问。
- 复用当前已确认的精确工程、时间线、素材和输出目标。信息不足时先完成可独立进行的只读核对，只问影响下一步的一个决定性问题；不从软件“最近项目”或目录最新文件猜目标。
- 默认正式工作只有用户指定的一版，在同一原生工程中持续调整。用户要求修改亮度、冷暖或某个镜头时只改该范围，不自动新建三版、不复制整个工程、不把之前示例风格套到下一场。
- 只有用户明确要求测试时，保留原版与三个候选，默认使用同一约 20 秒的代表片段；用户指定 30 秒或其他范围时遵从其范围。方向按人物、光线、段落情绪及源素材的可塑性制定，不能固定为三种滤镜。
- 只用已核验的 Resolve 官方脚本 API，或确实封装该 API 的本机 MCP 桥接操作原生工程。后台执行不使用鼠标、键盘、快捷键、屏幕坐标或 Computer Use；不因某项 API 缺失自动启用这些路径。
- 不默认使用外部 FFmpeg 滤镜完成调色或代替达芬奇导出。已有只读分析工具可用于实际文件的元数据和帧检查，其结果不能冒充原生工程、节点或渲染证据。
- 先读 [原生执行与能力边界](references/resolve-native-execution.md)，核对连接与本次操作能力。软件有某个 Color/Fusion 功能，不代表当前 API/MCP 可以操作；原生执行缺一项时只限制该项，不虚构完成。

## D 专业接口

在兼容影视项目内，从项目入口读取实际版本和 D 任务范围；`edit-and-finish-ai-film` 仍是 D 主 Skill，负责接管、CUT/Lock、组件、Master 和正式记录。本技能只承担调色专业判断与已授权的原生执行，不新增部门或第二套项目状态。

V0.9 项目按入口和实际能力文件运行。`media_execution` 只描述工作室运行时内置媒体功能，本技能安装与独立调用不改变该字段。独立 Resolve 官方 API/MCP 工具按“本次操作所需接口真实可用＋用户已授权本次动作”判断能否执行；字段为 false 不阻挡满足这两项条件的独立调用，字段为 true 也不替代接口核验或动作授权。未满足条件时完成可继续的方案与具体缺项说明，不改能力配置。该分支不迁移旧项目、不扩大 C 生成、上传或发布权限。项目外独立调色按用户明确的输入、工程和输出范围工作，不强制建立影视项目目录。

- 不改变采用媒体、顺序、切点、时长、变速或故事事实；若当前调色任务确实依赖这些变化，先说明依赖及影响。
- 调色工作稿、测试候选和原生导出不自动成为采用版本。只有用户正式采用时，D 按现有写入契约更新相应 PIC/调色指针与实际受影响的 Master/QC 状态；本技能不创造 CUT 编号、不写 A/B/C/E。
- 独立恢复点、原生工程保存与必要工作稿属于执行可追溯性，不表示项目采用、Picture Lock、PIC 冻结、Master 或 QC 已通过。
- 不用调色掩盖人物身份、动作、空间或材质结构的生成错误。按是否需要重建内容判断专业去向；“改变了像素值”本身不是 VFX 分界。

## 专业判断流程

每次覆盖以下判断，但只对实际需要的部分实施操作。它们是判断层，不是固定节点顺序；可在已确认的共享 Look 下迭代平衡与匹配。详细方法见 [专业调色判断](references/grading-method.md)。

1. **输入与色彩管理**：核对源身份、实际采用文件、色彩标签及可信度、已烘焙 Look、输入解释、工作空间、观看与输出路径。保留未知，不凭低反差认定 Log，不以宽色域转换声称恢复缺失信息。检查遗漏和重复变换。
2. **影片意图与参照**：用一句话说明本场的情绪、关注对象和允许变化；选能代表主要光线状态的参照镜头。单场存在合理暖冷、明暗或时间状态变化时采用多个锚点，保留它们的关系。
3. **基础平衡与匹配**：先修非意图曝光、白平衡、反差、饱和及通道偏差；以同对象、同受光区域和实际切点核验。不要把整体直方图相同、肤色贴线或所有镜头中性化作为目标。
4. **风格与必要局部**：共享 Look 规定场景共同外观，镜头修正补偿各自偏差；按叙事需要才使用局部选区、窗口、跟踪或特定工具。全局改变反复损伤肤色、暗部或重要物体时，先查源解释和 Look 适配，再考虑局部。
5. **按需质感**：有源噪声、过度平滑、锐度差或具体介质诉求才处理。降噪、锐化、颗粒、光晕和其他效果均非必选项；每项须检查细节保留和运动副作用。
6. **动态复看**：在正常速度、前后镜头与交付尺度下完整播放本次影响范围；检查切点跳变、面部层次、选区呼吸、遮挡、闪烁、纹理游走及高光/暗部损失。代表静帧只作定位，不能代替动态判断。
7. **原生导出与回读**：按授权输出目标经 Resolve 导出，核对真实渲染状态和文件，再回读实际标签、帧数/时长、画幅及关键画面。与工程批准参考比较，分开记录技术一致、创作接受和显示限制。

本流程不预设任何曝光、曲线、色温、饱和度、颗粒强度或节点数量。操作没有净收益时允许保持原状；一场测试通过只支持该场与该来源条件，不升级为跨场景万能模板。

## 场景测试与同一版续调

明确测试时，选择能暴露问题的连续段：有代表性主镜头、不同景别或反打、必要的亮暗/肤色/关键物体，以及可观察运动的区间；不能只挑最漂亮的一个静帧。比较各版时固定同一源、起止帧、画幅、播放速度、色彩管线与输出设置，仅改变待评估调色。

原版是无本次调色改动的基线，仍需正确源解释和相同输出路径，不能故意关闭必要色彩变换以拉大优劣。三个候选各自写清一个主要意图、保护项和否决条件；幅度按素材决定，不为凑数量制造无差异版本。已有工程版如何作为原版须说清。

选定方向后回到用户指定的一版继续修改；保留实际恢复点及必要比较证据，不在每次反馈后重新开三方向。下一场先检查共享规则是否适用，再做该场锚点和镜头修正；共同目标不等于参数整包复制。

## 原生工程与保存

- 修改前确认工程、时间线、媒体状态和目标范围；若用户或其他任务可能同时编辑，紧邻写入前重新读取相关状态。出现外部变化时停止该次写入并重新对齐，不覆盖未知修改。
- 常规调整在同一指定工程中保存。覆盖、替换节点图、批量应用 DRX 或其他难以撤销动作前，必须有实际成功且可定位的原生恢复点；空备份路径、未检查返回值或一句“可撤销”不算恢复证据。
- 把 LUT、DRX、节点图与 Fusion 合成的作用分开。LUT 不能表示空间窗口、跟踪、降噪、颗粒或其他时间/空间效果；DRX 的实际覆盖范围按当前版本验证，不能宣称无损追加所有节点。
- 写入调用返回成功后仍读回目标状态，并检查真实渲染画面；API 成功、工程保存成功、渲染完成、用户采用分别记录。
- 仅保存有助续调的事实。可按需使用 [工作稿模板](assets/grading-worknote-template.md)，不要求每次填完整大表；不要把大量专业正文复制到 D 主文件。

## 知识与证据

本技能自含日常判断。遇到源解释冲突、特殊光照、复杂局部/纹理或其他专业缺口时，按 `apply-film-knowledge` 和工作流已有 [知识桥](../orchestrate-ai-film-project/references/knowledge-bridge-contract.md) 补证：传岗位 D、精确场景/片段、当前问题与约束，读取方法和边界，再落到素材判断。不写死知识树路径、不因检索命中宣称效果验证、不自动回写知识树。

`references/grading-method.md` 区分来源原则与综合方法。软件接口、参数含义和版本支持以本机官方文档与真实探测为准；此前“自然柔和”案例仅是该素材的参考，没有证明跨场景通用。

## 交付

交付精确工程/时间线、本次改变与理由、原生导出路径、实际检查结果，以及仍未完成或受能力/显示条件限制的项。正式单版只交用户指定的一版；明确测试才并列原版与三候选，便于按同一段比较。

停止条件是本次意图可辨、重要信息受保护、场景连续可信、动态与输出回查完成且用户意见已处理。未看完整影响段时不能称动态通过；只有静态验证或工具连接时不能称调色效果通过；本技能完成不等于整片后期、Master QC 或发行就绪。
