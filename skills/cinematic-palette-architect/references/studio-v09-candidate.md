# V0.9 前期配色与生成前 Look 候选

遵循共同契约的候选模式。接收 C1/C2 当前明确提交的资产或镜头工作稿即可开展色彩设计，不等待正式 Axx/Vxx 或逐项采用；未给出的关键设计可形成有依据的候选。真实取样仍必须基于已查看图片，不能把设计色标记为实测。

## 专业读取与用途

按需读取 [对象与色彩规则](object-and-color-rules.md)。创意设计使用 [创意判断](creative-judgment.md) 的视觉命题、多方案比较和反套路审查；图片取样复刻不加入重设计。需要英文色卡制图提示词或 JSON 时才读取 [输出契约](output-contract.md) 的对应格式，旧项目的采用/稳定 ID 门不进入本候选分支。

先分清本次的色彩职责，再设计：

- 项目视觉方向：颜色、材料和明暗组织如何支持故事阶段、人物与观众体验，哪些关系固定、哪些随场景变化。
- 资产本色：C1 负责的材料色、涂层、织物、饰边和磨损关系；用适合识别本色的观察条件描述，不把一张强染色画面的像素色当作固有色。
- 状态变化：明确颜色或材质变化来自何种状态，不用不同滤镜伪造同一资产状态。
- 场景/镜头显示：结合真实光源、方向、光质、天气/空气、曝光锚点、反差、色彩在具体材料/区域的分布以及成像质感，给 C2 一份可直接整合的生成前 Look 候选。

不为完成固定格式而给每个简单镜头另建色卡。已有基准足够时保留基准，集中解决本场差量；不能用“沿用项目色卡”代替提交给外部模型的具体光色内容。

## 前期协作和交付

在 C1 资产定稿前参与材料本色与场景光源讨论；与摄影候选对齐曝光、阴影和高光的可见结果。一个颜色同时被人物身份、物理光源和叙事强调要求争夺时，指出冲突并给一个推荐取舍；涉及既有硬约束的替代列为差量，不能直接覆盖。

返给 C2 的是本场推荐色彩/光影判断、作用对象、材料本色保护、允许变化及风险。D 可给后期匹配和显示接口意见，C2 统合生成前 Look；预期显示效果不能报告为已经调色。最终镜头匹配、精确调色和最终 Look 仍由 D 完成。

交付前用当前主要光源、曝光和景别检查：主体能否从背景辨认、强调色是否抢错焦点、肤色和服装是否被环境色污染、材质差异是否仍可读、相邻状态是否连续。比较可以在内部完成，用户收到推荐工作版及真正影响选择的备选理由。

色卡图是颜色关系的参考，其版式、字样、白底和示例物体不能进入最终画面；镜头用的色卡职责不得覆盖身份或空间。英文制图提示词由本专业按明确请求提供，最终场景/镜头提示词仍交格式器；候选由当前工作集按能力 SaveDraft；明确采用的色卡文本由所属 C1/C2 通过 Adopt 保存，已采用输入先 Resolve。能力关闭时保留演练决定；本批不调用生成工具。
