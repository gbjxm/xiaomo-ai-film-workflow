# 流程改进日志契约

## 记录范围

允许类别：`重复返工`、`遗漏`、`交接失败`、`职责冲突`、`重复手工步骤`、`工具失败`、`证据缺口`、`契约不清`。

不记录普通创作修改、未发生的风险猜测、个人隐私、密钥、完整聊天记录或项目外文件内容。

## 文件结构

```text
项目根目录/
└─ 流程改进日志/
   ├─ 待处理/
   │  └─ WFI-YYYYMMDD-HHMMSS-岗位-六位码.md
   └─ 已处理/
```

每条记录包含：ID、状态、记录时间、来源项目、岗位、任务阶段、问题类别、Pattern-Key、建议修改位置、已核验事实、影响、证据、当前临时处理和建议方向。

## 状态

- `待定`：已记录，尚未由用户选择或尚未完成验证。
- `采用`：用户点名处理，修改和全部验证已成功。
- `停用`：用户明确拒绝，或核对后确认为重复、项目特例或不应进入总工作流。

状态为采用或停用后移入 `已处理/`；不得删除。失败或部分完成仍保持待定。

## 去重与选择

- Pattern-Key 只用于聚合同类问题，不自动授权修改。
- 同一项目、岗位、任务阶段和 Pattern-Key 只保留一条待处理记录。
- 维护报告必须列出完整 WFI ID。只有用户点名的 ID 可以进入修改批次。
- 未点名、证据不足或并发变化的记录保持原样。
