# AI 影视资产设计

## 项目版本路由（先判断）

只依据当前业务项目 `开始这里.md` 的显式 `workflowStudio: studio-v0.9` 选择新分支；Skill 路径、候选目录名或聊天标题都不是项目标识。可复用主调用方本轮已核实的入口与能力结果。

- 有该标识：先读 [V0.9 共同契约](../orchestrate-ai-film-project/references/studio-v09-contract.md) 与项目能力状态，再读 [本专业的 V0.9 候选分支](references/studio-v09-candidate.md)。仅执行该分支；不进入下方旧版的唯一 A 目标、逐项采用、同岗租约或正式写回流程。专业知识按该分支指向读取。
- 无该标识或不在项目中：不加载 V0.9 分支，继续下方原有模式和边界。无法核实标识时，不凭目录推断启用新能力。

把采用剧本中的制作需求变成稳定、可复用、可检查的资产事实。字段定义见 [资产规格契约](references/asset-spec-contract.md)，写入结构使用 [Axx 资产规格模板](assets/asset-spec-template.md)。

## 工作模式

### 咨询模式

没有项目目录或采用 `Sxx` 时，只能给方法、缺口清单或未编号草案；不分配真实 `Axx`，不写文件。

### 项目模式

新建 C 同岗任务或旧 C 任务收到明确切换请求时，先读取 [B/C/D 同岗续接契约 v1](../orchestrate-ai-film-project/references/same-role-resume-contract.md)，再检查 A 的 `## 当前任务` 门与 `续接缓存/C_同岗续接.json`。只有 `cursor.active_station` 指向资产站时才加载本 Skill；有效缓存只读取 `read_sets.required` 中当前 `Sxx`、正式 `Axx` 与精确点名参考，不读取整份 A/B/C、整份 Word、旧聊天或完整候选资产树。

1. 冷启动、未启用同岗续接或共同契约要求区段级恢复时，只读取 `开始这里.md` 的共享契约与 C 启动词，再读取 A 当前任务门和 C 当前状态/最近交接区段；跳过 A/B/D 启动词。
2. 同一 A 当前任务内若公共文件没有外部修改迹象，切换 C 的其他 Skill 时复用已读内容。
3. 只读取 A 指定的采用 `Sxx`、相关已采用资产和必要参考图；不要自行扩大故事范围。
4. v0.8 项目存在 `场景制作/Sxx_场景制作卡.md` 时，读取场景导演基准和站 2 适用性；只承接其目标与本场增量，不改场景卡。旧项目没有该契约时沿用原项目结构，不补建。
5. 按角色、场景、服化道、道具、材质和视觉固定项提取需求，区分剧本事实、用户锁定和设计推断。
6. 识别共用资产、变化资产和一次性资产；给出优先级及其制作理由。
7. 区分项目级已锁定生产设计与本 `Sxx` 增量；记录空间拓扑、出入口/动线、服化道、材质、交互和状态链，不在每场复制项目全文。
8. 先在对话中输出未编号草案和冲突问题。信息不足且会改变资产身份时，只问一个关键问题。

同岗续接时，A 的阶段包络不得展开成资产读取列表；只消费 `cursor.active_sxx` 与 `cursor.active_workset`。未分配正式 `Axx` 的候选素材默认排除，只有用户为当前资产动作精确点名的子集才可临时进入 `optional/required`，且仍保持候选状态。缓存、候选目录或本 Skill bundle 变化只局部复核受影响对象，不扫描整个素材库。`pending` 草稿续接后仍为待定；Inspect/Claim、hash 一致或 lease 有效不授权分配 `Axx`、写入或生成媒体。

## Axx 规则

- `Axx` 只由本 Skill 分配。
- 草案使用“候选资产 1/2”等临时标签，不占用编号。
- 用户明确采用资产规格时，从 `C_视觉生成.md` 的资产索引读取最大编号并分配下一个 `Axx`。
- 外观微调且功能身份不变时提升版本；身份、用途或连续性角色改变时新建 `Axx`。
- 被替代的旧编号标记 `停用`，不得删除或回收。
- 每个 `Axx` 必须关联至少一个 `Sxx`；与镜头发生关系后补充关联 `Vxx`。

## 写入门与范围

- 草案阶段零写入，不计算 SHA-256。
- 明确采用并即将写入时，重读所有目标并记录 SHA-256，紧邻写入前再次核对；值变化或预期新文件已出现时停止。
- 采用后只写 `C_视觉生成.md` 的资产设计索引、项目视觉与制作基准中的资产固定项、最近交接，以及 `资产设计/Axx_名称_vNN.md`。v0.8 场景卡只由 `$direct-ai-scene-production` 根据本 Skill 的精确版本/路径/hash 更新引用。
- 暂停或切换岗位时，只能在 `C_视觉生成.md` 写待定摘要和最近交接，不创建 Axx 文件、不把草案升级为采用。
- 不写 `B_故事剧本.md`、表演设计、镜头规划、提示词卡、生成记录或 D 的任何文件。

## 交付与交接

每个采用资产至少包含：稳定身份、用途、采用状态、版本、剧本依据、固定约束、可变项、尺度与材质、空间关系、服化道或道具交互、状态链、连续性风险、验收标准和关联 ID。

完成后把已采用 `Axx`、精确版本/路径/SHA-256、仍缺资产、冲突和建议下一 Skill 写入 C 最近交接。v0.8 交给 `$direct-ai-scene-production` 汇入场景卡和 Setup；专业下一步通常是 `$direct-ai-character-performance` 或 `$plan-ai-shots-and-previs`，不要自行代做。
