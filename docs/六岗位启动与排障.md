# 六岗位启动与排障

本页适用于入口唯一声明 `workflowRelease: 1.0` 和 `workflowStudio: studio-v0.9` 的 V1 项目。产品仍为 1.0，完整六岗位启动包版本为 4；v0.9/v0.8 继续使用各自分支。

## 先选择要做的动作

| 你的目标 | 使用方式 | 会发生什么 |
| --- | --- | --- |
| 创建一部新影片的项目目录 | `$start-ai-film-project` 新建项目 | 复制并核验模板，分配递增目录版本，交付完整启动包 |
| 为现有 V1 项目建立或补齐岗位任务 | 在该项目中请求初始化六岗位 | 当前任务作为 A，只查询、复用或补齐其他五岗 |
| 只获取一段总启动词 | 明确“准备启动词，暂不执行创建” | 返回一个完整代码块，不创建任务 |
| 继续某个片段或已有工作稿 | 从当前专业和工作集继续 | 按项目记录恢复具体工作，不重新初始化岗位 |

**安装技能、建立岗位入口、继续已有工作集是三个独立动作。** 已有项目初始化不能再次运行新建脚本，也不应把空待命任务当成工作集交接。

## 从新项目开始

先在工作流仓库中完成[安装](../README.md#1-安装随包技能)，再发送：

```text
使用 $start-ai-film-project，新建影视项目《项目名》。
```

拿到项目路径后，在 Codex 中打开该目录，把返回的整个 `launchPrompt` 发给首个任务。它包含同项目核对、重复任务检查和 B/C1/C2/D/E 五段待命消息，不需要逐岗复制五次。

当前任务命名为 `A｜制片统筹`，其余标准标题为：

- `B｜编剧开发`
- `C1｜美术与资产`
- `C2｜导演与视听制作`
- `D｜剪辑与声音后期`
- `E｜发行与复盘`

新任务在同一个已注册本地项目中运行，不创建工作树，不覆盖模型或推理设置。每个新任务只收到自己的短待命消息，不附整份聊天或业务材料。

## 已有 V1 项目

在准备作为 A 的任务中发送：

```text
使用 $start-ai-film-project，为当前 V1 项目初始化或补齐六岗位任务。
当前任务作为 A，查询并复用或补齐 B、C1、C2、D、E，核验后待命。
沿用已确认设定，不创建新项目、不接管旧工作集、不生成或剪辑。
```

也可在工作流仓库根目录用 PowerShell 只读获取启动包，将示例路径替换为实际项目绝对路径：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ".\skills\start-ai-film-project\scripts\get_role_launch.ps1" -ProjectRoot "C:\AI-Film\项目\2026-09-20_示例片_v1"
```

该命令仅返回 JSON，`tasksCreated=false`、`projectModified=false` 是正常结果；真正的任务创建由 Codex 接到你的初始化请求后执行。`success=true` 只能说明启动包准备完成。

脚本核验 V1 标识、能力文件及九个必要入口。它支持 `production-docs-v1` 和旧的工作室资料目录布局，但不据此搬文件、迁移旧版项目或放宽能力字段。

## 如何判断启动完成

1. 当前目录和目标项目一致，入口文件齐全。
2. 查询得到唯一的目标项目；同名但属于其他项目的岗位被排除。
3. 已有唯一同岗任务复用，缺失才创建；出现第二个 A、重复岗位或身份歧义时停止。
4. 创建后有真实任务 ID，标题、项目归属和 cwd 能被核对。
5. 新建的五个岗位分别返回“已待命”；无回复时只记“已创建，待命未核实”。

完成后留在 A 等下一条请求，不自动开始剧本阶段，也不运行工作集创建、采用、媒体生成或剪辑。

## 常见情况

### 提示没有任务创建工具

本工作流依赖当前会话提供以下 Codex 原生能力，实际工具名可能带命名空间：

| 能力 | 常见工具名 |
| --- | --- |
| 查询项目 | `list_projects` |
| 查询与核对任务 | `list_threads`、`read_thread` |
| 创建独立本地任务 | `create_thread` |
| 命名当前 A | `set_thread_title` |
| 读取异步待命结果 | `wait_threads` |

先确认工具是否真的出现在当前会话中。安装 23 个影视技能不会安装或启用这些应用工具；已有“工具已连接”的旧记录也不能替代当次查询。若刚调整过应用配置，重新加载 Codex 后再检查实际可用能力。

没有工具时保留现状，输出未执行的原因和五段短待命消息供手动创建。不要用子代理、CLI 会话或直接修改任务数据库来冒充用户可见的岗位任务。应用配置排查应针对该电脑与版本进行；本仓库不发布个人管道地址或通用强制开启配置。

### 任务已回复待命，列表却没有新条目

保留创建回执和任务 ID，先用状态读取或按 ID 直读核对标题、cwd 和待命回复。将“任务存在且已待命”与“任务列表和项目归属核验通过”分开记录。

不要因为列表暂未返回新任务就重复创建或重新运行整个初始化。查询仍不完整时，停止补建并报告未核实项。这类现象在一次真实执行中出现过；本次发布没有把列表同步、自动复用或重复启动防重标为全部实测通过。

### 发现已有岗位或第二个 A

同项目已有唯一岗位时直接复用，不唤醒或接管它。标题不同但可能属于同一岗位时先确认身份。若已有其他 A，不自动合并、删除或改名，先由用户明确哪个任务承担 A。

### 需要把旧工作稿交给新任务

这是工作集续接，按[共同契约](../skills/orchestrate-ai-film-project/references/studio-v09-contract.md)办理。只有明确接替同一个已有工作集时才使用 PrepareHandoff/ActivateHandoff/CancelHandoff；批量建岗不能顺带抢占租约。

## 更新已有安装

获取仓库最新内容后，在仓库根目录重新运行安装器及 `-VerifyOnly`。本次主要更新 `start-ai-film-project` 和 `orchestrate-ai-film-project`，原有同名不同内容会进入安装事务备份。

已存在项目不自动迁移。初始化入口会读取它自己的 V1 标识与能力；旧项目没有标识时不应通过手工补一行版本标记强行启用。使用当前材料和确认过的迁移流程处理版本接入。
