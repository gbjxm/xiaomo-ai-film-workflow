# 小陌 AI 影视工作流 V1

在 Codex 中使用的个人 AI 影视工作室。你决定作品要表达什么、采用哪一版、何时投入制作；AI 按编剧、美术、导演、后期等专业协助工作，并把当前方案、选择理由和实际结果保存在项目中。

**产品版本 1.0 · 23 个随包技能 · Windows / PowerShell · `studio-v0.9` 工作室协议**

当前维护更新恢复了**一段总启动词建立六岗位入口**，并支持为已有 V1 项目补齐岗位。项目版本、工作流版本和启动包版本是三个不同概念；本次启动包为 `launchPromptVersion=4`，产品仍为 1.0。

## 能用它做什么

- 从点子发展故事骨架、人物冲突、分场与剧本，围绕具体问题局部返修。
- 设计角色、场景、服化道、配色、表演与镜头，说明参考素材的用途和需要保持的连续性。
- 整合可复制的图片、视频提示词，记录真实生成结果与可用区间。
- 用真实素材讨论或执行剪辑、声音、调色与成片检查；具体执行取决于你的授权和工具能力。
- 准备标题、封面、发布包、比赛资格检查，并根据真实发布数据复盘。

它适合独立创作者和小团队逐步制作 AI 短片。技能提供专业方法、项目记录和协作规则；生成模型、剪辑软件、账号与媒体素材由实际使用环境提供。

## 快速开始

### 1. 安装随包技能

完整下载仓库或克隆到本地，保留目录结构和 `.gitkeep` 文件。在 Codex 中打开仓库文件夹，发送：

```text
请读取根目录 AGENTS.md、00_开始这里.md、skills/manifest.json 和 安装工作流.ps1，安装随包23个Skills并验证本机路径配置。不要迁移或修改现有项目。
```

也可以在仓库根目录运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ".\安装工作流.ps1"
powershell -NoProfile -ExecutionPolicy Bypass -File ".\安装工作流.ps1" -VerifyOnly
```

安装器按清单安装技能并写入本机路径配置，已有同名不同内容的技能先备份。移动仓库后重新安装以更新路径。若 Windows PowerShell 缺少 `Get-FileHash`，可在已有 PowerShell 7 中将命令开头换成 `pwsh`。

### 2. 新建项目并一次启动六岗位

```text
使用 $start-ai-film-project，新建影视项目《项目名》。
```

启动器创建递增版本目录，返回项目路径和**一个完整的六岗位启动包**。在 Codex 中打开该项目目录，将整个启动包发给首个任务：当前任务成为 **A｜制片统筹**，查询并复用或创建 B、C1、C2、D、E 五个本地独立待命任务。

首轮只建立和核对岗位入口，各岗位回复“已待命”。收到你的下一条具体请求后才读取对应业务材料；不会因此自动生成图片、剪辑或发布。

### 3. 已有 V1 项目只补齐岗位

在已有项目的 Codex 任务中发送以下内容，无需再创建项目目录：

```text
使用 $start-ai-film-project，为当前 V1 项目初始化或补齐六岗位任务。
当前任务作为 A，查询并复用或补齐 B、C1、C2、D、E，核验后待命。
沿用已确认设定，不创建新项目、不接管旧工作集、不生成或剪辑。
```

只需要获取启动词时，可以说“为当前 V1 项目准备六岗位总启动词，暂不执行创建”。脚本入口是 [get_role_launch.ps1](skills/start-ai-film-project/scripts/get_role_launch.ps1)，读取已存在的项目后返回启动包，本身不写项目、不创建 Codex 任务。

自动建岗需要 Codex 当前会话提供原生任务工具。缺少工具、查询不完整或出现重复岗位时会停止并报告；此时不要反复发送启动词来尝试“刷新”。已有创建回执应先核对，避免重复任务。详细操作见[六岗位启动与排障](docs/六岗位启动与排障.md)。

## 六个专业部门如何协作

| 部门 | 主要负责 | 常见请求与交付 |
| --- | --- | --- |
| A 制片统筹 | 目标、资源、进度、依赖与完成证据 | 判断下一步、组织跨专业问题、核对交接 |
| B 编剧开发 | 故事、人物、行动因果与对白 | 故事骨架、剧本、场景诊断与局部修改 |
| C1 美术与资产 | 角色、空间、服化道、材质与状态 | 资产规格、配色、身份与视觉参考 |
| C2 导演与视听制作 | 创作整合、表演、摄影灯光与镜头 | 指定片段的完整视听候选与生成前方案 |
| D 剪辑与声音后期 | 素材接管、组接、声音、调色与 QC | 剪辑诊断、实际后期、成片与验证记录 |
| E 发行与复盘 | 传播包装、资格检查与真实反馈 | 发布包、封面、发布前核验与数据复盘 |

六个岗位任务是可分别进入的工作入口。专业咨询按问题组织，A 管制作协调，C2 管创作整合，不要求每个小调整都回 A 重新批准。C1/C2 可各有多个工作集，完整工作稿与正式采用内容分别保存。

例如，你可以在 C2 说：“继续处理已确认剧本中的追逐片段，先解决空间关系和动作衔接，给出完整候选，暂不生成。”相关专业围绕这一个问题协作，不重新梳理全片。

## 项目材料放在哪里

默认新建 V1 项目采用以下布局：

```text
项目/日期_片名_vN/
├─ 开始这里.md              日常入口、版本标识与岗位启动词
├─ 工作室能力.json          本项目实际启用的能力
├─ A_总控.md                制作组织与状态导航
├─ B_故事剧本.md            故事记录
├─ C_视觉生成.md            C 专业导航
├─ D_后期剪辑.md            后期记录
├─ E_发行复盘.md            发行与反馈记录
├─ 01_图片/                 人物、场景、道具、镜头图、封面
├─ 02_视频/                 Aroll、Broll、其他素材
├─ 03_音频/                 音效、BGM
├─ 04_导出/                 小样、成片
└─ 90_制作资料/             剧本、资产、镜头、提示词、工作稿等
```

工作集和采用索引按运行时需要保存在项目根目录的 `.工作室/`。C1、C2 的工作稿入口位于 `90_制作资料/工作稿/`。已经被工程引用的素材保持真实路径，不因新布局自动移动或重命名。

仓库的 `项目/` 只跟踪 `.gitkeep`，你的影片项目默认被 Git 忽略。项目建立后从项目内的 `开始这里.md` 继续；不必每次读取整个工作流维护历史。

## 候选、采用和实际制作

| 状态 | 表示什么 |
| --- | --- |
| 候选已保存 | 完整方案和必要理由已留存，仍可继续讨论 |
| 已采用 | 你明确选择了精确内容，所属专业按采用事务保存 |
| 已生成／已剪辑 | 有真实媒体、工程操作或工具回执 |
| 已验证 | 完成了对应层级的检查；文本、接口、连续播放和成片 QC 分别判断 |

采用提示词不会自动执行生成，创建岗位不会接替旧工作集，安装成功也不会自动迁移旧项目。这样可以保留探索空间，同时避免下游误用尚未确认的版本。

## 工具与环境

| 能力 | 使用条件 |
| --- | --- |
| 六岗位自动创建 | Codex 提供项目查询、任务查询、创建、改名和状态读取工具 |
| 图片生成／编辑 | 当前 V1 项目已授权本次操作，输入充分，原生图片工具可用 |
| 视频生成 | 按项目约定在实际视频平台执行，记录真实返回结果 |
| DaVinci Resolve 后期 | 软件、官方 API/MCP 与本次所需接口实际可用，并已授权指定工程操作 |
| 个人知识树 | 单独配置可选知识桥，不随本仓库提供知识库原文 |

仓库安装器不会安装 Codex 自带的任务服务、复制机器级 MCP 配置或替你连接外部账号。任务工具缺失时，应检查应用与当前会话的实际能力；不要从另一台电脑复制管道地址或整份配置。
