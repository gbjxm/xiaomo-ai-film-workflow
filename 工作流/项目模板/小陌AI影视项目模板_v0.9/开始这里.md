# 开始这里

> 本项目使用“小陌 AI 影视工作室 v0.9”；仅按本入口标识与实际能力启用。
> workflowStudio: studio-v0.9
> workflowMediaLayout: media-layout-v2
> workflowDocsLayout: production-docs-v1
> 本文件是项目日常入口；项目根目录为本文件所在目录。

## 共享入口与能力

先读 [工作室能力.json](工作室能力.json)，再按本次工作读取下面一个部门启动词。

共同契约的唯一正文：skills/orchestrate-ai-film-project/references/studio-v09-contract.md。此路径相对显式指定或本机安装配置的 workflowRoot；也可从本次所用 orchestrate-ai-film-project Skill 的 references 定位。找不到时停止版本路由，不猜旧工作流目录。

实际运行时动作以能力文件为准。workset_runtime 与 adoption_transactions 同时开启，并声明 runtime_schema=xiaomo.studio-runtime/v1；media_execution 所指的工作室运行时内置媒体功能仍关闭。D 的独立达芬奇原生 API/MCP 需实际可用且用户已授权本次执行，不改此字段，也不扩张 C 生成、上传或发布权限。早期演练项目两项仍为 false 时只保留候选决定，不调用运行时。V0.9 不运行旧同岗续接脚本。

## 素材存放

本项目采用 media-layout-v2。新生成或下载的媒体按下表放在项目根目录的四个入口；用户在外部工具保存或下载，记录仍引用实际文件位置。

| 入口 | 放置内容 |
| --- | --- |
| `01_图片/` | 固定预建 `人物/`、`场景/`、`道具/`、`镜头图/`、`封面/`，按真实用途存放图片 |
| `02_视频/Aroll/` | 主要叙事或主要内容的视频素材 |
| `02_视频/Broll/` | 补充画面、环境、细节和插入镜头素材 |
| `02_视频/其他素材/` | 暂不属于前两类的其他视频素材 |
| `03_音频/音效/` | 环境声、拟音和效果声 |
| `03_音频/BGM/` | 背景音乐 |
| `04_导出/小样/` | 真实导出的预览、小样；不代表采用或 QC 通过 |
| `04_导出/成片/` | 真实成片导出；采用、Master 绑定、QC 和发布状态仍依各自证据 |

图片五项、视频三项、音频两项以及小样/成片目录固定保留。尚未确定归属的文件先保留真实位置，不把对白等未约定类别强塞入其他类型；具体命名、批量归档及搬运规则后续另定。

C 回传结果、D 接管与 E 封面记录使用真实路径；目录名不分配 S/A/V/CUT/PUB，不代替推荐、入片、锁定或发布判断。已经被记录或工程引用的旧媒体继续从原路径读取，不因启用新目录而移动、改名、覆盖或改写历史指针。工程、参数、代理和后期处理件保持其原专业位置，不混入小样或成片。

本布局只规定生成后素材的存放入口；其他工作流文档、工作集与能力不变。目录定义随项目创建技能的 `references/media-layout-v2.json` 维护，整理技能复用，不另造第二套规则。

## 生成视频整理

使用 `$organize-ai-film-media` 整理点名的一批下载视频：同一片段的多条完整原片归在一起，按需要记录每条的源时间可用区间，不要求先标完区间。明确未导入剪辑软件的新文件可复制归位；已导入或状态不明的文件保持原位置。机械索引按需保存到 `90_制作资料/生成记录/素材整理/素材索引.json`，不预建空索引，不代替专业采用，不修改剪映工程。

## 制作资料位置

本项目明确启用 `workflowDocsLayout: production-docs-v1`。剧本、资产设计、色卡、表演设计、镜头规划、场景制作、提示词卡、生成记录、后期方案、发布包、工作稿、续接缓存、流程改进日志统一保存在 `90_制作资料/` 下同名子目录；不得重新在根目录建立这些旧目录。

本页入口、A/B/C/D/E 主文件、工作室能力.json 和 `.工作室/` 状态/采用索引继续位于项目根目录。生成的图片、视频、音频及导出文件仍放四个媒体入口，专业资料与媒体本体分别保存。

专业 Skill/reference 中根相对的业务路径，按共同契约的 `studio-project-layout-v1.md` 定位。例如 `资产设计/Axx_名称_vNN.md` 在本项目实际为 `90_制作资料/资产设计/Axx_名称_vNN.md`。运行请求、链接、依赖、采用和恢复记录必须使用实际项目相对路径，不把旧路径当别名；历史事实不自动改写。

## 怎样开始

说明本次要做的故事、资产或片段即可。C2 从整片意图开始统合，C1、B、表演、摄影和 D 按问题协作，再交一份完整候选供集中修改；不逐专业要求用户先采用。

六个部门是责任划分，不是六个永久聊天。只在用户明确要求新开或续接任务时创建可见任务；工作集的准备、激活与取消由新运行时办理。内部专业协作用受限子代理，不要求预建六个待命任务。

## 保存、采用与恢复

日常制作只读取本项目入口、能力、当前工作集与必要专业材料；不读取工作流维护 HANDOFF。运行入口为 workflowRoot 下的 skills/orchestrate-ai-film-project/scripts/studio_runtime.py（或同名 .ps1），具体参数按共同契约使用。

- 新工作内容先 Create 独立工作集；继续已有内容先 List/Inspect 找到精确工作集，再按 Inspect 的 required_read_set 读取完整稿。C1/C2 可以各有多个工作集，各自持有租约、工作稿与缓存。
- 完整候选形成或关键差量变化时，用 SaveDraft 保存当前整稿，不只保存摘要；候选仍是候选。工作稿在 90_制作资料/工作稿/<部门>/<key>/，不可变快照在 历史/，当前.md 是可编辑视图；保存时使用刚读到的视图 hash，不能覆盖未知手改。
- 运行状态为 .工作室/工作集/<key>/state.json；90_制作资料/续接缓存/<key>.json 只保留短指针且可重建。缓存丢失或损坏时 Inspect 从 state 与不可变快照恢复必读集，不扫描旧聊天或全素材树。
- 用户明确采用当前精确版本后，所属专业准备完整目标文本，经 Adopt 统一提交；脚本只保存用户采用的内容，不重新创作。影视稳定 ID 保持 S/A/V/CUT/PUB，运行键不是影视编号。主要对象的 object_id 由所属专业显式声明，脚本不自动选号、不从正文引用认领；发布索引在提交锁内拒绝同一 ID 绑定不同路径。冲突由所属专业调整编号后再提交，C 场景卡引用 S 不认领 B 的 S 编号。
- .工作室/采用索引.json 是唯一原子采用发布点。普通专业 Markdown 和 .工作室/采用索引.md 是可重建视图；消费已采用内容必须先 Resolve，再读取返回的不可变快照，不能把半套更新视图当作生效输入。
- 中断后按回执区分“尚未采用”“已完整采用但视图待同步”“已被后续版本替代”。ResumeSync 接续原事务；未提交才可 CancelAdoption。未知手改保留并报告，不能把恢复当成覆盖许可。

新开/续接可见任务必须有用户明确请求。先 PrepareHandoff，创建成功才 ActivateHandoff；创建失败调用 CancelHandoff。旧持有者激活后停止写本工作集，其他工作集不受影响；不能只改聊天名称或沿用旧单 C 租约完成接管。

能力为 false/false 的早期项目保持仅候选演练；不尝试新运行时或宣称已自动保存。已明确启用且能力开启的 V0.9 项目执行以上动作；生成与发布仍由用户在外部完成，D 后期按本页达芬奇实际能力及本次执行授权处理。安装不迁移旧项目或自动开放媒体动作。
